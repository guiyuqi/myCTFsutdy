## 已修复：`fw-decompile` 的静默截断（严重 bug，我引入的）

**根因确认**：`~/re-tools/bin/fw-decompile` 第 48–49 行原文：

```bash
"$GHIDRA_INSTALL_DIR/support/analyzeHeadless" "${ARGS[@]}" 2>&1 | tee "$OUT" | \
  sed -n '/### DECOMPILED/,$p' | head -100
```

`head -100` 读满即退出 → SIGPIPE 逆管道杀死 `sed` → `tee` → `analyzeHeadless`，
**落盘文件同样被截断**，而脚本仍打印「完整结果已保存」并 `exit 0`。

这个 bug 是我在搭建期为了终端输出好看加的管道造成的。报告的诊断完全正确，
**且它比我更早发现**——正是这类 bug 会在比赛中造成"拿着 3% 伪代码当完整结果"的事故。

### 修复内容

1. **去掉全部管道**，完整输出直接 `> "$OUT" 2>&1`；
2. **加产物完整性校验**：缺少 `### DECOMPILED_COUNT` 收尾行即判定未正常结束，
   打印 `[!!]` 并 `exit 1`——不再静默成功；
3. **如实报告统计**：输出「二进制函数总数 / 已成功反编译 / 反编译失败」三个数字，
   不再让 `maxFuncs` 的入参与真实产出混淆。

### 修复前后实测对比（同一目标 uhttpd）

|---|---|---|
| 产物行数 | 1,084 | **6,508** |

## 待人类决策的遗留项

1. **musl 动态验证能力**（可选）
   要跑 OpenWrt/musl 二进制需要以下之一：
   - `qemu-x86_64-static`（x86_64 与宿主同构，其实**不需要 qemu**，只需 musl loader）
   - `/lib/ld-musl-x86_64.so.1` 或 musl 工具链
   最省事的做法：从 OpenWrt SDK 或 Alpine 镜像里取 `ld-musl-x86_64.so.1` 放进工作区，
   用 `./ld-musl-x86_64.so.1 --library-path ./lib ./uhttpd` 运行。
   **纯静态逆向不需要这个**，按需再装。

2. **rizin/r2 缺失**
   `fw-env.sh` 的提示里提到了 `rizin`，但实际没有。两个选择：
   - 从提示里删掉（诚实但少一个工具）
   - 装 rizin 静态版（GitHub Release 下载，比赛前装好）
   当前 Ghidra 已覆盖反编译需求，**非阻塞**。

3. **Ghidra 偏好目录版本不一致**
   跑 12.1.3 却读 `ghidra_12.1.2_PUBLIC/preferences`（因我给 rea 做了版本号伪装）。
   **纯外观问题，不影响功能**，可以不处理。
