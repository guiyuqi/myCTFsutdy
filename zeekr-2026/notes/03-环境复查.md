## 3. ✅ 动态运行可行 —— 我上轮的结论是错的

**纠正我上轮的两点错误：**

1. 我说"需要额外准备 OpenWrt 23.05 rootfs" → **不必要**。`notes/02` §4 的反驳是对的，
   我实测确认：固件镜像解出的 rootfs **自带全部依赖**
   （`libubox` / `libjson_script` / `libblobmsg_json` / `libjson-c.so.5` / musl libc）。
2. 更重要的：**动态运行根本不需要装任何东西。** 宿主就是 x86_64，
   用 rootfs 自带 loader 直接跑：

```bash
cd work/fixture-rootfs
./lib/ld-musl-x86_64.so.1 --library-path ./lib:./usr/lib ./usr/sbin/uhttpd -h
```

**实测成功**，打印出完整 usage：

```
Usage: ./usr/sbin/uhttpd -p [addr:]port -h docroot
  -c file   Configuration file, default is '/etc/httpd.conf'
  ...
```

关键点（已存 `evidence/dynamic-run-recipe.txt`）：
`--library-path` 必须同时给 `./lib` 和 `./usr/lib` —— `libjson-c.so.5` 只在 `/usr/lib`。

> 所以"仿真"这一环对 x86_64 目标是**零额外工具**即可；其他架构走
> `qemu-<arch>-static -L <rootfs>`。我上轮把它列为"需人类批准的装新工具"，属于误报。

## 5. ❌ 新 bug（轻微）：失败诊断行被截断

`fw-decompile` 新增的错误诊断：

```bash
grep -aoE 'ERROR REPORT: [^\r\n]*' "$TMP" | head -3
```

**`[^\r\n]` 在 grep 的 ERE 里不是"非 CR/LF"** —— 方括号内 `\r` `\n` 不转义，
被当成字面字符 `\`、`r`、`n`。于是它表示"非反斜杠、非 r、非 n"，
**碰到 `Import` 里的 `r` 就停**：

```
$ grep -aoE 'ERROR REPORT: [^\r\n]*'   →  ERROR REPORT: Impo
$ grep -aoE 'ERROR REPORT: .*'         →  ERROR REPORT: Import failed for file: /x/y
```

我这次失败运行的日志里就实际出现了 `ERROR REPORT: Impo`。
这条恰好是**出错时给你看的**信息，截断了最影响排查。建议改成 `.*` 或 `[^[:space:]]*`。
