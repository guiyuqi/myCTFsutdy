## 1. 关于 §2 的澄清：它说得对，我的推断错了

我曾在 `notes/02` 里写「`~/.config` 可写……说明当时策略更严」。**这个推断是错的。**

复查指出真正原因是**执行者不同**：

- 它的每条 bash 都跑在 DSH 沙箱内 → 对**它**而言 `~/.config` 按策略只读
- 我的交互式 shell 不在该沙箱内 → 对**我**可写

两件事同时成立。这不影响结论——`XDG_CONFIG_HOME` 依然是正确且**唯一**能让 agent
自主反编译的修法。**它纠正得对，我的归因不准。**

> 教训：我用自己的 shell 结果去推断 agent 的运行环境，这是方法论错误。
> 验证 agent 侧行为必须在 agent 侧做。

## 2. grep 正则 bug —— 确认并修复

它指出的问题**完全成立**。`grep` 的 ERE 在方括号内**不解析** `\r` `\n`，
于是 `[^\r\n]` 实际是「非 `\`、非 `r`、非 `n`」，碰到 `Import` 的 `r` 就截断：

```
$ echo 'ERROR REPORT: Import failed' | grep -aoE 'ERROR REPORT: [^\r\n]*'
ERROR REPORT: Impo          ← 截断

$ echo 'ERROR REPORT: Import failed' | grep -aoE 'ERROR REPORT: .*'
ERROR REPORT: Import failed ← 正确
```

**已修复为 `.*`，并在代码里留下注释说明为什么不能用字符类。**

这条虽轻微但**影响故障排查**——它恰好在你最需要信息的时候把信息截断。

## 3. 动态运行 —— 我此前的判断是错的

复查纠正我两点，我实测确认**它是对的**：

```bash
cd work/fixture-rootfs
./lib/ld-musl-x86_64.so.1 --library-path ./lib:./usr/lib ./usr/sbin/uhttpd -h
```

**实测成功**，打印完整 usage：

```
Usage: ./usr/sbin/uhttpd -p [addr:]port -h docroot
	-c file   Configuration file, default is '/etc/httpd.conf'
	...
```

要点（易踩坑）：`--library-path` **必须同时给 `./lib` 和 `./usr/lib`**，
因为 `libjson-c.so.5` 只在 `/usr/lib`。

**结论修正**：
- x86_64 目标动态运行**零额外工具**（宿主同构，只需 rootfs 自带 loader）
- 我曾说要装 `qemu-x86_64-static` / 准备 OpenWrt rootfs —— **都不必要**
- 异构架构才需要 `qemu-<arch>-static -L <rootfs>`

## 4. 解包工具缺口 —— 已补全（本轮最大改善）

复查把这条列为「唯一实质风险」，判断正确：路由器固件大量使用非标准 squashfs / JFFS2 / UBI。
这条我原本只做到「可装」，现在**已装好并实测**：

| 工具 | 用途 | 结果 |
|---|---|---|
| `sasquatch` | 非标准 squashfs | ✅ 从 Kali 容器提取二进制到 `bin/`，**实测拆出 1069 文件**（与 unsquashfs 结果一致） |
| `jefferson` | JFFS2 | ✅ pip 装 + wrapper，可调用 |
| `ubireader_extract_images` | UBI 镜像 | ✅ pip 装 + wrapper |
| `ubireader_extract_files` | UBIFS 文件 | ✅ pip 装 + wrapper |
| `unsquashfs` 等 | 标准 squashfs | ✅ 宿主自带 |

`sasquatch` 的 PyPI 包**本身是坏的**（缺 `requirements.txt`，元数据生成失败），
所以走的是和 qemu 同样的路子：Kali 容器内 apt 装好 → commit → `docker export` 提取二进制。
它依赖的都是宿主已有的常见库（zlib / lzma / lzo2 / lz4），可直接运行。

**现在"唯一实质风险"已消除。**
