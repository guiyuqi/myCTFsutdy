# 极简二进制协议 · CBC 填充预言机（nc <target>:33221，无附件）

- **flag**: `flag{53a77647-2f62-4145-a546-d9931c1d1e2e}`
- 出处: 用 `op=2` 填充预言机解密 `op=1` 下发的令牌，再经 CBC 比特翻转伪造
  `role=admin`，在同一连接内提交给 `op=3`，服务端返回 `00` + ASCII flag。
- 解题脚本: `work/proto/solve_final.py`（依赖 `oracle.py` / `rb.py` / `pc.py`）
- 证据: `evidence/proto-solve.log`（3 次独立复现，flag 一致）

## 协议框架（交互还原）

```
请求 = uint32 BE length || payload
响应 = uint32 BE length || body            body[0]=状态(00 ok / 01 err)
payload[0] = 操作码；单字节派发，只有 1/2/3 存在
payload 上限 4096 字节（>4096 直接无响应）
```

| op | 语义 | 响应 |
|---|---|---|
| `01` | 下发会话令牌 | `00` + 48B = `IV(16) ‖ C1(16) ‖ C2(16)`（AES-CBC/PKCS#7） |
| `02` | **填充预言机**：把 `args[-32:]` 当两段 CBC 密文解密，padding 合法返回 1 | `00 00` / `00 01` |
| `03` | 取 flag：同连接内令牌解密后 `role=admin` 才给 | `00` + flag / `01 "denied"` |

## 关键判定过程（几个容易走偏的点）

1. `op=2` 需要 **`len(args) % 16 == 0`**；否则一律 0。
2. 随机 32 字节的通过率 ≈ 1/256 —— 正是"随机密文碰巧 padding 合法"的概率。
3. 单字节突变实验里"无关前缀"的长度会变：`op1` 令牌是 20 字节窗口（padding=4
   → `4+16`），随机命中样本是 17 字节窗口（padding=1 → `1+16`）。
   即**相关字节 = padding 长度 + 最后 16 字节**，这就是 CBC padding oracle 的指纹。
4. `op2` 只看最后 32 字节，所以 IV 不参与校验——可以直接当作万能解密预言机使用。

## 利用链

```python
# 1. 同一连接 op1 拿令牌（令牌绑定连接，换连接提交会被拒）
IV, C1, C2 = token[0:16], token[16:32], token[32:48]
# 2. 用 op2 预言机按标准 CBC padding-oracle 逐字节恢复 D(C1)、D(C2)
D2 = pad_attack(C2); P2 = D2 ^ C1      # b'sid=<8hex>\x04\x04\x04\x04'
D1 = pad_attack(C1); P1 = D1 ^ IV      # b'role=user       '
# 3. CBC 比特翻转：只改 IV 即可精确改写 P1
IVp = D1 ^ b'role=admin      '         # 格式必须恰好是 role=admin + 6 空格
# 4. 同一连接提交
op3(IVp + C1 + C2)  ->  00 + flag
```

### 两个决定性细节

- **令牌与会话绑定**：`op3` 只接受"本连接 `op1` 刚下发的那个令牌"派生出的密文。
  在别的连接里提交同一个伪造令牌会得到 `denied`。因此 `op1 → 伪造 → op3`
  必须在**同一条 TCP 连接**内完成（`op2` 预言机查询可以另开连接，它无状态）。
- **role 字段格式**：明文是 16 字节定宽字段，必须正好
  `b'role=admin' + b' '*6`（`role=admin\0...`、`role=administrat`、
  `role=admin`+`0x04`、`role=ADMIN`、`admin` 全部 denied）。
