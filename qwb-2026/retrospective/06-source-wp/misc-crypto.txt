2. 题目分析
容器内容附件是一个MKV容器。用ffprobe里面装了五样东西：
Stream #0:0  Video  (主视频，正常节目画面，结尾约8秒是雪花)
Stream #0:1  Video  (隐藏视频，整段都是雪花，共400帧)
Stream #0:2  Audio
Stream #0:3  Subtitle (SubRip)
Attachment   g2.tar
Attachment   g4.tar

MKV的底层是EBML元素树：Segment下并列着Tracks、Attachments等节点。每条音视频、字幕轨对应一个TrackEntry，按类型各自编号，所以字幕显示为0:s:0；两个tar不在轨道里，而是以Attachment元素挂在Segment下，每个元素带FileName、FileMimeType、FileData三个字段，因此ffprobe只在末尾单列Attachment行，不占用流编号。这决定了后续两条不同的提取路径：轨道用-map选，附件只能用-dump_attachment导。
五类载体实际承载六段文字：隐藏视频轨共400帧，前后各200帧是两段独立文字；主视频只有结尾约8秒（按25 fps约200帧）是雪花；字幕轨200条正文；两个tar各200张图片。音频轨是干扰项，不含信息。
单帧看不见每段素材的200帧里，文字并不是用固定灰度“画”上去的：笔画内部同样填满噪声，单帧看上去和背景没有区别，对多帧直接求灰度均值也会被噪声淹没。真正的差别在时间维度上——背景噪声每帧重新随机生成，同一像素在相邻两帧取相同值的概率约为0.5；笔画覆盖的像素则逐帧复制同一份噪声，相邻帧同值概率接近1。文字是以“时间稳定性”而不是“亮度”编码的。
于是问题转化为一个逐像素的伯努利检验：对每个坐标统计199次相邻帧比较中“相同”的比例，背景期望0.5，文字区域显著高于0.5。单个像素的估计噪声很大（标准差约0.035），但文字是空间连通的，几百个像素的偏差同向叠加，再做空间平滑就能把信噪比拉起来。最后按六段各自的语义把文字排成一句话，即得flag。
3. 解题过程
拆容器先用ffprobe -show_streams -show_attachments核对轨道编号、帧率和附件名，再原样抽取，不需要重新编码：
ffmpeg -y -i challenge.mkv -map 0:1 -c copy hidden.mkv
ffmpeg -y -i challenge.mkv -map 0:s:0 hidden.srt
ffmpeg -y -dump_attachment:t "" -i challenge.mkv

命令细节：
-map 0:1选输入0的第1号流，即隐藏视频轨；-c copy只搬运已编码packet，不重新解码编码，帧数、时间戳、像素值都与原文件一致。若改成重新编码，编码器可能丢帧或补帧，200帧等间隔的前提就被破坏。

-map 0:s:0按“字幕类型第0条”选取，避免和视频流编号混淆。

-dump_attachment:t ""中t限定附件类型，空字符串作为匹配模式表示全部匹配；附件按FileName落到当前目录，得到g2.tar、g4.tar。

两个tar解开后分别是编号零填充的BMP/PNG序列（如000.bmp到199.bmp），按文件名排序即时间顺序。BMP与PNG都是无损格式，不会像JPEG那样在帧间引入压缩抖动，这一点对“相邻帧是否相同”的统计很关键。

取帧时有三点必须卡死：
隐藏轨前后分段：hidden.mkv共400帧，用cv2.VideoCapture顺序读到内存后按[0:<端口>]、[200:<端口>]切开。OpenCV按显示顺序解码，B帧已被重排，所以数组下标相邻就等于时间相邻。若把400帧一起统计，f1ag{S与0f_cM6_会叠加成重影。

字幕正文还原PNG：SRT以空行分块，每块第一行是序号、第二行是时间轴、其余是正文。正文是一条被换行拆开的十六进制串，去掉非[0-9a-f]字符后应满足长度为偶数且以89504e47开头，bytes.fromhex()后再cv2.imdecode即得一张单帧PNG；200条正好200帧。时间轴不参与计算，块的出现顺序就是帧序。

主视频尾段定位：读容器fps与总帧数，start = total - round(fps * 8)，用CAP_PROP_POS_FRAMES跳转后连续读到结尾，取最后200帧。25 fps时8秒正好200帧；帧率不同则按同一公式自适应。

用时间相关性把文字积出来第一步是二值化而不是直接比较灰度：BMP/PNG解码后的像素受调色板和细微抖动影响，两个稳定像素的灰度值也未必逐位相等，直接比较“相等”几乎恒为假。用阈值125把每帧压成0/1位图后，“相同”才有意义——笔画像素的位在多帧间保持不变，噪声像素的位则近似等概率翻转。阈值取125是因为雪花灰度近似铺满0–255，该值落在笔画与背景直方图的谷底附近；过低会把背景划入笔画，过高会削掉笔画边缘，实际可在100–150之间扫一遍确认稳定。
score[y,x] = (1/(N-1)) * Σ_t [ B_t[y,x] == B_{t-1}[y,x] ]

实现时先令prev = frames[0] > 125，从第1帧循环到第199帧，每轮score += (cur == prev)再更新prev，共199次比较，最后除以199。score用float64累加，避免uint8在199次加法中溢出。
统计性质决定了后处理的必要性：零假设下每次比较是p=0.5的伯努利试验，199次的均值标准差为0.5/sqrt(199) ≈ 0.035，文字区若p≈0.55，单像素只有约1.4σ，肉眼仍是一片灰。帧数增加到200以上只能按1/sqrt(N)降低噪声，边际收益有限，所以必须借助空间信息：
高斯平滑：cv2.GaussianBlur(score, (0,0), 2)，ksize传(0,0)时由sigma自动推出约9×9的核。等效平均几十个像素后，噪声标准差降到千分之几，0.05的偏移就变成十几个σ，文字轮廓浮现；半径不能大，否则相邻笔画糊在一起。

对比度拉伸：np.clip((smooth - 0.49) * 2200, 0, 255)。以0.49为基线略低于0.5，保证背景被压到接近0而不误伤偏暗的笔画；增益2200把0.01的差异放大成22个灰阶，0.55处约为132，黑白分明。

先截断后转uint8：np.clip必须在astype(np.uint8)之前。负值直接转uint8会回绕成255，背景整片变白，文字反而被淹没。

帧顺序重排与flag拼接六张恢复图按数据在容器里的存放位置编号为part0–part5，但存放顺序不是语义顺序。按3.2表重排为[0, 1, 4, 3, 2, 5]，即隐藏轨前半、g2、字幕、g4、隐藏轨后半、主视频尾段：
f1ag{S | 3cr3t_ | 0f_cM6_ | h1dd3n_ | 1n51d3_ | 5tr34m}

判断顺序的依据是语义：S3cr3t_0f_cM6是“CMB的秘密”，h1dd3n_1n51d3是“藏在里面”，5tr34m是“stream”，只有这个排列能读通。按存放顺序直接拼会得到跨段的乱码，而np.hstack只做像素拼接、不校验语义，错序只能靠人眼读图发现，所以六张恢复图要分别落盘、逐张核对。横向拼接前按最小高度裁齐各图，才能对齐基线。画面首段写作f1ag{，用数字1冒充字母l，提交时只替换第一处前缀为flag{，其余字符（包括cM6的大小写、下划线和结尾花括号）保持原样，最终flag为：

设计假设是：顾客只碰得到浏览器，kiosk即使被拿下也只是普通用户，D-Bus调用方可信。裂缝在于桌面会话本身就以kiosk身份可交互，而覆盖目录与降级开关都落在kiosk可写处。链能走通不是某行代码写错，是三个假设同时失效。
加载契约管理器的职责是“把组件装进自己的进程”，分三段：发现（厂商目录与覆盖目录按id归并，覆盖优先）、验签（用component-signing.pub校验清单signature）、装载（python走importlib导入entry并回调on_load，native走动态库）。危险在二、三段接缝：验签查的是清单，装载读的是entry指名的另一个文件，签名对象与执行对象分离后，签名退化成“目录准入标签”。叠加可写覆盖目录、可写降级开关、无鉴权重载，契约被按“写入→使能→触发→root装载”逐一击穿。
3. 解题过程
二维码泄漏的动态令牌密钥首屏是「手机动态码验证」，屏幕上直接画着一个绑定二维码。对VNC画面截图后交给OpenCV的QRCodeDetector解码，得到：
otpauth://totp/0perator:KIOSK-07?secret=ULPYXTUIZVJZQRJVWGM2MISRTLZGJTEF&issuer=0perator

漏洞在于：TOTP密钥ULPYXTUIZVJZQRJVWGM2MISRTLZGJTEF直接印在自助机屏幕上（issuer用数字0冒充字母O），任何人扫码即可无限生成6位动态码，“手机绑定+动态口令”形同虚设。
为什么密钥泄漏就等于失守：TOTP是对称的，服务端与令牌端持有同一secret，各算HMAC-SHA1(secret, floor(now/30))再动态截断取6位；secret本身即凭证，所谓“手机”只是它的存放处，把绑定二维码长期画在公共屏幕上等于公开第二因素（issuer用数字0只是品牌混淆）。pattern是浏览器端格式拦截，服务端只做数值比对，绕过无收益；之后靠cookie里的会话标记串联，业务流可脚本驱动。
拿到密钥后按标准TOTP（HMAC-SHA1、30秒步长、6位、Base32解码）在本地生成动态码，提交到POST /totp（前端pattern="[0-9]{6,7}"只是格式校验）。会话用cookiesession=eyJ0b3RwX29r…维持。业务流后续字段：

四个缺陷叠起来就是一条root代码执行链：
/var/lib/0perator/components/user权限为drwxr-xr-x kiosk kiosk，kiosk可写；

python组件include_sha256=False，签名只覆盖清单字段、不覆盖entry文件内容，可以复用厂商已签名清单、只替换face.py；

降级开关/run/0perator/face.status位于kiosk可写的/run下，写入disabled就能让管理器走user-override分支；

D-Bus策略允许user="kiosk"调用ReloadComponents，无鉴权。

按因果顺序把这四点摊开：
可写目录决定“能放东西”：装载读的是文件系统而非数据库，能在覆盖目录造出同id的子目录，管理器就会把它列为候选。

验签范围决定“能否过检”：include_sha256=False对python组件只比对清单字段与签名是否匹配公钥，不看entry文件哈希；native组件用include_sha256=True把.so钉住，所以同一手法对printer-driver无效——这是必须选face-recognition的直接原因。

使能条件决定“候选会被选中”：只有not self._face_disabled()成立时才退回厂商件，而该判断只读/run/0perator/face.status是否为disabled，/run可写，健康判定因此被低权限侧篡改。

调用权限决定“谁能触发”：ReloadComponents无入参、无鉴权，策略放行user="kiosk"，一条dbus-send就能让root进程重走装载。

四者缺一不可：没有可写目录只能看不能改；签名绑内容则替换face.py必然失败；改不了状态则覆盖件被健康判定挡回；调不动重载只能等重启。凑齐后，攻击者做的是“借厂商的合法签名，装载自己的代码”。
利用(1)复制厂商已签名清单

def totp(secret: str, digits: int = 6, period: int = 30) -> str:
    key = base64.b32decode(secret, casefold=True)
    counter = struct.pack(">Q", int(time.time()) // period)
    digest = hmac.new(key, counter, hashlib.sha1).digest()
    offset = digest[-1] & 0x0F
    value = struct.unpack(">I", digest[offset:offset + 4])[0] & 0x7FFFFFFF
    return str(value % 10 ** digits).zfill(digits)

2. 题目分析
附件结构解压后的目录只有三个文件，没有源码工程也没有权重配置文件：

三个较宽隐层的宽度正好是48、40、32，这三个数后面会原样成为置换（打乱）的参数。
model_B.bin是干扰项：长度44982字节，与model_A.npz完全等长；前16字节为3268100616af6522bb081f48d0acf626，形如一个16字节摘要；整个文件的字节分布接近均匀（每个字节值出现频率约200次），既不满足zipfile.is_zipfile，也不是zlib/lzma/bz2压缩流，按float64、float32在任何偏移切片都得不到量级合理的权重值。它是权重被“摇匀/加密”后的黑盒副本，无法直接解析。
解题不需要拆开model_B.bin：model_A.npz已经给出了同一批张量的数值，缺的只是“顺序”。题目真正的考点在check.py——它要的答案是一段索引排列。
check.py的校验逻辑check.py全文只有三十余行，核心是把用户输入规范化后做两级SHA-256：
V = "cf8303ef7e9fc6f51baf27b6e2c8763bd199a0a24c5294bcdaca3ddef6e47864"

def main():
    if len(sys.argv) != 2:

    src = Path(sys.argv[1])

几点关键设计：
输入形式宽松：参数既可以是文件路径，也可以直接是答案字符串（Windows上超长字符串当路径会触发OSError，用except OSError兜底回退成字符串）。

规范化很严：按;切三段、每段按,切、每项int()后重新拼接，因此前导零、空格、多余换行都会被吃掉；答案在文本层面唯一，必须真正生成正确的索引序列，随便加空格不会“碰巧”通过。

两级哈希：先算body = sha256(canon)[:<端口>]（只取前32个十六进制字符，即128位），再算sha256("ns::" + body)与硬编码常量V比对。

flag就是body：body直接构成flag{...}的内容，所以二级哈希只是“防直接读flag”的外壳，真正要做的是还原被哈希的原文，而不是爆破摘要。

V在附件里是明文常量，这给出了一个可判定的终点：只要构造出一段候选规范串，算两次哈希就能立刻判断对错，不需要提交到平台。
权重来自可预测的随机序列对model_A.npz做统计：8个数组共5384个float64，去重后只剩926个不同的值。如果权重是逐层独立抽样得到的连续分布随机数，上千个值几乎不可能出现如此高的重复率，说明权重是从一个候选值池按索引反复取用的。
再用默认位生成器验证：np.random.default_rng(20261101).normal(0, 0.6, 974)产生的974个样本恰好覆盖模型全部926个唯一值，而且k5的第0行（32个值）与样本序列的前32个逐位相同：
k5[0][:5]  = [-1.07367412 -1.10126123  0.5885369   0.40113786  0.03993815]
samples[:5] = [-1.07367412 -1.10126123  0.5885369   0.40113786  0.03993815]
array_equal(k5[0], samples[:<端口>]) → True

这里的相等是float64的完全相等，不是近似相等。池长974是下界而非估计值：模型里最后被用到的那个值位于该序列下标973，取973个样本无法覆盖全部权重，取974个刚好覆盖。
由此得到三条可复用的结论：
权重由default_rng的normal(0, 0.6, N)生成，均值和标准差固定为0与0.6；

种子是整数，且20261101符合YYYYMMDD日期形式，说明种子就是日期；

序列是确定性的，只要种子对了，整个模型可以原位重建；反之种子空间极小，可以直接枚举。

3. 解题过程
提取浮点池与指纹行先把模型压成一个一维浮点池（用于判断覆盖率），同时单独保存k5第0行（用于锁定序列起点）：
with np.load('model_A.npz', allow_pickle=False) as model:
    row = model['k5'][0].copy()
    values = np.unique(np.concatenate([model[name].ravel() for name in model.files]))

选择k5[0]作为“指纹行”有两个原因：它是模型里真实存在的一行，长度32足以排除偶然命中；它的值恰好等于序列的前32个样本并且保持顺序，等于把种子的起点也一起钉死了。如果只用“集合覆盖”判断，序列越长越容易误命中，命中后还要再回头验证顺序，多绕一步。
本步结果：row长度32，values长度926。
枚举日期种子并逐位比对种子既然是日期，枚举窗口取题目发布前后的三个月即可：从2026-10-01开始连续92天（覆盖到2026-12-31）。对每个日期做两步比对：
day = start + timedelta(days=offset)
seed = int(day.strftime('%Y%m%d'))
samples = np.random.default_rng(seed).normal(0, 0.6, 974)
if np.array_equal(row, samples[:<端口>]) and np.setdiff1d(values, samples).size == 0:
    ...

np.array_equal(row, samples[:<端口>])：float64逐位相等，没有容差，避免“看起来差不多”的误判；

np.setdiff1d(values, samples).size == 0：模型全部926个唯一值都必须出现在974个样本里，排除“前32个碰巧相同但整体不对”的假阳性。

枚举结果是唯一命中：
weight seed = 20261101   （2026-11-01）

其余91个日期要么前32个样本不匹配，要么无法覆盖926个唯一值，直接被淘汰。
用相邻种子生成48/40/32置换权重池由20261101生成，那么“摇匀”这一步用的就是同一条随机流的后续调用。default_rng是流式的，同一种子连续取用即可复现；出题人的做法是把权重生成和打乱放在相邻两天的种子上，因此只需在20261101的基础上试-1、0、+1三天，代价可以忽略。
置换参数来自2.1里读出的三个隐层宽度：48、40、32。对每个宽度调用rng.permutation(n)，得到长度为n的索引数组（0..n-1的一个排列，permutation返回新数组，正好适合这种“只要排列”的场景）。三段合并成规范串：段内用,连接，段间用;连接，与check.py的canon规则完全一致。

2. 题目分析
思路概要附件直接给了一个完整的世界模型和权重：服务端接收48步离散动作（每步5选1），用模型"想象"（imagine）未来48步的奖励并求和作为分数，分数过阈值就给flag。所以这题不是盲打，而是离线把模型当白盒，搜一条让reward head输出爆炸的动作序列，再在线提交。
最终这条序列把GRU隐状态推到分布外，单步reward最大冲到564，48步合计1290。
附件分析dreambound/
├── checkpoint.pt    4,245,557 B   torch.save({"config": {}, "state_dict": ...})
├── model.py         1,715 B       模型定义 + imagine() + load_checkpoint()
└── requirements.txt               torch>=2.0, numpy>=1.24

model.py核心：
OBS_DIM, ACT_DIM, H_DIM = 4, 5, 384

class WorldModel(nn.Module):
    def __init__(self, obs_dim=4, act_dim=5, h_dim=384):
        self.gru           = nn.GRUCell(act_dim, h_dim)          # 5 -> 384
        self.decoder       = Sequential(Linear(384,256), ReLU(), Linear(256,4))
        self.reward_head   = Sequential(Linear(384,512), ReLU(),
                                        Linear(512,512), ReLU(), Linear(512,1))
        self.continue_head = Sequential(Linear(384,128), ReLU(), Linear(128,1))

    def step(self, h, a_onehot):return self.gru(a_onehot, h)
    def predict_reward(self, h):return self.reward_head(h).squeeze(-1)
    def decode(self, h):          return self.decoder(h)

@torch.no_grad()
def imagine(model, actions):          # actions: (B, T) 的 long
    h = model.initial(actions.shape[0], actions.device)
    rewards = []
    for t in range(actions.shape[1]):
        a = F.one_hot(actions[:, t], model.act_dim).float()
        h = model.step(h, a)
        rewards.append(model.predict_reward(h))
    return torch.stack(rewards, dim=1)   # (B, T)

解码头decode和continue_head在这题里没被服务用到，真正参与打分的只有GRU + reward_head。
模型的想象结果WorldModel是一个隐空间世界模型：它不预测画面，而是把历史压进384维隐状态h，再用三个头分别解码观测、奖励和终止信号。gru是GRUCell(5, 384)，每步只吃一个5维one-hot动作：
r_t = σ(W_r a_t + U_r h_{t-1} + b_r)
z_t = σ(W_z a_t + U_z h_{t-1} + b_z)
n_t = tanh(W_n a_t + U_n (r_t ⊙ h_{t-1}) + b_n)
h_t = (1 - z_t) ⊙ n_t + z_t ⊙ h_{t-1}

三个门各384维，所以weight_ih是[1152, 5]、weight_hh是[1152, 384]。输入只有5维，携带的信息极少，h_t主要由h_{t-1}和固定偏置决定，动作序列的作用更像"沿着一条轨迹持续轻推"；真正把h推远的不是某一步的神来之笔，而是几十步同向累积。
reward_head是384→512→512→1的MLP，中间ReLU、末端线性。ReLU让它在h上分段线性，末端无激活意味着输出没有上界：只要h落进某个"高奖励扇形"，单步reward可以任意大。decoder（384→256→4）和continue_head（384→128→1）分别是观测重建与终止预测，属于训练世界模型时的辅助头，打分时完全不参与。
imagine()就是"在隐空间里做梦"：从零状态出发喂48个动作，逐步取reward，全程不回真实环境。所以分数衡量的不是"这条策略真能拿多少分"，而是"模型相信它能拿多少分"——题面"Try to dream hallucinate"说的正是这件事。
动作空间与搜索规模服务端要求恰好48个[0,5)整数，组合数5^48 ≈ 2.8×10^33，穷举无望；但单条评估极便宜：48次384维GRUCell加48次小MLP，CPU上批量算上百条也在毫秒级。这种"维度中等、评估廉价、目标确定"的结构适合基于邻域的启发式搜索。每步只有5种取值，邻域也规整：固定其余47步、枚举某一步的另外4种，一次全扫描正好48×4=192条，可以一个batch前向算完，这直接决定了后面的坐标下降方案。
白盒给附件把模型定义和state_dict一起给出，等于把评分函数原样交出：可以本地复现分数、看任意时刻的h、对输入求梯度、无限次批量评估而不受服务端限速。黑盒只能一次次提交换回一个标量，既慢又看不到中间量。所以本题难点不在"猜打分逻辑"，而在"对一个已知函数做组合优化"。
同时这也暴露了设计缺陷：服务端直接对48个reward求和，不clip单步奖励、不约束隐状态范数、也不检查动作是否落在训练分布内，模型在分布外给出的荒谬高奖励会被照单全收。
阈值的大致位置常量策略已经给了参照：全0是7.15、全1是-63.12、全3是24.80、全4是170.51。全4是常量里最好的却仍不返flag，说明阈值明显高于170；按此类题的常见设置，大概率是1000这样的整数。必须找到比最好的常量策略还高数倍的序列，"稍微调一调"到不了，只能真正把隐状态推到模型没见过的区域。
从防御视角看这题本质是奖励模型被对抗性策略利用：
世界模型/奖励模型在训练分布内很准，但对分布外的隐状态会输出荒谬的高奖励；

如果这是真实的RL训练/评估系统，攻击者可以构造动作序列骗过reward model，得到虚高的评估分（reward hacking）；

缓解思路：奖励模型集成/不确定性估计、隐状态范数约束、动作序列分布约束（KL/支持集限制）、对抗训练、以及把"想象评估"和"真实环境评估"交叉验证。

GRU是逐时间步递推的，soft输入（5维概率向量）和one-hot输入产生的轨迹差异很大，梯度指向的"软最优"在argmax后不成立；

还有一层更本质的问题：即使梯度方向是对的，离散动作也没有"步长"可调。logits动一点，argmax可能纹丝不动，也可能整步翻转，梯度给的是局部斜率而不是可执行的离散更新；再加上48步递推中每步雅可比连乘，长程依赖上的梯度要么消失要么被放大，指向的方向在argmax之后往往并不成立。白盒梯度能告诉你"往哪边软一点会更好"，却回答不了"把哪一步改成哪个整数"。

2. 题目分析
服务端流程task.py先跑一遍NTRU/Falcon风格的密钥生成，再用密钥的“自相关多项式”D派生对称密钥，把真实flag加密后输出。核心步骤：
keygen(N=128, q=12289, sigma=19.16)采样高斯多项式f, g（系数标准差19.16），用塔式扩展欧几里得解出F, G，满足
[ fG-gF=q , ]
再做Babai约化控制F, G的范数，最后算出公钥
[ h=g\cdot f^{-1}\bmod q . ]

真正的秘密量是
[ D=f\cdot\mathrm{adj}(f)+g\cdot\mathrm{adj}(g), ]
其中adj是负循环伴随（adj(a) = [a0, -a_{N-1}, ..., -a_1]），所以D就是f与g的负循环自相关之和，系数为整数且很小。

D按十进制、逗号连接后取fk = sha256(b"frozen:" + canon)，密钥流为sha256(fk || counter)逐块拼接，异或flag得到flag字段。

打印pubkey（含h与rho_hint）、memory（泄露的双精度浮点块）、flag（密文）。

：只要能还原整数多项式D，就能算出fk、解出flag，完全不需要求f, g。
把四个多项式都看成商环R_q = Z_q[x]/(x^N+1)里的元素，这套记号会更清楚：负循环乘法中x^N = -1、x^{-1} = -x^{N-1}，所以adj(a)正是a在环内的共轭（把x换成x^{-1}），于是
[ D=a\cdot\overline{a}+b\cdot\overline{b} ]
就是f与g的负循环自相关之和，而不是别的什么“派生量”。再看密钥关系：矩阵[[g,-f],[G,-F]]的行列式恰为q，它把(f,g)送到(q,0)，因此公钥h=g/f只是这个矩阵一行信息的投影，128个模q系数里没有D的直接痕迹；D只活在整数域。其系数量级为sqrt(N)·sigma² ≈ 4.3×10³，而D[0]=|f|²+|g|² ≈ 2N sigma² ≈ 9.4×10⁴，全都远在2^53以内，双精度可以逐个精确表示——这既是“取整即得”的前提，也是后面用叶子中位数估计绝对尺度的依据。
Falcon树的中间量expanded_doubles()先算四个谱fh, gh, Fh, Gh，再构造Falcon的LDL树：
G00 = gh*conj(gh) + fh*conj(fh)
G01 = gh*conj(Gh) + fh*conj(Fh)
G11 = Gh*conj(Gh) + Fh*conj(Fh)
Ltop = G01 / G00
Dright = G11 - Ltop*conj(Ltop)*G00
return [Ltop, _T(G00), _T(Dright)]

_T(E)递归做“折半+归一化”：
Ee, Eo = splitfft(E)          # Ee=(E[:h]+E[h:])/2, Eo=(E[:h]-E[h:])/(2*rho)
L = conj(Eo) / Ee
return [L, _T(Ee), _T(Ee - L*conj(L)*Ee)]

关键性质：
G00就是D在2N次单位根上的取值（G00(ζ) = D(ζ)），所以D是G00的逆NTT；

Dright由Falcon关系满足Dright = q² / G00，因此两个子树其实是同一个D的两种镜像表示；

树的每个内部节点只存一个L，它编码了两个孩子谱的比值，本身不含量纲；绝对尺度由叶子给出。

G00与D的关系设ζ是2N次本原单位根，fh(ζ)=Σ_j f_j ζ^j。因为ζ^N = -1，有
[ \overline{fh(\zeta)}=\sum_j f_j\zeta^{-j}=\sum_j f_j \zeta^{N-j}=\mathrm{adj}(f)(\zeta), ]
于是
[ G_00}(\zeta)=fh(\zeta)|^2+|gh(\zeta)|^2 =f(\zeta)\mathrm{adj(f)(\zeta)+g(\zeta)\mathrm{adj}(g)(\zeta)=D(\zeta). ]
G00在ζ^k (k=0..N-1)上的N个取值正好是D的N点NTT，所以做一次逆变换就能取回D的整数系数。
再看Dright。令
[ S=

[ SS^{\mathsf T}=

]的行列式为q²。因此
[ G_{00}G_{11}-G_{01}^2=q^2 \quad\Longrightarrow\quad D_{\text{right}}=G_{11}-\frac{G_{01}^2}{G_{00}}=\frac{q^2}{G_{00}}. ]
这条恒等式把左右两棵子树绑定在一起：左树给出G00，右树给出q²/G00，两者是同一组未知量的两次独立观测。拟合时把右树的模型写成2·log q - z（z是左树log G00的参数），等价于同时使用两份数据。

节点L的编码内容一次splitfft把长度m的谱E拆成偶数位与奇数位两组，h=m/2，rho_j = exp(iπ(2j+1)/m)。记两个孩子谱为a=Ee、b=Eo，_T里存的节点值是
[ L=t\cdot\rho,\qquad t=\frac{a-b}{a+b}. ]
因为|ρ|=1，从L立刻得到t = L\cdot\bar\rho，进而
[ \frac{b}{a}=\frac{1-t}{1+t}. ]
L只描述“右子与左子的比值”，不携带任何绝对大小；把80个内部节点全部读完，也只能确定谱的相对形状，最后必须靠叶子（E的实部标量）定标。这正是拟合时“内部节点权重0.25、叶子权重取叶子中位数”的原因。
噪声模型：位翻转而不是加性高斯corrupt_blob()对每个double的bit 0..55以及bit 63做翻转：
flipbits = list(range(56)) + [63]
## 当前位为 1 时以 rho10=0.01 翻成 0；为 0 时以 rho01=0.001 翻成 1

这带来两类误差：
bit 0..55：只动尾数低位，相对误差极小（~2^-56量级），属于“几乎无损”的抖动；

bit 63：符号位翻转，数值直接变成相反数，属于粗大误差（gross outlier）。

粗差在L上有一个可检测的特征：正常的|t| ≤ 1，而|ρ|=1，所以物理上必须|L| ≤ 1；一旦符号被翻，L变成-L，模长仍小于1却指向反方向，或者与|L|>1的数值一起出现。拟合时把|L|>1.01和非有限值直接屏蔽，再用soft_l1损失压制残余的离谱点，就能把翻转样本的影响压到可忽略。
冗余还来自树本身：深度d的节点有2^d个，每个节点在同一个下标j上都存了一份L，同一位置的比值被重复测量了2^d次；再加上右树的镜像观测，总共2304个double全部进入拟合。
不过“只动尾数低位”说的是最常见的情形：bit48~bit55落在尾数高位甚至指数区，一位翻转就能把该double抬高或压低几倍，概率虽低，量级上却与符号翻转同属粗差。所以噪声整体是重尾的，既不是干净的高斯，也不是单纯的全有全无，鲁棒损失加掩码这两手必须同时具备。
自由度与冗余度未知量只有n/2 = 64个实数（G00的共轭对称把128个谱点砍半），观测却有2304个double。256个double给出根节点与下一层的L，越往深层节点越短但数量越多，每个下标上的同一比值都有2^d份副本；再叠加右树的q²/G00镜像，等于同一组未知量被独立测量了两遍，整体冗余度约2304/64 = 36。冗余带来两个好处：任何单个double被毁（非有限、符号翻转、高位翻转）都不致命，去掉它仍有大量同位置副本可用；拟合残差因而能被压到1e-10量级，让rint的余量远小于0.05的判据。
3. 解题过程
把整棵树参数化成n/2维不要逐层手工合并，而是把log域的谱值z（n/2 = 64维）当作未知量，用树的结构正向生成全部观测。因为G00是实多项式D在单位根上的取值，它满足共轭对称E(ζ^{N-j}) = conj(E(ζ^j))，所以只需要64个自由度：
idx = np.minimum(np.arange(n), n-1-np.arange(n))
E   = np.exp(z[idx])            # 把 64 维参数镜像成 n 维谱

给定父谱E，两个孩子由splitfft决定。反过来，若已知孩子a, b，则
A = (a+b)/2;  t = (a-b)/(a+b);  L = t*rho
B = A*(1 - t*t)

即：只要给出n/2个谱值，整棵树（所有层的L与所有叶子）都能确定。于是“恢复D”变成一个只有64个未知量、2304个观测的非线性最小二乘问题。
选log域而不是直接拟合谱值，原因有三：谱值恒正且动态范围有1e5量级，取对数后各分量才在差不多的尺度上，优化器的步长不必为最亮的点和最暗的点分别妥协；exp保证参数化后的谱永不越过零点，避免t=(a-b)/(a+b)在a+b→0处爆炸；而单调变换不改变极小点，z到每个观测的雅可比仍可由链式法则解析写出，不必退回数值差分。
稳健最小二乘残差按段加权：内部节点的误差尺度取0.25（L的量级就是1，0.25已经是宽松上界），叶子的尺度取叶子观测的中位数（叶子是绝对量，量级差很多）。同时屏蔽非有限值与非物理值（|L| > 1.01）。
权重要与掩码严格同步：同一个mask必须同时作用在观测、尺度和雅可比的行上，否则残差向量与雅可比的行数会对不上。bounds把z限制在log(scale0) ± 8，即谱值允许在两个数量级内浮动：下界防止某个分量被粗差推到0附近（log发散），上界防止个别点吞掉全部能量；初值取全log(scale0)，等于先假设谱是平的，让优化器自己长出不均匀性。
右树用镜像模型2*log(q) - z，对z的雅可比取负号：
rv, rj = tree_model(2*np.log(q) - z)
v = np.r_[v, rv]; j = np.r_[j, -rj]

这样一次调用就同时拟合了左树与右树。
求解器用scipy.optimize.least_squares配loss='soft_l1'，f_scale从1e-2逐步收紧到1e-10：
for fs in [1e-2, 1e-4, 1e-6, 1e-8, 1e-10]:
    sol = least_squares(..., loss='soft_l1', f_scale=fs, max_nfev=150, ...)
    z = sol.x

为什么要分级？soft_l1在大f_scale下近似L1损失，对符号位翻转造成的整段误差不敏感，先把解拉到正确盆地；随后逐步减小f_scale，损失趋近L2，用剩余的干净样本把解精修到1e-10量级。若一上来就用L2，几个-L的粗差足以把解拖偏。
雅可比是手工推导而非数值差分：对A=(a+b)/2、t=(a-b)/(a+b)、B=A(1-t²)三式求导，得
[ J_A=\frac{j_a+j_b}{2},\quad J_t=\frac{(j_a-j_b)-t,(j_a+j_b)}{a+b},\quad J_B=J_A(1-t^2)-2At,J_t, ]
再乘上rho的对角项与exp(z[idx])的对角项，就得到每个观测对64个参数的偏导。右树把q²/G00写成2log q - z后，链式法则只多一个负号，J整体取反即可，两份数据的雅可比在同一轮里拼起来，避免了两次独立求解可能落到不同局部极小。
逆变换与取整收敛后把z镜像成spec = exp(z[...])，再做逆NTT。注意G00是在ζ^k（2N次根）上采样、而D是负循环多项式，所以逆变换要带一个半格相位因子：
D = np.fft.fft(spec) / n * np.exp(-1j*np.pi*np.arange(n)/n)

那个相位因子不是凑出来的：G00采样在zeta_j = exp(iπ(2j+1)/N)上，也就是2N次本原根只取奇数次幂，而还原D需要偶数次幂的均匀网格。zeta_j^{-k}里多出的exp(-iπk/N)正好补上这半个格子的偏移，所以写成exp(-1j*pi*arange(n)/n)；若直接调用普通的逆NTT，结果会整体错位半格，每个系数都偏一点，自相关结构也随之破坏。
理论上D的系数是整数，实测虚部与小数部分都在1e-10量级，直接np.rint(D.real)即可。为了不把错误结果当答案，脚本做两道保险：
取整误差max|raw - rint(raw)| < 0.05，否则拒绝解密；

自伴随校验D[n/2]=0且D[i] = -D[n-i]，这是D = f·adj(f) + g·adj(g)必然具备的对称性。

从D到flagcanon = ','.join(map(str, D)).encode()
fk = sha256(b'frozen:' + canon).digest()
pt = bytes(a ^ b for a, b in zip(ct, keystream(fk, len(ct))))

这里必须注意三点，任何一处不同都会解出乱码：
D必须是整数且按str(int)、逗号无空格连接；

前缀固定为b'frozen:'；

计数器是4字节大端。

密钥流的生成为
[ \mathrm{ks}i=\mathrm{SHA256}(\mathrm{fk}\parallel i{32,\text{BE}}),\quad i=0,1,\dots ]
拼接后截断到密文长度。
密文字段是十六进制，长度即明文长度；每32字节一个块，最后一块按需截断，块内不再做任何填充。解密结果应当是可打印ASCII且以flag{开头，这个检查比任何概率判据都直接：只要D错了一个系数，fk就完全不同，输出会整体变成随机字节。反过来，一旦看到flag{，基本可以断定D的128个整数全部正确——SHA-256把任何一位错误都放大成了全文不可读。
用公钥独立复核若不想只依赖“取整误差小”这一条判据，还可以从h独立地把密钥捞回来做交叉验证。构造2N×2N的NTRU格基
[ I  H ]
[ 0 qI ]

其中H是h的负循环卷积矩阵。这个格子里同时含有(f, g)及其全部旋转，该行范数约sqrt(2N)·sigma ≈ 217，与q=12289相比小得多，LLL就能把它直接拉出来。对候选行做系数居中（映到[-q/2, q/2]），检查h·f ≡ g (mod q)且最大系数在合理范围内，再用D = f·adj(f) + g·adj(g)重算一遍。两条完全独立的路径给出同一个D，才说明整条反演链没有踩到数值巧合；N=128时LLL只需几秒，BKZ仅在极端实例上才有必要。

## 关键代码：Falcon树模型与最小二乘恢复
def tree_model(z, jac=False):
    """Preorder serialization of the Falcon LDL tree for a spectrum exp(z)."""
    n = 2 * len(z)
    idx = np.minimum(np.arange(n), n - 1 - np.arange(n))
    E = np.exp(z[idx])
    J = E[:, None] * np.eye(n // 2)[idx]
    vals, deriv, leaves, dl = [], [], [], []

    def rec(E, J):
        m = len(E)
        if m == 1:
            leaves.append(E)
            dl.append(J)
            return
        h = m // 2
        a, b = E[:h], E[h:]
        ja, jb = J[:h], J[h:]
        A = (a + b) / 2
        JA = (ja + jb) / 2
        t = (a - b) / (a + b)
        JT = ((ja - jb) - t[:, None] * (ja + jb)) / (a + b)[:, None]
        rho = np.exp(1j * np.pi * (2 * np.arange(h) + 1) / m)
        L = t * rho
        vals.extend([L.real, L.imag])
        deriv.extend([JT * rho.real[:, None], JT * rho.imag[:, None]])
        B = A * (1 - t * t)
        JB = JA * (1 - t * t)[:, None] - 2 * (A * t)[:, None] * JT
        rec(A, JA)
        rec(B, JB)

    rec(E, J)
    return np.concatenate(vals + leaves), np.concatenate(deriv + dl)

def recover(obs, n=128, verbose=False, right=None, q=12289):
    # Internal nodes encode spectral ratios; leaves determine absolute scale.
    scale0 = np.median(obs[-n:][(obs[-n:] > 100) & (obs[-n:] < 1e8)])
    ifnot np.isfinite(scale0):
        raise ValueError('No usable leaves')
    scales = np.r_[np.full(len(obs) - n, .25), np.full(n, scale0)]
    limits = np.r_[np.full(len(obs) - n, 1.01), np.full(n, scale0 * 100)]
    if right isnotNone:
        rscale = np.median(right[-n:][(right[-n:] > 0) & (right[-n:] < 1e8)])
        scales = np.r_[scales, np.full(len(right) - n, .25), np.full(n, rscale)]
        limits = np.r_[limits, np.full(len(right) - n, 1.01), np.full(n, rscale * 100)]

第一段：0x31415926

第二段：0x27182818

密钥扩展的核心代码：
h = (v & 0xffffff) ^ seed;                  // 只保留低 24 bit
h ^= h >> 13;
h *= 0x45d9f3b;
h ^= h >> 16;                               // murmur3 finalizer

for (i = 0; i < 8; i++) {
    h  = h + i * 0x7f4a7c15 + 0x9e3779b9;
    h2 = h;
    h2 ^= h2 >> 13;
    h2 *= 0x85ebca6b;
    h2 ^= h2 >> 16;
    key[i] = (h2 ^ (h2 >> 16)) & 0xffff;
    h = h2;
}

这里有两个细节值得记住：
v & 0xffffff把每段输入截成24 bit，所以7位十六进制的最高4 bit对轮密钥没有任何影响；

第i轮先把常数i*0x7f4a7c15 + 0x9e3779b9加进状态，再做一次murmur3 finalizer（乘0x85ebca6b），取低16位作为轮密钥；下一轮的起点是本次的h2，因此8个轮密钥彼此串联。

轮函数与整体结构加密状态初始化为0xa80处的32字节常量：

0x5349 0x415f 0x4e5f 0x4749 0x5448 0x414d 0x4552 0x2121

0x1357 0x2468 0x369c 0x48ad 0x5be1 0x6cf2 0x7d03 0x8e14

随后执行两次sub_1cc0，分别使用X、Y两段的密钥。每轮中16条lane相互独立，单条lane的变换为：
x ^= x >> 5                         // 每次调用 sub_1cc0 时先执行一次
b = rol16(x, 3)
y = (key[i] + C_lane + b) mod 2^16
y ^= y >> 7
y = rol16(y, 9)
y ^= y >> 5                         // 第 8 轮省略

因此整体加密过程可以表示为：
C = R(K(Y), R(K(X), S))

其中S是初始状态，X、Y是两段输入解析出的整数，K(·)是密钥扩展，R(·)是8轮变换。两次调用各自都带开头那次x ^= x >> 5。把上面这套结构与cipher.bin对照，用已知明文flag{...}跑一遍即可逐字节复现密文e717f224...537527，说明反汇编得到的常量与运算顺序都是对的。
三个可利用的结构性质把轮函数放在一起看，可以得到三条互相独立的结论，第3节的整条攻击链都建立在这三条上：
lane之间完全解耦。轮函数里唯一与lane下标相关的是常量C_j，它是按位置固定的，不含数据依赖。因此16条lane等价于16个互不通信的16 bit小密码，共享同一组轮密钥。

每段加密是双射。单轮由rol3、模加、y ^= y >> 7、rol9、y ^= y >> 5组成，五个操作都是GF(2)^16上的可逆映射，复合后仍是双射。加上开头那次x ^= x >> 5，R(K, ·)整体可逆，逆函数存在且唯一，这正是反向枚举Y段的前提。

密钥空间被压到2^24。因为& 0xffffff，X、Y各自只有2^24种可能的轮密钥序列，且映射v → K(v)可以被完整枚举。

顺带得到一个推论：由于K(·)只依赖低24 bit，密文对7位十六进制数的最高半字节完全不敏感，所以解出的X、Y只能确定到低24 bit，flag写法天然不唯一。这一点会在3.4节量化。
3. 解题过程
单lane可逆由于各lane相互独立，给定密钥后，单lane的每一轮都可以逆运算：
y ^= y >> n可以通过连续异或y >> n, y >> 2n, ...还原（右移后高位补0，迭代16/n+1次即收敛）；

循环左移对应循环右移；

模加对应模减。

于是正向一轮可以写成
[ z=(\mathrm{rol}_3(x)+k_i+C)\bmod 2^{16},\quad w=z\oplus(z\gg 7),\quad y=\mathrm{rol}_9(w), ]
最后一轮之外再补一步y ^= y >> 5。反向只需按相反顺序做“去末尾异或→右旋9→去异或7→减密钥与常量→右旋3”。
去异或右移之所以能用迭代收敛，是因为x ^ (x >> n)是一个上三角线性变换：最高的n个bit保持不变，随后每一位只依赖比它更高的位。因此unxor_r(y, n)从x = y出发，每迭代一次就多修正n个bit，16/n + 1次后必然稳定（n=5时4次，n=7时3次）。这保证反向过程是精确的，不涉及任何近似或暴力猜测。
另一个有用的观察是：由于lane独立，正向和反向都不必算完全部16条lane。给定密钥后，第j条lane的演化只用到key[i]和C_j，与其他lane的中间值无关。这为下文的“部分指纹匹配”提供了合法性——截取前3条lane不是启发式剪枝，而是严格无损的局部计算，只要这段局部结果匹配，整段密钥就必然被唯一确定（至多差一个待排除的碰撞）。
3-lane meet-in-the-middle密钥只有24 bit有效位，所以正向空间是2^24；反向从密文出发的空间同样只有2^24。直接枚举2^48不可行，但lane之间互不影响，可以只比较前3条lane组成的48 bit指纹：
正向枚举2^24个X，计算R(K(X), S)的前3条lane，拼成48-bit指纹并排序；

反向枚举2^24个Y，从密文计算R⁻¹(K(Y), C)的前3条lane，拼成同样的指纹；

在正向表中二分查找对应指纹。

随机假匹配的期望数量为
[ \frac{2^{24}\cdot 2^{24}}{2^{48}}=1, ]
所以前3条lane足够定位唯一解；命中后再用完整的16条lane重新加密一次做最终确认。总代价从2^48降到2^25量级的计算，用numpy分块向量化后在普通单机上几分钟内即可跑完。
工作量可以再具体一点：单次lane计算约8轮、每轮5个基本操作，正向总共2^24次；把候选按20 bit一块向量化后，每块2^20个候选只需几百毫秒。正向表用2^24个uint64存48 bit指纹，约128 MiB，内存完全可控；排序O(2^24 log 2^24)是整个流程最贵的一步，但仍能在一分钟内结束。反向侧不必存表，可以流式生成指纹后立刻searchsorted，额外内存接近零。
随机碰撞的处理也需要交代清楚：期望值1意味着实际可能得到0个、1个或少数几个候选。脚本对每个命中都做一次完整16 lane重加密，只有32字节全部相等才接受，因此多出来的碰撞会被自动淘汰，不需要人为去挑“看起来最合理”的那一个。若某次运行命中0个，说明正向表或反向式的某个细节（比如第8轮是否省略末尾异或）与实际二进制不一致，应回到2.3节逐项核对，而不是扩大枚举范围。

用这组值重新加密初始状态，得到的32字节与cipher.bin逐字节相同（脚本最后会打印cipher-ok=True）。
校验建议分三层做，任何一层不过都说明复现有偏差：先重算两段的8个轮密钥，与手工跟踪密钥扩展的结果对比，确认h的串联方式没写错；再把初始常量按小端uint16读成16条lane，完整跑完两段共16轮，逐字节比对cipher.bin；最后用encryptor本身接收候选flag文本，确认输出文件的MD5仍是03243ad1d8942819f4beaa67c188a578。三层都通过，才能说明常量表、轮顺序、“第8轮省略末尾异或”这些容易出错的细节全部正确。
flag的等价写法密钥扩展中的v & 0xffffff只保留每段输入的低24 bit，因此7位十六进制数的最高4 bit不会影响轮密钥，也不会影响密文。同时，输入校验和strtoul都接受大小写。
所有形如下面的字符串都会得到完全相同的cipher.bin：

flag{0174812_01af718}  ->  X=0x174812 Y=0x1af718  == cipher.bin
flag{...}  ->  X=0x174812 Y=0x1af718  == cipher.bin（最终 flag）
flag{0174813_01af718}  ->  X=0x174813            != cipher.bin

把等价类数清楚会更放心。每段的低24 bit固定，最高半字节可取16种值，而校验与strtoul都接受大小写，所以每段共有16 + 6 = 22种文本形式（10个数字各1种，6个字母各2种）。此外低24 bit内部若含字母，同一数值还会因大小写再翻倍：0x174812与0x1af718的固定部分里共有a、f两个字母，每个字母两写法，合计4种组合。于是等价flag总数为22 × 22 × 4 = 1936个，密文对这1936个字符串完全一致，单靠cipher.bin无法区分，只能由平台给出“官方写法”来选定。官方取值是h1 = h2 = '3'、字母全小写，即flag{...}，其低24 bit恰好等于0x174812与0x1af718，与密文自洽。

def fingerprint(lanes):
    return (lanes[:, 0] | (lanes[:, 1] << np.uint64(16))
            | (lanes[:, 2] << np.uint64(32)))

def encrypt(block, vx, vy):
    st = np.frombuffer(block, dtype='<u2').astype(np.uint64)
    for k in (schedule(vx, SEED_X), schedule(vy, SEED_Y)):
        keys = [np.full(1, t, dtype=np.uint64) for t in k]
        st = forward(st[None, :], keys, LANE_C)[0]
    return st.astype('<u2').tobytes()

p = 0x3ac01f87                      # 985669511，素数
f = x^512 + 885977155*x^511 + ... + 309893591*x + 500564413   # 512 次首一多项式
n = f.degree()                      # 512

def F0():                                    # bit = 0
    s = PR([D() for _ in range(n)])           # 离散高斯，sigma=3.371
    e = PR([D() for _ in range(n)])
    a = PR([randbelow(p) for _ in range(n)])  # 均匀
    b = (a*s + e) % f
    return [a.list(), b.list()]

def F1():                                    # bit = 1
    a = PR([randbelow(p) for _ in range(n)])
    b = PR([randbelow(p) for _ in range(n)])
    return [a.list(), b.list()]

把环摊平成512维。代码里s、e、a、b都是R_p = F_p[x]/(f)的元素，而f的次数是512，所以R_p作为F_p-向量空间的维数就是512，基取1, x, ..., x^511，一个元素等价于一个512维系数向量。乘法不是逐坐标的：先做多项式乘法，再把次数≥512的部分按x^512 = -(f_0 + ... + f_511 x^511)折回。但把a固定成常数之后，映射s ↦ a·s mod f是F_p-线性的，幂基下就是一个512×512矩阵M_a：第一列是a本身，之后每一列都是前一列“乘x再折回”，结构接近循环矩阵，折回系数由f决定。只要gcd(a,f)=1（f无重因子、a随机，概率约1-1/p），M_a就可逆，于是b与a之间不存在“能不能表示”的差别，能携带信息的只剩“表示系数有多小”。

判定问题归约成search-LWE一个样本(a, b)满足什么？
若bit = 0：存在小的s, e（||s||∞, ||e||∞ ≲ 15）使b = a·s + e mod f；

若bit = 1：不存在这样的s。

因为a在R_p = F_p[x]/(f)中几乎必然可逆，任意b都能写成a·s' + e'（取s' = a^{-1}(b-e')），所以“能否线性表示”这件事本身不含信息；唯一的信息是(s, e)能同时很小。这正是一个标准的search-LWE：给定(a, b)，找小向量(s, e)。
两个分布只差在一个“小”字。严格按照分布写，F0输出(a, a·s+e)，其中(s,e)服从Z^{2n}上的离散高斯D_{Z^{2n},σ}；F1输出(a, u)，u在R_p上均匀。这两个分布在计算上不可区分，正是Ring-LWE的判定版本（decisional Ring-LWE）。方向上也很清楚：能区分就能在a·Z^n这个格上解“带噪最近向量”从而恢复s；反过来有了s就能算出e并检查它小不小。所以本题不是求一个全局结论，而是把同一个判定问题独立实例化336次，逐条回答0/1——每条样本的答案互不影响。
于是判定规则很干净：
能在格Λ = {(p z + M_a s, s)}里找到长度~10²的向量，当且仅当bit = 0。
其中M_a是“乘a再模f”这个线性映射在幂基下的512×512整数矩阵。注意这里是整数格：系数先按模p的中心代表元取[-p/2, p/2]，p·z负责消去p的倍数。
格建mult_matrix(a, f)逐列生成a·x^j mod f。因为f首一，有
[ x^{512}=-(f_0+f_1x+\cdots+f_{511}x^{511}), ]
所以从a·x^j右移一位得到a·x^{j+1}时，最高位系数top要按上式折回低位：
nxt[0] = (-top * f[0]) % p
nxt[i] = (cur[i-1] - top * f[i]) % p      # i = 1..511

于是a·s mod f = Σ_j s_j · cols[j]，cols[j]正好是M_a的第j列。取格子
        ┌ p·I_n   0    0 ┐        Λ ∋ (p·z + M_a·s , s , 0)
    B = │  M_a    I_n   0 │        det Λ = p^n
        └   b      0    K ┘        Λ ∋ (b - M_a·s - p·z , -s , K) = (e, -s, K)

最后一行是Kannan embedding：把目标(b,0)塞进去。取K=1，并令z由b - M_a s - e ≡ 0 (mod p)逐坐标给出，则目标向量(e,-s,K)本身就是格里的一个向量。格的秩是2n+1 = 1025，行列式是p^n，与s无关，因此每个样本的格结构完全一致，只有最后一行随b变化。
几处容易忽略的细节。一是det怎么来：按n + n + 1分块，左上角[[p·I, 0], [M_a, I]]是下三角分块矩阵，对角块行列式相乘得p^n·1，末行只动最后一个坐标，所以det B = p^n与a、b都无关——这也是336个格“难度相同”的原因。二是p·I只占前n列：z的作用就是把M_a·s与b的差补齐成p的整数倍，让e落在居中代表元[-p/2, p/2]上；若不做居中，e会被写成接近p的正数，长度立刻变成~p√n，短向量根本不存在。三是最后一列只有末行有K：任何用到末行的整数组合末坐标都是±K，否则恒为0，于是row[2n]=±1就是“这行是Kannan行”的指纹，而row[n:2n]正好是被嵌入的±s。四是K取1：它只负责标记“带b的组合”，取大了反而拉长目标向量、削弱它与普通短向量的差距。
gap大小与可解性dim Λ       = 2n+1 = 1025
det Λ       = p^512
det^(1/d)   = 31080
Gaussian heuristic = det^(1/d)·sqrt(d/2πe) ≈ 2.4×10^5
目标向量    ||(e,-s)|| ≈ sqrt(2n)·σ ≈ 108
gap         ≈ 2232×

Λ里“普通”的短向量长度是~2.4e5，而目标只有108，比格里的其它向量短2200倍，是一个非常极端的uSVP（unique-SVP）实例。这种“gap巨大”的实例正是BKZ最擅长的情况：不需要把格约化到很好，只要能把这一个异常向量“顶”到基里就行。
uSVP、BKZ与“判1”的本质。 uSVP指的是λ_2/λ_1很大的格：这里λ_1 ≤ ||(e,-s,1)|| ≈ 108，其余向量的长度都在Gaussian heuristic2.4×10^5附近，unique gap≈2200。BKZ-β的根Hermite因子是δ_β，能把基中最短向量压到约δ_β^{d}·det^{1/d}；要让它低于2.4×10^5、也就是把异常向量从背景里挤出来，需要δ_β^{1025} ≲ 2200，即δ_β ≲ 1.0075，对应β一百以上——这就是下表β≈120的来源。作为对照，LLL的δ≈1.0219给出1.0219^{1025} ≈ 4×10^9，差了六个数量级，所以LLL在这里毫无希望，必须上BKZ。反过来，对bit=1的样本，格中最短向量就是约2.4×10^5的普通向量，β再大也只能把它约到δ_β^{d}·det^{1/d}，永远碰不到10^2量级；“找不到”本身就是答案，只是它只能以“约化后最短行长什么样”这种统计证据出现，必须配合复算与边界BOUND，而不能看到“最短行不太长”就判0。
环的可分解性f看起来像随机多项式，其实在F_p上是完全可约的：用distinct-degree加equal-degree分解可以得到261个不可约因子，次数分布为
deg 1: 140   deg 2: 56   deg 3: 28   deg 4: 19   deg 5: 8   deg 6: 10

随机512次多项式期望只有~1个线性因子，这里有140个，说明f是刻意构造成“光滑”的。于是
[ R_p=\mathbb F_p[x]/(f)\cong\prod_{i=1}^{261}\mathbb F_{p^{d_i}},\qquad d_i\le 6 . ]
直觉上会想：既然能CRT拆成261个6次以内的小域，那就在每个分量里解LWE。这条路走不通，因为误差在分量里不再小：
e 的系数：        max|e_j| = 10 ~ 13                 （极小）
e mod g（deg 1）：max|centered| = 4.3e8, 2.9e8, 1.3e8  （完全均匀）
e mod g（deg 6）：max|centered| = 4.7e8, 4.4e8, 4.5e8  （p/2 = 4.9e8）

e是次数511、系数≤13的多项式，除以6次因子g后商的系数是~p量级的随机数，e - q·g把小系数彻底搅匀。所以“小”这个性质只存在于系数基（幂基）下，CRT分量里既没有小误差也没有小秘密；何况每个分量只有d个方程、2d个未知数。
结论：f光滑是硬化而不是软化，本题唯一有效的攻击就是整格上的uSVP。标题里的“Ring”三个R，指的就是这个“环不是域”的事实。

2. 题目分析
P/V协议。服务端实现的是GQ身份证明：私钥x，公钥y=x^e mod n。P取随机数r，先给承诺com=r^e mod n，由com的哈希派生挑战chal∈[0,e)，再回res=r*x^chal mod n；验证只需res^e ≡ com*y^chal (mod n)。本题e=2，所以chal只可能是0或1，com必是模n的二次剩余。
V却把私钥本身当成了校验指数：
y = pow(bytes_to_long(FLAG.encode()), x, n)
com = int(input("com>"))
chal = next(gen) % x
res = int(input("res>"))
assert pow(res, x, n) == com * pow(y, chal, n) % n

y在读取com之前就已打印。只要猜中chal=c，令com=y^(-c) mod n、res=1，则左边1^x=1，右边y^(-c)*y^c=1，校验必然通过，无须求flag的x次根。难点只剩chal=next(gen) % x：要知道未公开的x，还要知道生成器的下一个输出。
生成器结构。ECGenerator的构造是：
取两个256 bit素数p, q且p≡q≡3 (mod 4)，令n=p*q，系数a, b随机，曲线Y²=X³+aX+b定义在Z_n上；

初始点A由E_p、E_q上各取随机点再用CRT拼成；

预置k=16个固定平移点Ds；

__next__()输出当前点横坐标，再用int(A[1]) % 16选一个Ds[ind]做加法来更新A。

所以下一步只有16种可能：当前点(X,Y)已知时，下一个横坐标由16个固定平移点之一决定，选中哪个只看未公开的纵坐标模16。预测因此不是复现随机数，而是把16个候选全部算出来、赌一个。
协议层面的两处失效。 GQ的可靠性原本依赖两点：chal足够长，以及单轮通过概率1/e足够小从而重复多轮把欺骗概率压下去。本题e=2，单轮通过概率天生就是1/2，而服务端只跑一轮；更要紧的是零知识性所依赖的前提——com必须真的来自某个随机r的e次幂——从未被检查。验证式只约束三者的代数关系，不约束com的来历，于是攻击者可以按y反推com。把两个接口分开看：P是一台泄露横坐标的预言机（chal=0时res直接给出r），V是一台接受任意com的宽松验证器。单看任何一个都不够，合起来才构成完整攻击链——P提供样本以恢复参数，V提供免费的flag泄漏点。
被打破的是可枚举性而非随机性。每步只有16个候选这一事实，把"预测下一位输出"从"恢复内部状态"降级为"解一组代数方程"：已知当前横坐标X，对16个固定平移点分别解F(X,Z;u_j)=0即得16个Z_j，真实输出必在集合内，与隐藏索引取到哪个无关。Ds在构造时一次性生成、此后固定，这正是攻击可行的关键——同一组(u_j,v_j)在每一步复用，恢复成本只付一次；若每步重采平移点，16个候选就得逐步重算，难度完全不同。出题人选16也有讲究：太小则候选集合小到可以盲试而不必做代数恢复，太大则一次会话内无法把候选全部算出，16正好让"代数恢复"成为必需、又让"枚举加猜"仍然经济。
两个难点是串联的。预测chal要对x取模，故必须先有x；求x要用曲线参数与加法公式，故必须先有n与(a,b,D)。顺序固定为n → (a,b,D) → x → c，任一环算错，最后的表现都是16个候选全不中，与"猜错"不可区分。这也是全流程必须处处自检的原因：只在最后一步失败无法定位问题，只能靠每一步独立的同余检查逐步确认。
3. 解题过程
由证明记录求nP用e=2，每条记录(com, chal, res)满足com=r²、res=r*x^chal (mod n)，其中r正是生成器当时输出的横坐标。chal=0时res=r，坐标直接泄露，于是Δ_i=res_i²-com_i都是n的倍数：
[ n=\gcd_i\left(\mathrm{res}_i^2-\mathrm{com}_i\right). ]
这里有一个容易被忽略的细节：chal=1的记录同样可用。此时res=r*x，于是res²-com=r²(x²-1)，仍然是n的倍数；无论挑战是0还是1，每条记录都提供一个n的倍数，chal=0只是额外把r直接暴露出来，方便事后抽查。实际操作取三到五条记录求gcd即可：单条Δ含大素因子，几条互素的概率极高，gcd几乎必然收敛到n本身，多取反而可能因为某条记录让Δ含额外小因子而引入噪声。
验证方式：取几条记录的gcd后检查位数为512 bit、能整除全部Δ_i，再抽查chal=0记录满足res² mod n == com；若得到的是n的倍数，除掉小因子即可。全程不分解n。这样得到的模数与生成器内部使用的n完全一致，后续所有同余运算都在同一模数下进行；一旦n错了，后面的线性消元会立刻退化，因此这也是一道天然的自检。
恢复平移点与曲线参数设当前点P=(X,Y)加上固定点D=(u,v)后横坐标为Z。消去纵坐标得到只含X,Z,u的双二次关系：
[

]只有16个D，故所有相邻横坐标对(X_i, X_{i+1})都落在16条这样的曲线上。把F视作五个系数c2..c6的线性式，取四条归属同一D的坐标对即可解出，其中还剩一个自由参数t；利用恒等式
[ 4c_3=c_2^2,\qquad 4c_6=c_4^2-2c_2c_5-c_4c_2^2 ]
（关于t分别为二次、三次）消去t，再回代得到u, a, b。实际操作是随机抽样凑齐四对同类坐标，只需线性代数与gcd求逆，不对合数模数开方。
这一步的真正意义在于把"预测下一个输出"化归为纯代数。16个平移点D_j=(u_j,v_j)是构造时一次性生成、此后永不改变的常量，所以每条记录、每一步用的都是同一组(u_j,v_j)，变的只是当前点。给定当前横坐标X与某一对(u_j,v_j)，下一横坐标Z由F(X,Z;u_j)=0唯一确定（另一支对应P-D_j，可用后续记录排除）。因此只要恢复出a, b与16组平移参数，就能对任意当前点算出全部16个候选Z_j，既不需要知道纵坐标Y，也不需要知道隐藏索引int(A[1]) % 16到底取了哪个。
求x并验证chal=1的记录里com=Z²而Z未知。取前一条chal=0的横坐标X和已恢复的F(X,Z;u)=0，代入Z²=com后F对Z退化成一次方程，解出Z并用Z²≡com过滤。该记录又给出res=Z*x mod n，故
[ x=\mathrm{res},Z^{-1}\pmod n. ]
验证：对全部记录令r=res*x^(-chal) mod n，检查r²≡com；若条条成立，说明n与x都正确。
算出16个候选横坐标已知a, b后，F(X,Z;u)=0对u是二次方程，取两条同一平移点的坐标对相减即得一次式，可从记录中找齐16个u并标注每步用了哪个平移点。令f(T)=T³+aT+b，
[ S(X,Z,u)=(X+Z+u)(X-u)^2-f(X)-f(u), ]
加法公式给出S=-2Yv；反向看同一条边可算Y'v。两步共用中间点处，Y'v_i与Y'v_j相除得v_j/v_i，记录连成图后即得16个纵坐标相对基准的比例，仍不需开方。已知最后一步的Yv_i，即可对每个j求出Yv_j并得到
[ Z_j=\frac{f(X)+f(u_j)-2Yv_j}{(X-u_j)^2}-X-u_j\pmod n. ]
预测chal、伪造并取flagV消耗的正是生成器下一个输出：chal=next(gen) % x。末次P的横坐标X已知，故3.4算出的16个Z_j就是next(gen)的全部可能取值，对每个候选取模即得c_j=Z_j mod x。由于Z_j是模n的512 bit量级整数，x也是同量级随机数，Z_j mod x近似均匀，16个候选一般互不相同，也没有额外信息可用于排序，只能任取一个c去赌，单次命中率约1/16。
在V打印y之后提交com=y^(-c) mod n、res=1。校验式是pow(res,x,n) == com*pow(y,chal,n)%n：左边1^x=1；一旦命中使chal=c，右边y^(-c)*y^c=y^0=1，两边恒等。注意这里的指数是x而不是e，但res=1让左边与指数无关，所以等式能否成立只取决于c是否等于chal，与x的具体取值无关，x只在预测chal时被用到。
com与res还必须落在(0,n)内：y是flag的幂，flag的字节数远小于n的256 bit素因子，gcd(y,n)=1几乎必然成立，y^(-c)就是普通的模逆，结果自然合法，res=1也满足范围检查。若隐藏索引恰好命中，服务打印：
Good job! Here is your flag: flag{动态容器已脱敏}

flag的RSA根为何不必求。常规伪造GQ证明要从y解出x次根，即由y=flag^x mod n反推flag，这等同于在不知道n分解的情况下解RSA，代价极大。本题绕开了这一点：com不再是某个随机r的e次幂，而是按公开的y构造的y^(-c)，使验证等式退化成恒等式；服务端只检查取值范围和这条等式，并不检验com是否真来自某个已知的r。所以攻击者所需的输入只有服务在读com前打印的y和一个正确的chal预测，flag本身始终没有被求出。
gcd的实际操作与边界。各条Δ_i都是n的倍数，但倍数里通常还带着r_i²或r_i²(x²-1)这些与n互素的因子，所以单条Δ是1024 bit量级的数，gcd几条后掉到512 bit，位数本身就是判据。取三到五条即可；取太多反而可能因为某条恰好让Δ带上n之外的小公因子而把结果压低，此时乘回去或换样本重来。若得到的是2n之类的倍数，除掉小因子即可，不要对合数模数做质因数分解。求出n后，3.2的线性消元全在Z_n上进行，需要对系数求逆，而模合数下逆存在当且仅当系数与n互素——随机系数几乎必然可逆，偶发失败换一组样本重试；这条失败模式本身也是n正确的旁证。
候选落到c。 3.4的公式为每个平移点给出一个Z_j，取c_j=Z_j mod x即得16个候选。理论上可能有两个Z_j模x相同（x是512 bit随机数，Z_j同量级，碰撞概率可忽略但不为零），实现上按集合去重即可，去重只缩小候选集、不改变命中逻辑。候选之间没有任何可排序的信息——Z_j与x无关联，索引只由未公开的纵坐标模16决定——所以策略只能是任取一个提交，单次命中率约1/16。
提交前的自检。com=y^(-c) mod n用pow的负指数加模数写法即走模逆，res=1。gcd(y,n)=1几乎必然成立，故com落在(0,n)内，满足范围检查；c=0时com=1，连模逆都不需要，同样是合法的1/16。正式发送前在本地算一遍pow(1,x,n)==com*pow(y,c,n)%n，两边都该等于1，这一步能挡掉脚本自身的低级错误。
会话不可复用。每次重连，服务端都重新生成p,q、x与平移点，n、x、(a,b,D)随之全部作废，恢复结果没有跨会话价值。所以脚本必须在一轮内走完"采集300条证明→求n→恢复参数→求x→算16个候选→提交"，命中失败直接断开重来；期望约16轮，主要耗时在采集与线性消元上。

分组加密与故障注入[2]和[3]使用AES-192结构：16字节分组、12轮、24字节（192位）密钥。程序把S盒永久改写了一个表项：
S'[0x06] = S[0xaf]

标准S盒中S[0x06]=0x6f、S[0xaf]=0x79，因此改写后0x6f不再出现，0x79出现两次。故障贯穿整条连接，2500组样本都受同一替换影响。最后两轮连续经过故障S盒，使密文字节的可达值集合出现缺口并伴随重复值；输出端又异或8字节尾密钥重复两次形成的掩码，形成可统计、可差分的结构。攻击目标是恢复轮密钥，由密钥扩展反推24字节主密钥，再解密H1NT_CT得到提示明文。
3. 解题过程
由提示确定704位因子的高位hint.txt去掉换行后共44个UTF-8字节：
gylike{魔法仕掛けのファンタジア}

把它整体按大端解释为整数：
hint = b'gylike{魔法仕掛けのファンタジア}'
H = int.from_bytes(hint, 'big')

虽然占44字节，但首字节0x67只有7个有效位，所以H的实际位长是351。恢复出的素因子q满足
q >> 353 == H
q = H * 2^353 + x,  0 <= x < 2^353

即q的高351位完全等于H，低353位未知，351+353=704正好补齐因子位长。右移353位而非352位，是因为H的首字节只有7个有效位；若右移352位，得到的是2H。这正是题面提示的落点：704位因子减去已知的351位，剩下353位需要求解。
于是构造首一多项式
f(x) = x + H * 2^353

它在模q下有一个小根x0（真实未知的低353位），且f(x0) ≡ 0 (mod q)。恢复x0后即可拼出完整的q。
单变量已知高位小根攻击这是Coppersmith意义下的部分因子已知问题。q为704位，N为1248位，取
beta = 704 / 1248 ≈ 0.5641

单变量模未知因子求小根的渐近根长界约为
X < N^(beta^2) = 2^(beta^2 * 1248) ≈ 2^397.1

其中beta^2 * 1248 = 704^2 / 1248 ≈ 397.13。本题的未知量只有353位，比上界小44位左右，余量充足，不需要把格维数堆得很高。取m = t = 6，格维数
dim = m + t = 12

m决定模q^m的约束强度，t补充高次项；12维已足以让最短向量落在“在x0处取值小于q^m”的范围内，继续增大维数只会增加系数规模。
格构造与LLL约简12维格基的每一行对应一个整数多项式：
前m行：N^(m-i) * f(x)^i，i = 0,1,...,m-1；

后t行：x^k * f(x)^m，k = 0,1,...,t-1。

由于f(x0) ≡ 0 (mod q)，前m行在x0处的取值都被q^m整除；后t行同样含有f(x)^m这一因子，因而也在x0处被q^m整除。为了让短向量对应“在x0处取值小”的多项式，把第j列整体乘以X^j做尺度替换（等价于把x换成X*x），使根落在单位区间内。这样格中短向量的系数被压到同一量级，LLL约简后才容易暴露出共享小根的多项式。
对12维整数格做LLL约简后，取约简基的每一行，把第j列除回X^j（整除性由构造保证，余数必为0），得到整数系数多项式。其中若干行的多项式在x0处满足|g(x0)| < q^m，因此它们共享x - x0这个因子。把这些多项式两两求GCD，即可提取出线性因子，其根就是x0。
最后用
q = gcd(N, H * 2^353 + x0)

得到素因子；只要1 < q < N即命中。取GCD可排除“仅在某个中间模下成立”的伪根，并确认该根确实对应N的因子。

d_q = pow(65537, -1, q - 1)
m = pow(TARGET_CT, d_q, q)

由于m < q，结果就是完整明文，不存在模q剩余类的歧义。按大端转回字节得42字节并解码为flag{动态容器已脱敏}。随后做完整模数回验：
assert pow(m, 65537, N) == TARGET_CT

m^65537 mod N与靶机返回的TARGET_CT逐位相同，说明得到的不是仅在q模下偶然成立的候选明文，而是真正的RSA明文。整个flag推导只依赖[1]的目标密文、N和hint.txt，与余因子r的分解无关。
AES故障攻击与提示恢复分组加密支线使用[2]采集的2500组(16字节明文, 16字节密文)样本。由于S盒被永久改写为S'[0x06]=S[0xaf]，输出0x6f缺失、0x79重复；经过最后两轮后，每个密文字节位置的可达值集合出现缺口，输出端异或的8字节尾密钥又重复两次，使密文前后半块带有相同的8字节结构。攻击分三步：
恢复外层轮密钥。逐字节统计密文取值，得到缺失值集合；枚举其中两两组合，用异或差delta构造候选。对候选缺失输出y，按K11 = InvShiftRows(y ^ InvS[y ^ delta])反推第11轮密钥，再由轮常数推进密钥扩展得到K12。利用前后半块共享同一尾字节的约束筛除候选，得到唯一的故障表、K11、K12和8字节尾密钥。

逐轮反推。用故障S盒的预像撤销最后一轮：密文异或尾掩码与K12后，逐字节取所有S盒预像，只保留唯一状态继续。之后依次撤销K11到K2；每步利用密钥扩展中ShiftRows置换的循环结构，下一轮密钥已知时，当前轮密钥的每个置换循环只需满足若干异或条件，循环约束把多解迅速收缩，逐轮恢复K10到K1，最后回推K0。

恢复主密钥并解密提示。对任一样本完整撤销12轮，与明文异或得到K0；前16字节K0加后8字节尾密钥组成24字节（192位）主密钥。用它重新加密2500组样本，密文全部一致；解密H1NT_CT的3个分组，所得合法UTF-8明文与hint.txt完全相同。

因此AES支线独立给出了同一个44字节提示和同一个H，但不改变flag来源：最终flag仍由3.5用q模解密TARGET_CT得到。
