### NeuronShuffle（平台 630 队解出）
- **官方关键一步**：三组整数**不是类别编号，是三个置换** `np.random.default_rng(20261102).permutation(48)`、`permutation(40)`、`permutation(32)`（三段各自是 `0..n-1` 的完整排列，按 `,`/`;` 拼成 329 字符）。
- **官方路径**：① 全模型 5384 个 float64 去重只剩 **926** 个值 ⇒ 权重取自一个候选池 → ② 假设池 = `default_rng(YYYYMMDD).normal(0, 0.6, 974)`，枚举 2026-10-01 起 92 天，判据是 `np.array_equal(k5[0], samples[:32])` **且** `setdiff1d(unique926, samples)==0` ⇒ 唯一命中 **20261101** → ③ 相邻种子 **20261102** 生成三个 `permutation` 当"摇匀"→ ④ canon → `body=sha256(canon)[:32]`，二次哈希对上 `V=cf8303ef…7864` → flag。
- **我方做到哪**：canon 语义钉死 + 本地零成本 oracle 正负双向对照（`team/NeuronShuffle/evidence/dfp22egtL6Iso8M1-canon.txt` §1、`scripts/b4_poscontrol.py`）；模型结构 32→48→40→32→16 与分块常值 14×32=448 / 12×13=156 / 10×11=110 / 16×10=160（`…-static.txt`）；`model_B.bin` 判诱饵。
- **差在哪**：★核心★ **假设错（解读方向错）**——我们把三组整数钉成"每层神经元的类别编号"（14/12/10 类），所有候选都以**类标签数组**为目标；官方要的是 `permutation(n)` 本身。两处可核查的具体边界：`scripts/b2_seed.py:36-45` 确实跑了 `default_rng(seed).permutation(48/40/32)`，但 ① 只到 `seed < 300000`（正确种子 **2.02e7**，差两个数量级）、② 判据是 `blocked(L[p])`（类标签按置换后成连续块），**即使种子命中也不会通过**。另一处原语缺口：从未在全模型做"5384→926 唯一值池"指纹（`grep 926 team/NeuronShuffle/ work/neuron2/` 零命中）。不是环境、不是算力。
- **一句话教训**：哈希原像题先问"这串数**是谁生成的、能不能重建生成器**"，再问"它语义是什么"；值级指纹（926/5384 去重 + float64 逐位相等）比语义枚举便宜六个数量级，而我们 14.6M 次枚举全都在语义层。

### Dreambound（平台 429 队解出）
- **官方关键一步**：**没有从 `reward_head` 反推动作的闭式解**；把"白盒 = 组合优化"落地成**批量坐标下降 + 随机踢动**——固定其余 47 步、枚举该步另外 4 个值，一次前向 48×4=**192** 条，从全 4（170.51）出发，第 9 轮破 1000、第 14 轮收敛到 **1290.2621**（单步峰值 564.45）。
- **官方路径**：① 裸 TCP 一行 JSON（不带 HTTP 头，HTTP 一律 `bad submission`）摸出协议 → ② 全 1 序列做指纹定 `score=Σ_{t} reward_head(h_t)`（−63.1219）→ ③ 全 4=170.51 已排除"均值/最大值/折扣"三个假设 → ④ 白盒离线批量打分 `(B,48)`，单条 ~0.1 ms → ⑤ 坐标下降 + "随机改两位再重新下降"跳出窄峰 → ⑥ 1290 一次提交（服务端 1290.2773）。
- **我方做到哪**：协议与语义**都对**——`evidence/LrjaG__9f5MrXApw-proto.txt`、`-banner.txt`（裸 TCP、一行 JSON、48 个 `∈0..4`、无 banner、回包 4–6.5 s）；离线 oracle 逐位吻合（`work/LrjaG__9f5MrXApw_dreambound/wm.py`：all-0 7.1453/7.1452、all-4 170.5087/170.5086、随机 317.9697/317.9699）；最好成绩 **318**（未落盘，`team/Dreambound/README.md` 10:33 节）。
- **差在哪**：★核心★ **没跑标准工具（离散坐标下降）**，叠加 **假设错**：我们的战术结论（`team/Dreambound/README.md` §战术结论 1–4）写的是"别 beam → 对 `reward_head(h)` 梯度上升求单步天花板 → 模拟退火/连续松弛"，而官方实测 ST 梯度法 600 步只到 **28.26**（比全 4 还差），结论是"适合离散搜索，不适合梯度"。差距**不是资源**：官方全程纯 CPU 分钟级，而我们手里已经有"该有的原语"（逐位吻合的 oracle + 廉价批量评估 + 5 值离散动作），只差没跑那 192 条邻域扫描。
- **一句话教训**：有精确 oracle + 廉价批量评估 + 小离散动作空间时，第一条该试的是"单步全枚举的贪心坐标下降"，而不是梯度/退火——目标对离散输入是阶跃的（官方单点替换 1290→1133/1041/…/200），连续松弛在这里结构性失效。

### frozen（平台 874 队解出）
- **官方关键一步**：`memory` 里 Falcon LDL 树的根 `G00 = |fft(f)|²+|fft(g)|² = fft(D)`（`D=f·adj(f)+g·adj(g)` 正是 `sha256("frozen:"+D)` 的原像）⇒ 把 2304 个 double 的树当观测，对 **n/2=64 维 log 谱**做 `scipy.optimize.least_squares(loss='soft_l1')`（`f_scale` 1e-2→1e-10 逐级收紧），反 FFT 时带半格相位 `exp(-1j*π*arange(n)/n)`，`rint` 取整（误差判据 <0.05）。
- **官方路径**：① 砍掉头 8N=1024 double（四个谱），按 `2n + 896 + 896 + n + n` 切出左右树 → ② 屏蔽 `|L|>1.01` 与非有限值（bit63 符号翻转是粗差，靠 `soft_l1` 压）→ ③ 64 维 log 谱全局最小二乘，右树用镜像模型 `2·log q − z` 在同一轮拼雅可比（`J` 取负）→ ④ 逆变换 + rint + 自伴随校验 `D[n/2]=0`、`D[i]=-D[n-i]` → ⑤ `fk=sha256(b"frozen:"+canon)`、`ks_i=sha256(fk‖i32BE)` 异或 → flag；⑥ 可选再用 2N×2N NTRU 格 LLL 独立复核 f,g。
- **我方做到哪**：**独立推出同一个关键一步** `G00 = fft(D)`（`work/frozen/notes.md:20`、`work/frozen/handoff.md:5`），并端到端解开**自造**实例：clean blob 3/3 精确、`rho=0.01` 下 **16/20**（均 0.98 s、最大 18.2 s；`work/frozen/bench5.py`、`dec2.py`、`mitm3.py`）。
- **差在哪**：★核心★ **缺环境（真实例）** + **原语缺**。① 这题是动态 flag + 走容器取 pubkey/memory/flag，我方**全程未申请容器、未连远程**（`team/frozen/EVIDENCE.md` §5、`evidence/` 0 文件，队友真解法**未记录**）⇒ 只能拿自造实例做基准；② 相位修复用的是"逐 double 候选 + 分块 MITM"的组合枚举，官方是 64 维**全局鲁棒最小二乘**——所以我们在 20 例里失败 4 例（seed 2006/2010/2011/2014，"残差小但整数错"），官方能把残差压到 1e-10、rint 余量远小于 0.05。方向同路，**恢复算法不同档**。
- **一句话教训**："观测多、坏点少、未知量少"（2304 观测 / 64 自由度 / 36× 冗余）时，正确动作是写残差 + 雅可比做鲁棒拟合，而不是给每个坏位枚举候选；枚举在 `nd≥2` 时真值掉出候选集，正是我们 16/20 的那个 4。

### vmshare（平台 899 队解出）
- **官方关键一步**：`and 0xffffff` 把每半 28 bit 截成 24 bit ⇒ 用**前 3 条 lane 的 48-bit 指纹**做 2^24 正向表 + 2^24 反向查表（期望假匹配 `2^24·2^24/2^48 = 1`），得唯一 `X=0x174812, Y=0x1AF718`（seed 常量 `0x31415926` / `0x27182818`）。
- **官方路径**：① 反汇编确认 16 条 lane 完全解耦、单轮 5 个操作全可逆（`x^=x>>n` 是上三角，迭代 16/n+1 次收敛）⇒ 反向可算 → ② 正向 2^24 排序、反向流式 `searchsorted`，命中后全 16 lane 重算验 32 B → ③ 认下"最高半字节信息已销毁" ⇒ 等价类 **22×22×4 = 1936** → ④ 取**作者原写法** `flag{3174812_31af718}`（h1=h2='3'、字母全小写）提交。
- **我方做到哪**：同一条 MITM 我们自己独立跑出来了 —— `pairs=1`、0 摘要碰撞（`work/vmshare_recheck/mitm.log`）；1936 串逐串真跑原 `encryptor` 全 `exit 0`、`distinct=1` ≡ `cipher.bin`（`evidence/brz2pZwJzt8gV8r6-vmshare/verify.txt`、`evidence/vmshare-keywidth.txt` §0）；提交台账 268 条、正确 0、停扫时判错去重 **253/1936 = 13.1%**（`evidence/vmshare-sweep-summary.md` §3）。
- **差在哪**：★核心★ **判据错（提交次序的先验）**——算法与官方**完全同路、同结果**，唯一分歧是"1936 形式里哪个是作者写的"。我方按"`&0xffffff` ⇒ 补零 ⇒ 首位 0 + 全大写"排优先级（`notes/brz2pZwJzt8gV8r6-vmshare.md` §5），而判定按作者原串**逐字符**匹配：`flag{3174812_31AF718}` 在 `evidence/vmshare-sweep-stdout.log` 第 4 行明确被判"答案错误"，只差大小写。官方 writeup 自己也承认 1936 等价类"只能由平台给出'官方写法'来选定"，**并未记录如何推出 h1=h2='3' 与全小写**。平台节奏 19.3 s/次 ⇒ 扫完 1936 要 ~10 小时，13.1% 时这个策略已注定失败。
- **一句话教训**：密码学侧已无信息时，剩下的就是"作者手写风格"的先验排序问题——别用数值补零去想象字符串（`%07x` 不等于高位写 0），也不要用 19.3 s/次的平台提交去当搜索引擎。

### hoRRibleRing（平台 606 队解出）
- **官方关键一步**：每个样本建 **1025 维 Kannan 嵌入格** `[[pI,0,0],[M_a,I,0],[b,0,K=1]]`（`det=p^512`，GH≈2.4e5 vs 目标 `‖(e,−s)‖≈108`，gap≈2232×），LLL 之后必须上 **BKZ-β≈120** 把这一个异常向量顶出来（`δ_β^1025 ≲ 2200 ⇒ β≈120`；LLL 的 `1.0219^1025≈4e9` 差六个数量级）。
- **官方路径**：① 从 `task.sage` 抽 `p=0x3ac01f87`、`deg f=512` 的 513 个系数 → ② `mult_matrix(a)` 逐列生成 `a·x^j mod f`（折回 `x^512=-Σf_i x^i`）→ ③ 拼 1025×1025 格，`K=1`（取大反而拉长目标）→ ④ LLL 再 BKZ（`max_loops=4, AUTO_ABORT`，β 从低往高加）→ ⑤ 判据只认末位 `±1` 的 Kannan 行，且 `max|s|,max|e| ≤ BOUND=40`（12σ）**复算通过**才判 0，两次符号方向都试 → ⑥ 336 bit MSB-first 拼 42 字节。已知明文（`flag{`+`}` = 48 bit）**只用于标定 β**，一个样本都不省（181 个 0 必须真解出 s）。
- **我方做到哪**：结构全对，且算出了**同一个数**：目标 `σ√1024=107.9`（2^6.75）、GH 2.4e5、gap **2254×**（`team/hoRRibleRing/README.md` §F9/F10、`notes/InT2P9luOG_Em_Ee-hoRRibleRing.md` §D5）；留了自检装置 `work/InT2P9luOG_Em_Ee_r2/score_harness.json`（336 score + 48 已知 label）。
- **差在哪**：★核心★ **判据错——把一条能走通的路自己关掉了，`缺环境` 不成立**。`notes/InT2P9luOG_Em_Ee-hoRRibleRing.md:203` 明写 fpylll+cysignals 已装进 `work/InT2P9luOG_Em_Ee_hoRRibleRing/venv-lll`，`lll3.py:58` 真跑了 `BKZ.reduction(L, BKZ.Param(block_size=beta))`，但 β 阶梯只有 **{10,20,30}**（官方需要 **120**），于是第 206 行判"单样本需 β≈45+ 的 1025 维约减 ⇒ 336 样本不可行，勿再投入"，并在 README「明确别做的 3 件事」写成"别再用 LLL/BKZ 打系数域格"。本机复验：`work/InT2P9luOG_Em_Ee_hoRRibleRing/venv-lll/bin/python -c "import fpylll; BKZ.Param(block_size=120)"` → fpylll **0.6.4**、β=120 可用 ⇒ EVIDENCE §5 的"Sage/fpylll 缺失是硬缺口"**与自家产物矛盾**；Sage 也不是必需（官方 Sage 仅用于取参数/生成样本，PoC 全在 fpylll）。次要细节：我方 Kannan 嵌入用了 `M=140` 缩放（`lll3.py` 的 `check` 只认 `|z|==M`），官方明确 `K=1`。真正剩下的瓶颈是**算力预算**（β=120、维度 1025，fpylll 几十分钟/样本 × 336，G6K 分钟级）——那是"要排队算"，不是"做不了"。
- **一句话教训**：格题要把 gap 换算成"需要多大 β"，而不是换算成"差多少 bit 就放弃"——同一个 2232× 的 gap，官方读作 β≈120（可执行），我们读作"不可行"；β 阶梯的最后一档必须覆盖估算值，否则得到的结论只是"β=30 不够"。

## 最值得写进复盘的两条

1. **"我们有 oracle / 有工具，但没跑那一步"是这场的第一败因，不是环境。** Dreambound（有逐位吻合的离线 scorer，却没跑 48×4=192 的坐标下降，去写梯度/退火）和 hoRRibleRing（fpylll 0.6.4 已在自建 venv 里、`lll3.py` 已在调 `BKZ.Param`，β 只试到 30 就写"勿再投入"）是同一个病：**判据停在"我们试过的档位"，被写成"路走不通"**，而写进 README 后又变成下一棒的禁区。
2. **假设一旦钉错，枚举量再大都是零。** NeuronShuffle 的 14.6M 候选全建在"三组整数 = 类别编号"上（官方是 `permutation`），`b2_seed.py` 既把目标对象搞错、种子窗口又少两个数量级；vmshare 则相反——密码学与官方完全同路同结果，输在"1936 个等价串该按哪种书写先验排"的判断上（13.1% 的扫表 = 70 分钟、0 命中）。**先花 10 分钟问"生成器/书写约定是什么"，再决定要不要枚举。**
