# 团队协调协议（父代理专用）· 强网杯 2026

> 队长 2026-10-31 的要求：**队友解出来的题要及时停手**；**要汇总「哪道解出、哪道卡哪」给团队**。
> 本文把这两件事变成可执行动作 + 判据，不靠记忆。

---

## 0. 先说清能力边界（别把"能"想多了）

| 我能看到 | 我看不到 |
|---|---|
| 平台侧：`red_solved.is_solved`（本队是否解出）、`user_name`+`create_time`（谁什么时候提交）、各队员解出数 | 队友的聊天、本地文件、思考过程 |
| 我自己派的代理的报告 | **队友"正在做哪道题"** —— 平台不暴露 |
| 提交台账、证据 | 队友"已经做出来了但还没提交" —— 那时我完全不知道 |

⇒ 这套机制是**「队友一提交，我立刻停手」**，不是"事先避让"。
**事先避让只能靠人**：队长派题时把题号告诉我，我记进 `work/agent-map.json` 就不会重复派人。

---

## 1. 三个动作

### ① 派单前：判一次（10 秒）

```bash
python3 scripts/qwb-board.py --check <题号>
# 退出码 0 → 可派；10 → 本队已解出，别派；4 → 拿不到题单
python3 scripts/qwb-board.py            # 看全局：哪些已解、哪些可派、平台解出队数
```

### ② 派单后：登记（否则停不了）

派完立刻把「题号 → agent id」写进 `work/agent-map.json`：

```json
{"20261": "<agent_id>", "20265": "<agent_id>"}
```

> 这一步是整套机制的关键。没登记 = 队友解出后我不知道该停谁。

### ③ 每轮回复 / 收到代理报告时：查漏（10 秒）

```bash
python3 scripts/qwb-board.py --stale 600 --submits
```

出现 `★★ 需要立刻停手` 就执行 `interrupt_agent <agent_id>`，并把结果写进
`work/STUCK.md`（"X 题已由 <队友> 解出，代理已停"）。

---

## 2. 汇总给团队：`work/TEAM-BOARD.md`

```bash
python3 scripts/qwb-board.py --write --submits
# → work/TEAM-BOARD.md    可直接贴群里
# → work/team-board.json  给其它工具读
```

内容：队伍总分/排名 → **本队已解出（含平台解出队数、我方是否还在跑）** →
未解出（按平台解出队数升序 = 越前面越可能是"没人做出来"的硬骨头）→ 卡点 → 队员贡献。

`work/STUCK.md` 由我维护，格式：

```markdown
- **20261 Flappy**（Misc）：已跑到"确认是 x86-64 静态链接"，卡在 anti-debug 检测，
  已排除 UPX / 简单 patch；下一步试 unicorn 跑到 OEP。代理 a1b2c3，已用 42 分钟。
```

---

## 3. 停手判定（按优先级）

| 优先级 | 信号 | 动作 |
|---|---|---|
| 1 | `red_solved.is_solved = true`（本队已解出） | **立刻 `interrupt_agent`**，不再派新代理 |
| 2 | 提交记录里出现队友名字（`user_name`） | 同上；顺带确认 flag 是谁交的（要写进 WP） |
| 3 | 平台解出队数很多（>50 队）但本队还没出 | 不是"队友解出"，但**优先级要降**：说明是常规题，别超配 |
| 4 | 平台解出 0 队、我方也卡住 | 保留代理但**换方法跑**（同一目标同一方法别开第二个） |

---

## 4. 与既有纪律的关系

- **不破「一题一代理」**：队友解出只是让我**停**，不是让我**重派**。
- **不破提交门禁**：队友解出后仍要 `verify-flag.py check` + `qwb.py submit`
  （队友交过了就跳过，别重复烧次数——台账会拦）。
- **不破等待协议**：`--check` / `--stale` 是**单次调用**，不是轮询；要等就结束回合。

---

## 5. 开赛 10 分钟内要做的事（模板）

1. `python3 scripts/qwb.py list` 拉题单 → 按 `--board` 的排序决定先打哪几道
2. 向队长确认：**2 台容器给哪两题、由谁申请**（谁申请谁提交）
3. 派第一道题 → 写 `agent-map.json` → 结束回合
4. 收到代理报告或队友消息 → `qwb-board.py --stale` → 需要就停手 → `--write` 更新看板
