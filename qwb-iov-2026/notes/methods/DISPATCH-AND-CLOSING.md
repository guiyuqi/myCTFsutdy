# 派单、收束与止损（本场验证有效的做法）

## 派单：一题一 run，题面带"方法卡片"
本场质量最高的推进来自**人给的 3 步卡片**，而不是让 worker 自由探索。卡片三段：
1. 已确认事实（含**命令与回包原文**）；
2. 下一步只做一件事（可验证判据写在里面）；
3. 停手条件（多少次/多少分钟无结果就收束）。

模板（配 `scripts/tools/dispatch.py --extra`）：
```bash
python3 scripts/tools/dispatch.py --name q1 --category reverse \
  --file ~/ctf-2026/firmware/q1.tgz --reuse run-XXXX \
  --desc "$(cat q1.txt)" --flag-format 'flag{...}' \
  --extra '【只做这一件事】…判据：…；N 次无果即收束，写"已排除 + 下一轮唯一建议"。'
```

## 收束协议（写进 prompt，别指望模型自觉）
> 拿到候选立刻 `submit_flag` → `submit_fact` 写来源（命令+关键输出）→ `commit_step`。
> 这一轮没解出也要收束：写明「已完成 / 已排除（带判据）/ 下一轮唯一建议」三行。
> 每轮 ≤15 分钟、≤40 次工具调用。

## 止损线（本场实测）
- 三道解出全部发生在 **10:30 之前**；之后 90 分钟 0 解出却花掉 ≈103M token（$31）。
- ⇒ **连续 45 分钟无新解出**就停止派新 run，转人工/WP 收尾。
- 单题 token 上限 15M；超了强制收束。
- 最后 30 分钟只做证据固化，不再试新假设。

## 拆题
多附件题（本场"重卡"：BLF/GIF/WAV/ZIP 四路）**必须拆 4 个 run**，一个 run 判据一个。
本场把四路塞进一个 run，850 次工具、37M token、0 结论。
