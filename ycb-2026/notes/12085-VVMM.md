## 解法

题名 VVMM ≈ "VM + VM"（两层：VMC2 容器加密层 + 字节码 VM 层）。附件是 MinGW-w64 PE32+ x64
控制台程序 `VVMM.exe`，自带 `--check/--run/--disasm/--layout/--bof` 和交互 shell。

1. **容器层**：`.rdata` VA `0x140006f60` 处有一个 `"VMC2"` 容器（长度在 VA `0x14000bda0`，= 20016）。
   头部 `[4]` 是 entry 数 = 2，之后是变长 entry：`{u32 h0, u32 h1(低字节=seed 位, 高 16 位=len), u32 chk, data[len]}`。
   解密（`FUN_140002940`）= 逐字节 `plain[i] = data[i] ^ (seed & 0xff) ^ ((mix(i) >> ((i&3)*8)) & 0xff)`，
   `mix` 是 `(i*0x45d9f3b) ^ (h0_low ^ h1_low) ^ 0x9e3779b9` 再走两轮 xorshift-multiply；`seed -= 0x59`。
   校验 = FNV-1a 变体（`*0x1000193` 后 `^= h>>13`）与 `chk == len ^ hash`，并要求明文
   `[0]==1 && u32@4==0xC0DEF00D`。
   - entry#1（288 B）：校验和正确但魔数是 **`0x0BADF00D`** —— 诱饵（"bad food"），被魔数检查刷掉。
   - entry#2（19696 B = **2462 条指令**）：魔数 `0xC0DEF00D`，真程序。
2. **指令层**：8 字节定长 `[0]=opcode, [1]=rd&7, [2]=rs&7, [3]=byte, [4:8]=imm`（跳转按 s32）。
   从跳转表解出 21 个 opcode：`NOP MAGIC LEN LDB LDM STM MOVI XORI ADDI MULI ROLI RORI XORR ADDR
   STAGE CMPI8 CMPI32 JNZ JMP OK FAIL`。`MAGIC`/`NOP` 是无操作，未定义 opcode 直接停机。
3. **程序结构**：`MAGIC` → `LEN 0x1F`（输入必须 31 字节）→ round0 共 31 个 stage
   （`LDB` 取输入字节 → `XORI` → `ADDI` → `ROLI` → `STAGE` → `STM`）→ round1..7 各 31 个 stage
   （`mem[i] = rol8((mem[i]+mem[i+1]) ^ mem[c]) + d`，7 轮混合）→ 末尾 `0x4a00..0x4cd8`
   31 组 `LDM r0,i ; CMPI8 r0,expected` → `0x4ce0 OK / 0x4ce8 FAIL`。
4. **求逆**：发现 `STM` 只写低字节、`LDM` 零扩展读字节、`ROLI/RORI` 只旋转低字节（高 24 位保留），
   所以整条数据通路其实是 **8-bit**；用 z3 把 31 个未知字节符号化执行 2462 条指令、断言 31 个
   `CMPI8` 的期望值，SAT 一次出解。
5. **落地验证**：用 Unicorn 直接执行原始 PE 的 `FUN_140003480`，flag 返回 1（`steps=2460, pc=0x4ce0,
   halt=0xf0`），末字节翻转一位的近似串返回 0。

## 坑

1. **wine 不可用**（本沙箱 `/run/user/1000/wine` 只读，wineserver 建不了 socket，`wine cmd /c echo`
   都返回 1 且无输出；改 `WINEPREFIX`/`XDG_RUNTIME_DIR` 都没用）。**判定依据**：`wineserver -p` 直接
   报 `mkdir /run/user/1000/wine: Read-only file system`，且 prefix 只建出空 `drive_c`。
   → 改走 Unicorn 仿真（map PE + IAT 打桩），反而更好：能直接按函数调用 + 读 state 结构拿指纹。
2. **Ghidra 反编译在 VM 解释器上不可用**：`FUN_140003480` 被 GCC 自动向量化成 `paddb/punpcklwd/...`，
   C 伪代码里全是 `auVar60._0_8_` 这种东西。**判定依据**：`fw-decompile` 出来的该函数 500 行全是
   `auVar` 位域拼接。→ 改读汇编 + 解码跳转表，20 分钟搞定。
3. **最大的坑：`STAGE` 不是无操作！** 我第一版把它当 `nop`，z3 解出 31 字节二进制垃圾、真机 REJECT。
   教训是**差分 fuzz 只比对 ACCEPT/REJECT 是无效验证**——绝大多数随机程序两边都 REJECT，
   "0==0" 会被误判成模型正确（我跑了 60 例"全过"，其实全是 0==0）。
   → 换成比对 **(ret, steps, pc, acc) 四项指纹** 才暴露出 off-by-one 之外的真实差异；
   再用「前缀截断 + `LDM/CMPI8` 探针」二分，定位到把 `STAGE` 插进 `ROLI` 与 `STM` 之间就会改写 r0。
   `STAGE rd,imm` 的真语义：`regs[rd] = d10(imm, regs[rd]&0xff)`，
   `d10(a,b) = (rol8((b^u)&0xff,(3a+1)&7) + a*0x31 + 0x42) ^ ((u&0xff)>>1)`，`u = ce0(a, 0xa5)`，
   `ce0` 是 murmur3 finalizer；即 STAGE 是个**双射字节混淆器**。
4. **自造字节码 = 关键实验手段**：容器加解密完全可逆，所以我写了 assembler + encryptor
   （`tools/build.py`），把任意小程序重新加密塞回 blob 喂真机——这样每个 opcode 的语义都能
   单独做探针（比 `--disasm` 强，因为 `--disasm` 只给反汇编不给语义）。
5. 一个纯算术小错：`FUN_140002ce0` 的乘数是 `0x9e3779b9`（`-0x61c88647`），我一开始手写成
   `0xc39c79b9`，导致只有 `k=0` 的探针对上。**判定依据**：`objdump` 里 `imul ecx,ecx,0x9e3779b9`。
6. 题目里 `--bof` 模式（`[bof] send up to 512 bytes, then inspect the saved return address`,
   校验和 `0x42` 分支）是 pwn 味道的**旁路彩蛋**，与 flag 无关；`[audit] checkpoint` 也只是把
   31 个期望字节再混淆一遍打 FNV 哈希，不是 flag 本身。没有发现 prompt injection 字符串
   （`prompt`/`instruction` 命中处都是正常 usage 文案）。
