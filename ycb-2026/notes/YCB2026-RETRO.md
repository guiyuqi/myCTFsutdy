## 4. 方法论复盘

### 4.1 技能层终于真正用上了
每题 brief 里写死技能名、报告里强制 `SKILLS:` / `SKILLS_USED:` 两行 ⇒ 本场每个代理都给出了**具体的判据**而不是"我参考了技能"。可迁移的判据举例：
- `competition-reverse-pwn`「先被动 triage（file/checksec/imports/strings）再定 reverse-first / exploit-first」→ 由 `imports` 看到 seccomp 禁 `execve` + `dup2(…,7)`，直接否掉"拿 shell"，改走"作者预留 ROP gadget + fd 7"（12078）。
- `ctf-pwn` checksec 决策树（Full RELRO ⇒ 不打 GOT，改打返回地址）+ safe-linking 公式 ⇒ 12077 全链主线。
- `competition-template-render-path`「渲染管线与处理器分开取证」→ 由 PDF 元数据 `Producer: cairo / Creator: Mozilla Firefox` 判定是 Firefox 打印链，毙掉 WeasyPrint CVE 路线（12061）。

### 4.2 ★ 三次"判据修正"——比三个 flag 更值钱
| 场景 | 旧判据（错） | 推翻它的证据 | 修正后判据 + 边界 |
|---|---|---|---|
| 12077 | `op 0x23/0x33` 只能写"被门钉死的固定值" ⇒ **写原语缺失** | `strings` 见 glibc 2.35 的 `malloc(): unaligned tcache chunk detected` ⇒ safe-linking 开启 | 该式 `(chunk>>12)^(PIE+固定)` **正是**把 tcache next 指向 `.bss` 的合法编码 ⇒ 它就是投毒原语。**边界：仅 glibc ≥ 2.32** |
| 12061 | `text/plain` 分支 escape、`text/html` 分支解析（两分） | 前期真靶机产物里 `RAWHTML-OK-1` 单独成行、`<iframe>` 转义 | **单管线**：`输入 →(text/plain 才跑 markdown)→ HTML → sanitize-html(白名单 + allowedSchemes 仅 http/https/ftp/mailto/tel)` ⇒ `<img src=file://…>` 的 src 被整条剥掉、**根本没发请求**（"盲 SSRF 可用"因此撤回） |

### 4.2b ★ 第五次"判据修正"——本场最贵的一次（12080）

| 项 | 内容 |
|---|---|
| 假判据 | `sha256.txt`（`cfde9ebf…`）被判为"ZIP 口令的 SHA-256"。四个跑者在此之上穷举：`36^6`=2.18e9、`P(8,6)`、38M 装配变体、27M rotate-jam、rockyou 14.3M+10M |
| 真判据 | **AES-256 压缩包自带的 10 字节 HMAC-SHA1 认证码**（WinZip-AES）。`zipfile` 不支持，但 20 行 `hashlib.pbkdf2_hmac`+`hmac` 可写 |
| 结果 | 换成真判据后，**同一个 `P(8,6)` 空间第一轮就命中**；`sha256(真口令)=0193fddd…` 与 `sha256.txt` 无关 |
| 教训 | **"穷举已死"必须先验证判据本身**。判据错 ⇒ 全盘皆错，而且**搜索规模越大越像"已证死"**（这正是它骗过四个跑者的原因） |
| 破题的那句话 | 父代理反复说的一句：「`sha256.txt` 到底是不是口令的哈希？先看 `flag.txt` 结构、先本地 `unzip` 自验」——**判据可疑时，去问"最硬的那个验证器是什么"**，而不是加大搜索量 |

### 4.5 加时攻坚记录（12073 xmlbridge，14:00–14:45）——虽未出 flag，但这是本场工程含量最高的一段

**目标**：把一道被我们两次判成"不可解"的题（先判"交付缺陷"、再判"门禁恒 0"）打到出 flag。

**打通的部分**（全部本地可复现，`notes/12073-xmlbridge.md` 882 行）：
1. 方法论纠错：`B` 的 `ERR` 不是门禁给的（前面还有 `myDoc==0`/`wellFormed==0` 分支）；
2. 门禁 = 唯一 4 字节（gdb patch 证明）；绕过机制 = **libxml2 dict 哈希表越界插入**：
   `E` free 0x500 → `A` 的 `xmlDictCreate` 复用 → validity 错误(534) 回调把 `dict->size 0x80→0x81`
   → `hash%0x81` 越界 bucket 128 → 插入硬编码 `okey=1` 正好落在 `g_doc+4`。**线上可概率命中**；
3. **五服务本地复刻**（socket 路径等长改写 + oracle flag 路径改写）⇒ 不占容器、可无限次试协议；
4. **broker 全解 + ROP 生效**（`NOTE/VIEW` 任意读泄 libc/PIE/fd；`COMMIT` 无 canary 溢出 ret@0x108）；
5. **"跳两跳"捷径在本地跑通：整题只需 1 个 pwn**
   （broker ROP → `socket/connect(oracle.sock)` → `PROGRAM`/`RUN` → flag）。

**线上被卡住的点（本场最有价值的一条环境结论）**：
- 对照实验（同一会话只改一处）：只 `write` 正常；**一旦链里出现 `socket()`，进程立刻被杀（EOF）**；
- 附件里 broker 的 seccomp 静态解码显示 **41/42（socket/connect）未被拦**（拦的是 59/322/2/257/437/40/275/278/326）；
- ⇒ **线上部署的沙箱比附件那层更严，作者预判并堵死了"直连下一跳"**。
- 换句话说：**出题人把"最短路径"在附件里留了、在部署里堵了** —— 这是"交付与附件不一致"的一种**有意为之**版本，
