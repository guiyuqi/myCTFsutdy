## 1. 沙箱结构（app.py）

- `POST /run` 收 JSON `{"code": "..."}`；长度上限 5000，超时 5s，输出上限 100000。
- `run_sandbox()` 三道关卡：
  1. `unicodedata.normalize('NFKC', code)` —— 先做 Unicode 规范化（同形字技巧被拉平）。
  2. **46 条正则黑名单**（`dangerous_patterns`）对 **原始文本** 做 `re.search`。
  3. `ast.parse` + `ASTFilter` 访问者（`visit_Import/ImportFrom/Attribute/Call/Subscript`）。
- 执行：`exec(code, {'__builtins__': dict(SANDBOX_BUILTINS)})`，
  `SANDBOX_BUILTINS = builtins.__dict__` 仅剔除 `breakpoint`、`input`。
  → **`open` 本身就在 builtins 里**，只是名字被"点名"封了。

## 2. 绕过点（三个独立缺陷叠加）

### 缺陷 ①：`print.__self__` 就是 builtins 模块
`print` 是 C 内建函数，`print.__self__` → `<module 'builtins'>`。
`__self__` **不在** `DANGEROUS_ATTRIBUTES`（那里只封了 `__class__/__base__/__subclasses__/__globals__/...`），
于是 `print.__self__.__dict__` 直接给出完整 builtins 字典。

### 缺陷 ②：字典下标绕过正则 + 绕过 AST 常量检查
- 黑名单是对 **源码文本** 做正则：把名字拆开拼接，如 `'__imp'+'ort__'`、`'op'+'en'`、`'re'+'ad'`，
  正则永远看不到连续 token。
- `ASTFilter.visit_Subscript` 只拦 `ast.Constant` 字符串切片：
  ```python
  if isinstance(node.slice, ast.Constant) and isinstance(node.slice.value, str)
  ```
  切片写成 `BinOp`（`'op'+'en'`）就不再是 Constant → 直接放行。
- `visit_Attribute` 只检查**属性名**，不检查下标字符串；所以 `__dict__`（未封）可用。

### 缺陷 ③：`.read` 被封 → 改用文件对象迭代
`read/write/readlines/writelines` 都在 `BANNED_METHODS` 里，`f.read()` 行不通；
但 `for _l in f:` 不触发任何被封属性，照样读出内容。

### 最终 payload（已离线验证可执行）
```python

# 读 flag（不碰 .read）

```
