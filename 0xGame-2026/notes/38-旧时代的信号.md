## 附件

```
$ file attachment3.EXE

```

「此应用无法运行」→ 现代 64 位 Windows 直接拒绝跑 16 位 DOS 程序。
题目描述「旮旯给木」= galgame 的谐音梗，纯氛围，无技术含义。

## 关键点：MZ 头里藏着载入布局

```
$ xxd attachment3.EXE
00000000: 4d5a c000 0100 0000 0200 2000 ffff 0000  MZ........ .....
00000010: 0002 0000 0000 0000 1c00 0000 0000 0000  ................
00000020: <-------- 代码从这里开始 -------->
```

| MZ 字段 | 偏移 | 值 | 含义 |
|---|---|---|---|
| bytes on last page | 0x02 | 0x00c0 | 文件正好 192 字节 |
| header size | 0x08 | 0x0002 | 头 = 2 段 = **0x20 字节** |
| initial SP | 0x10 | 0x0002 | |
| initial IP | 0x14 | 0x0000 | 入口 = 镜像偏移 0 |
| initial CS | 0x16 | 0x0000 | |

**所以载入镜像 = 文件去掉前 0x20 字节**，镜像偏移 X ↔ 文件偏移 0x20+X。
（第一次用 objdump `--adjust-vma=0x100` 看，vma 与文件偏移差 0x100，容易搞错
DS:SI 的绝对位置；正确换算：文件偏移 = vma − 0x100 + 0x20。）

## 算法

```
k      = 0xa7
p[i]   = (ror(c[i], 3) - 7 - i) ^ k   (mod 256)
k_next = ror? no -> rol((k + p[i]) & 0xff, 1) ^ i
```

```
f4 fe 88 c2 d2 54 64 06 28 d5 bd b6 65 58 4d 1d 56 7e 0b 99
e6 f2 a4 55 7d 21 83 96 e1 10 0d 4f 5c
```

## 双重验证（关键，避免自欺）

1. **手写 Python 复刻**循环 → 得明文 33 字节，全部是可读 ASCII，以 `0xGame{` 开头、`}` 结尾。
2. **unicorn `UC_MODE_16` 真机仿真**：把载入镜像放到 `SEG=0x1000`，
   `CS=DS=ES=SS=0x1000`，**SP 必须给值**（原 MZ 头 SP=0x0002，
   unicorn 里若 SS:SP 未映射，第一条 `push cs` 就 `UC_ERR_WRITE_UNMAPPED`），
   从镜像偏移 0 起跑 → 内存 0x7e 处字节与手算结果 **完全一致**。

> 踩坑记录：unicorn 的 `emu_start(begin, …)` 在 x86 下 `begin` 是
> **相对 CS 基址的偏移**，不是线性地址；传 `BASE+0x120` 会跳到 BASE+0x20+0x120
> 的零填充区，得到 33 个 `\x00` 的假结果。传偏移量 `0x0` 才对。
