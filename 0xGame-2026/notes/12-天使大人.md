## 题目在算什么

附件脚本拼 4 个互不相关的数学量，拼成字符串后取 sha256：

```python
data = f"{field_value}|{norm_value}|{det_value}|{order_value}"
print(sha256(data.encode()).hexdigest())
```

| 量 | 来源 | 值 |
|---|---|---|
| `field_value` | GF(2^8)（模 `x^8+x^4+x^3+x+1`）中 `v = r1*r2 + r3` 的整数表示 | `88` |
| `norm_value` | 数域 `Q(θ), θ³-θ-1=0` 中 `u = θ⁸+3θ⁵-2θ+7` 的范数 | **`2645`** |
| `det_value` | 4×4 整数矩阵 `B` 经 LLL 后的 `abs(det)`（= `abs(det B)`） | `1149364915685671` |
| `order_value` | 椭圆曲线 `y²=x³+2x+3 over GF(10007)` 的阶 | `9846` |

`data = "88|2645|1149364915685671|9846"`
`sha256(data) = e834598ba8cf6695cc9299364fe4fa63b05a1b55f847ab5aecb6d5dc251e2b77`

## ★ 唯一但致命的坑：数域是特征 0，不是 GF(2)

题目前半段在 GF(2^8) 里算，很容易顺手把后面的 `NumberField` 也按特征 2 处理。**这是错的**：

```
θ³ = θ+1
θ⁴ = θ²+θ
θ⁵ = θ²+θ+1
θ⁶ = θ²+2θ+1      ← 2θ 必须保留
θ⁷ = 2θ²+2θ+1
θ⁸ = 2θ²+3θ+2     ← 不是 θ！
u  = θ⁸ + 3θ⁵ - 2θ + 7 = 5θ² + 4θ + 12   → norm = 2645  ✅
```

首轮我把 `θ⁶` 写成 `θ²+1`（把 `2θ` 当特征 2 消掉），于是 `θ⁸` 被算成 `θ`，
得到 `u = 3θ²+2θ+10`，`norm = 1487` → 整个 sha256 全错，容器判为
`result = it's OK to try again`。

**教训（重要）**：当时我用了三种方法校验范数（乘法矩阵行列式 / sympy Resultant /
三个共轭数值相乘），**三种全给出 1487** —— 因为它们校验的是同一个已经写错的输入。
**多方法交叉校验只能验算，不能验建模**：约简规则（特征）本身的正确性必须单独确认。

## 其它已确认点

1. **本机没有 sagemath 且禁止 pip install** → 纯 Python + sympy 逐行等价实现：
   GF(2^8) 手写无进位乘法 + 模 `0x11B` 约简；数域范数用乘法矩阵行列式 +
   `resultant` + 数值三重校验；真跑了一遍精确有理数 LLL（`Fraction`）并与
   `|det B|` 对照；椭圆曲线阶用 QR 集合 / 逐点开方 / 勒让德符号和三种方法数。
2. **哈希输入串没有结尾换行**：`print()` 只在输出时补 `\n`。
3. **GF(2^8) 的 `a` 是 `x`(0x02)，不是本原元**：`0x02^51 = 1`。
   用 log/antilog 表做校验会踩坑（我第一次交叉校验因此得到 0x31，已排除）。
4. **`det_value` 与 `order_value` 首轮就是对的**，只有 `norm_value` 错。

## 容器协议（实测）

`nc1.ctfplus.cn 21450` 是**原始 TCP**（`curl` 会报 `Received HTTP/0.9 when not allowed`）：

```
连上 -> "result = "                (9 字节，无换行，随后阻塞等一行输入)
正确 -> "result = 0xGame{...}\n"
错误 -> "result = it's OK to try again\n"
EOF  -> 只输出 "result = " 后静默退出（EOFError 被吞掉）
```

发送非 ASCII 字节可触发服务端栈回溯，暴露实现（`evidence/12-output.txt` 末尾有全文）：

```
File "/app/challenge.py", line 21, in main
    if compare_digest(answer, EXPECTED_ANSWER):
TypeError: comparing strings with non-ASCII characters is not supported
```

→ 精确字符串比对，用的是 `hmac.compare_digest`（常数时间，**没有 timing 侧信道**），
所以答案必须精确命中，靠试格式是试不出来的：**必须先把数学算对**。
