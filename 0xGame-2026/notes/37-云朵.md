## 一句话结论

「闪过去的东西」就是窗口类名 **`CloudFlashWindow`** 的字面意思：程序在 `WM_PAINT` 里
把藏在 `.rdata` 的密文用 **RC4** 解密后 `DrawTextA` 画到窗口上，紧接着 **`DestroyWindow`**，
所以 flag 只在屏幕上闪一帧。密钥 `ShedaLight` 就以**明文**躺在 `.rdata` 里。

## 静态分析路径

`file` → PE32+ x64 GUI，导入表只有 `KERNEL32/msvcrt/USER32`，纯 Win32 窗口程序，
没有反调试、没有壳、没有网络，**不需要动态跑**。

`strings` 一把命中（这是破题点）：

```
0x405000  CloudFlashWindow      <- 窗口类名，也是"闪"的暗示
0x405018  0xGame2026            <- 窗口标题
0x405028  Your flag is          <- 输出前缀
0x405038  ShedaLight            <- ★ RC4 密钥（明文！）
0x405050  d7 8c 35 ac a1 ff a3 57 0c 79 e7 13 e7 bc ff 8b   <- 26 字节密文
0x405060  99 54 5c 68 73 70 dd 44 77 f0
```

`objdump -d` 交叉引用定位主逻辑：

| VA | 作用 |
|---|---|
| `0x401550` | **RC4 KSA**（S 盒初始化 + 打乱；`div [rbp+0x20]` 即 `i % keylen`） |
| `0x401620` | **RC4 PRGA / 就地解密**（`buf[i] ^= S[(S[i]+S[j]) & 0xff]`） |
| `0x401871` | **WndProc**；`cmp [rbp+0xe8], 0xf` → `WM_PAINT` 分支 |
| `0x401aa2` | WinMain（`CreateWindowExA` + `ShowWindow` + 消息循环） |
| `0x401d40` | 画完之后调用，最终走到 `DestroyWindow` → 字一闪即消 |

### WndProc 的 WM_PAINT 分支（0x401871 起）

```asm
4018aa  cmp  [rbp+0xe8], 0xf          ; WM_PAINT
4018b1  jne  0x401a6b                 ; 否则 DefWindowProcA
...
40191a  mov  rax, [rip+0x372f]        ; 0x405050  <- 密文前 8 字节
401928  mov  rax, [rip+0x3729]        ; 0x405058  <- 次 8 字节
401936  mov  rax, [rip+0x3723]        ; 0x405060  <- 再 8 字节
401944  movzx eax, word [rip+0x371d]  ; 0x405068  <- 末 2 字节 (共 26)
        ; 目标缓冲 [rbp-0x50]
401959  mov  r9d, 0xa                 ; keylen = 10
40195f  lea  r8,  [rip+0x36d2]        ; 0x405038 = "ShedaLight"
401966  mov  edx, 0x1a                ; 长度 = 26
40196b  mov  rcx, rax                 ; 缓冲
40196e  call 0x401620                 ; ★ RC4 解密（就地）
...
401986  mov  rax, [rip+0x369b]        ; 0x405028 = "Your flag is "
4019b2  call 0x403238                 ; strcat(前缀, 明文)
401a0c  call [0x409458]               ; DrawTextA(hdc, 文本, -1, &rect, 0x25)
401a1f  call 0x401768                 ; 输出 "YOU GOT IT!!!" 到控制台
401a33  call 0x401d40                 ; ★ 立刻销毁窗口 → "闪过去"
```

注意 `0x403238` 是 `strcat`：先把常量 `"Your flag is "` 拷进缓冲，再把解密结果拼在后面。
`0x401768` 里还硬编码了 `"YOU GOT IT!!!\r\n"`（`0x20544f4720554f59` + `0x0a0d2121215449`），
通过 `WriteFile`（`GetStdHandle(-11)`）打到控制台 —— 但它执行在 DrawTextA **之后**、
DestroyWindow **之前**，且 GUI 子系统（subsystem=2）默认没有控制台，所以看不到。

## 解密

密钥 `ShedaLight`（10 字节），密文 26 字节，标准 RC4：

```
key      = b"ShedaLight"
ct       = d78c35aca1ffa3570c79e713e7bcff8b99545c687370dd4477f0
RC4(ct)  = 0xGame{Dyn4m1c_1$_s0_Fun!}
```

flag 本身也在玩标题梗：`Dyn4m1c`（动态的）`1$_s0_Fun`（就这么好玩）
—— 对应"动态窗口一闪而过"，而题目其实**完全静态可解**。

## 验证强度（为什么 CONFIDENCE = high）

1. **交叉校验**：脚本不是硬编码结果，是从附件里按 VMA 抠 key/密文，并断言与常量一致。
2. **独立实现验证**：标准的 Python RC4 vs **unicorn 直接执行 PE 里 `0x401550`/`0x401620`
   的真实机器码**，两者输出逐字节相同 —— 排除了"我把算法看错了"的可能。
3. **平台确认**：提交返回 `result: true`。

## 走过的弯路 / 排除项

- 本机**没有 wine**，无法直接跑 `.exe` 观察闪窗；但因为是纯静态算法题，
  改用 unicorn 模拟真机码替代动态验证，结论不受影响。
- 一开始怀疑 flag 藏在 `.bss`/运行时被覆盖（描述暗示"被跳过的校验"），
  实际 `.bss` 未被引用，没有校验分支，也不需要 patch —— 就是"画完就销毁"。
- `0x405061` 处的 `54 5c 68 73 70` 曾看起来像字符串 `T\hsp`，实为密文中段，非独立线索。
