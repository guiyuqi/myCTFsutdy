## 1. 服务形态（**交互题，但与 28 号不同**）

同作者 28 号是纯离线题；11 号**是真交互题**，但只有一个输入点：

```
[+] Welcome to challenge the treasures of the Balkans!
[+] curve = NIST521p          # secp521r1
[+] hash  = sha512
[+] public_key: <PEM>         # 跨连接完全固定
[+] hint: k ... is generated by Linear_Feedback_shift_resgister_of_length_five
How many signatures do you want? 1-60: 32
  [i] msg = <32 hex>  r = ...  s = ...
Have you decrypted successfully? (y/n): y
[+] Then sign this message for me.
message = the treasure lies hidden within the mirror
[+] The r is fixed.
r = 2661740802...5999846     # == x(G) !!
s = <输入 DECIMAL>
```

- 请求数 **≥ 32** 才会进入签名挑战；`2`、`60` 会回嘲讽
  `nonono,you didn't minimally interact to avoid the monster's sight...`
  （“minimally interact” 其实是在提示：31 是周期，32 条才刚好凑出重复 nonce）。
- 公钥、challenge message、challenge r 全部**跨连接固定**（和 9/28 号同作者风格一致）。

## 2. 第一步：LFSR → nonce 重复 → 恢复私钥

`k` 由 **length-5 LFSR** 生成 ⇒ 状态空间只有 `2^5-1 = 31` 个，
所以 `k` 序列**周期恰为 31**，于是 `r_{i+31} == r_i`。

实测：一次取 60 条签名，`rs[i] == rs[i+31]` 对全部 29 对成立（精确周期 31），
一次取 32 条也必定含 1 对重复 `r`（不同连接只是 LFSR 起点随机偏移）。

同一 `k` 签两条不同消息 `m_i, m_j`：

```
s_i = k^{-1}(h_i + r d)
s_j = k^{-1}(h_j + r d)
        ⇒  k = (h_i - h_j) · (s_i - s_j)^{-1}  mod n
           d = (s_i·k - h_i) · r^{-1}         mod n
```

**哈希口径（本作者 9 号题同款坑）**：`h = int(sha512(<msg 的 ASCII hex 字符串>))`，
即对**打印出来的那串 hex 文本**做 sha512，**不是** `bytes.fromhex(msg)` 的原始 16 字节。
（`raw` 口径解不出能通过公钥校验的 `d`。）

得到的私钥（`d·G == Q`，并在全部 32 条签名上交叉验证通过）：

```
d = 0xe109b2b0a3d9acdd5f642935b2d1539d79583685a92959e929d8a9c1aa8965ee33bd3dfc9e2d37c147d0d1ab17016ba28a2840bb030d2dc9354b1da1209b3cf1
```

## 3. 第二步：固定 r 的签名伪造

最后阶段服务把 `r` 固定成

```
r = 2661740802050217063228768716723360960729859168756973147706671368418802944996427808491545080627771902352094241225065558662157113545570916814161637315895999846
```

这个值**恰好等于 `Gx = x(G)`**（`k = 1` 或 `k = n-1`）。服务实际用的是 `k = n-1`（`R = -G`），所以

```
s = (n-1)^{-1} · (h + r·d) = -(h + r·d)  mod n
h = int(sha512(b"the treasure lies hidden within the mirror"))
```

发过去即得 flag。（`k = 1` 会回 `Unfortunately，you're not the chosen one.`，
说明服务端取的是 `-G` 那一支。）

## 4. 最大的坑：`s` 必须用**十进制**输入

服务是 `s = int(input())`（base 10）：

- 发 hex（含 `a`–`f`）→ 抛异常 → 回 **`bye`** 并断开；
- 只有“纯数字的 hex”（如 `2^200`、`2^256`）才会被当数字继续走验证 → 回 `Wrong signature.`；
- **每次连接只有一次尝试机会**，答错即关连接。

我一开始把服务回的 `bye` 误判成“尺寸越界”，实际是解析失败。
把候选 `s` 用 `str(s)` 十进制发出去后立刻拿到 flag。

## 5. 复现

```bash
cd ~/ctf-2026
source ~/re-tools/fw-env.sh
python3 scripts/11-solve.py          # 打印 d、challenge、flag
```

脚本流程：连一次取 32 条签名 → 用 `r` 重复对恢复并验证 `d` → 发 `y` →
对固定 `r` 依次尝试 `k=1` / `k=n-1`（十进制 `s`）→ 命中即输出 flag。
（`k=1` 会失败并断连，脚本会自动重连再试 `k=n-1`。）
