## 1. 漏洞

自动化结算系统对「购买数量」**没有校验必须为正数**（有符号整数，直接 `atoi`/`%d`）。

结算逻辑等价于：

```c
cost    = price * number;      // 有符号乘法
balance = balance - cost;      // 等价于 balance += (-cost)
```

传 `number = -10000`（单价 10）时：

```
cost    = 10 * (-10000) = -100000
balance = 100 - (-100000) = 100100
```

余额 100 → **100100**，超过 Flag 标价 99999，直接买下。

题目描述里的两句提示就是明示：

- 「远古 Flag 的标价高达 99999 金币，而你的口袋里却只有可怜的 100 枚」
- 「试着把购买的规则"倒"过来玩，也许财富不仅不用花，还会自己流进你的钱包」→ **负数数量**

> 不需要真的触发 32 位整型溢出：负数数量本身就是「倒过来玩」。
> (`int` 溢出只在 `number` 绝对值 > ~2.1e8 时才有意义，本题用不到。)

## 2. 交互协议（原文见 `evidence/15-banner.txt`）

```
==================================================
        Welcome to the shop (Beta v1.1)
==================================================

[Wallet] balance: 100 gold
[List]
  1. blood bottle    ---- Sale: 10 gold
  2. Flag   ---- Sale: 99999 gold
  3. Exit
Choice (1-3): Input the number you want:
--- calculating ---
price: 10 gold
number: -10000
cost: -100000 gold
Done

[Wallet] balance: 100100 gold
...（菜单循环）
```

要点：

- 选 `1` / `2` 后都会再问 `Input the number you want: `（数量）。
- **没有**「卖回 / 退款」功能，也不需要「钥匙 / 门票」——直接买 Flag。
- 买下 Flag（`2` → `1`）后立即打印：

```
[ Congratulation!!! ]
Flag:
0xGame{Welc0m3_7o_th3_pwn_w0rld!!!}
```

- 无需多轮结算，负数买一次即可。
