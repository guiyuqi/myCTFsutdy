## 2. 确定性结论（双重验证）

### 2.1 题面给的 n 不是合法模数

```
len(str(n)) = 154         (hint1 说应为 155)
gcd(n,3)    = 3
n/3         = 3647246213…144463  → sympy.isprime = True (507 bit)
```

即题面 n = **3 × 507-bit 素数**，绝不可能是 `getPrime(256)*getPrime(256)`
（两枚 256-bit 素数之积 ≥ 510 bit）。⇒ n 丢了一位十进制数字。

### 2.2 补回数字 = 末尾补 `'7'`

- 穷举全部 **1550** 个「插入一位数字」候选（任意位置、任意数字）；
- 先按「两枚 256-bit 素数的积必然为奇数且无 <1e5 的小因子」过滤 → 170 个候选；
- 对这 170 个查 FactorDB：**只有 1 个状态为 FF（完全分解）**，且恰好是两个 256-bit 素数：

```
n_full = 109417386415705274218097073220403576120037329454492059909138421314763499842889
         34784717997257891267332497625752899781833797076537244027146743531593354333897   (155 位)
       = 原 n 末尾补 '7'   ( i = 154, d = '7' )
p = 102639592829741105772054196573991675900716567808038066803341933521790711307779   (256 bit)
q = 106603488380168454820927220360012878679207958575989291522270608237193062808643   (256 bit)
p*q == n_full  ✓
```

证据：`evidence/8-factordb-hit.txt`（同时给出题面 154 位 n 的 FactorDB 结果 = `3 × prime`）。
作者另一题（0xGame2025 Week1 `RSA-FactorDB`）的官方 WP 明确写过「512 bit 模数可直接在 FactorDB 查到」，
正好呼应「吸食旧花的骨髓」。

### 2.3 解密结果（唯一确定）

```
e = 65537,  phi = (p-1)(q-1),  d = e^{-1} mod phi,  m = c^d mod n_full
re-encrypt check: m^e mod n_full == c   ✓
```

明文 **50 字节**：

```
ff 00 13 37 |  30 78 47 61 6d 65 7b 25 79 6f 75 5f ef bf a5 68 61 76 65 40
              6b 65 65 6e 23 65 79 65 73 26 66 6f 72 2a 43 72 79 70 74 6f 21 7d  | 80 00 7f ee
```

可读形式：

```
ff001337  0xGame{%you_￥have@keen#eyes&for*Crypto!}  80007fee
```

- `￥` = U+FFE5（全角日元），UTF-8 = `ef bf a5`；
- 4+4 字节不可打印「哨兵」：前缀 `ff 00 13 37`（含 `1337`）、后缀 `80 00 7f ee`；
- 花括号内 6 个杂质字符：`%` `￥` `@` `#` `&` `*`，
  位置 = 明文索引 **7, 12, 17, 22, 27, 31**，正好各自落在 6 个「单词」前面：
  `% you_ ￥ have @ keen # eyes & for * Crypto!`

（上述输出可用 `python3 scripts/8-solve.py` 一键复现。）

## 4. 未解决的歧义（写给以后接手的人）

数据本身**无法区分**「杂质是插入的」还是「杂质替换了原字符」：

- 若**纯插入**：还原必然 = `0xGame{you_havekeeneyesforCrypto!}` → 已被拒，
  **故该假设不成立**（这也是唯一能被数据唯一确定的一种清洗）。
- 因此**必然存在替换**：去杂质后单词之间丢了 4~5 个字符，原字符只能靠语义补。
  语义上只有两种合理补法 —— 下划线（候选 1）或空格（候选 4）—— **两种都被拒**。
- ⇒ **「淤泥」这个词的真实所指尚未破解**。它可能不是指 `% ￥ @ # & *` 这 6 个字符，
  而是指别的对象（例如两段哨兵字节 `ff001337` / `80007fee`，或它们编码的某种规则）。
  下面列出已排查/未排查的方向，供接手者参考。

### 4.1 已经排除的攻击面（都不成立，不必重做）

| 方向 | 结论 |
|---|---|
| 直接对题面 n 解密 | n = 3×prime，能算出 phi，但解出的是随机字节（c 不是对 3×prime 加密的） |
| `gcd(n1,n2)` 共用素因子 | 本工作区内所有附件里再没有第二个 ≥50 位的整数（已全盘扫描） |
| Fermat（p、q 相近 / `next_prime`） | 1550 个候选全部跑 200k 轮 Fermat，无命中（覆盖 \|p−q\| ≤ 2^138） |
| Wiener / 小私钥 d | 全部候选无命中 |
| 小因子 / 部分分解 | 已做 ≤1e5 试除 + 小因子候选解密测试，无 flag |
| 「素数模数」（Prime-Modulus-RSA 旧缺陷） | 1550 个插入候选里有 12 个是素数，逐个（大端/小端、+k·n）解密 → 全是随机字节 |
| 明文可能 > n | 对 3×prime 与 12 个素数候选都试了 m + k·n (k≤40)，无 flag |
| 附件内隐藏数据 | 全文 hexdump，无零宽字符、无附加流；文件大小与平台一致（616 B） |
| 公开 WP | 全网搜索（含 grep.app/GitHub API）：本题无公开题解 |
