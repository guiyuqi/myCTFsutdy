## 思路

题面提示「美丽的汤」= **BeautifulSoup**（bs4），即「别手点，写爬虫批量抓取 + 解析 HTML」。
信息实际上直接写在 **HTTP 响应头** 里：

```
X-Hint: fragments are gzip -> base64 -> split; join in page order
```

首页写明「一共 124 篇碎碎念」，每篇 `/page?id=N` 页面里有两个片段容器：

```html
<p>哈哈哈哈！今天奶蛙又笑到捧腹了！<span style="display:none" class="frag">&#43;</span></p>
<p>第 1 / 124 块碎片：
  <span class="flag-fragment">H</span></p>
```

- `.flag-fragment`（**可见**，橙色虚线框）= 真碎片 → 顺序拼接后 `base64` 解码再 `gzip` 解压。
- `.frag`（`display:none` 隐藏）= **干扰项**，拼起来长度也是 124，但 base64 解出来不是 gzip 数据
  （`Not a gzipped file (b'\xf8\xdc')`），是陷阱，不要用。

## 注意点

- 碎片里含 `+` `/` `=` 等 base64 字符，HTML 里以实体（如 `&#43;`）出现，**必须 `html.unescape`**
  后再拼接，否则 base64 解码失败。
- `gzip → base64` 的书写顺序指「编码顺序」，解码时要**反过来**：先 base64 解码，再 gunzip。
- 环境无 `bs4`（未 pip install，遵守规则），用标准库 `re` + `html` + `base64` + `gzip` 实现，
  等价效果。
